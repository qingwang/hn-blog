## 1. IceWM {#story-1}
*HN 第 2 名 · [ice-wm.org](https://ice-wm.org/) · 111 分 · 57 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50478515)*

这是 IceWM 的官方主页。IceWM 是 X Window System 的窗口管理器，由 Marko Maček 于 1997 年用 C++ 编写，目前托管在 GitHub 上维护。它主打速度、简洁以及不挡用户的路：带分页器的任务栏、全局和按窗口的快捷键、动态菜单系统、可配置的焦点模型、RandR/Xinerama 多显示器支持、可选的壁纸管理器和会话管理器；box-look.org 上有 450 多个主题，91 个可选的「Extra」亮点，提供三十几种语言的翻译，并已被打包进 Debian、Ubuntu、Arch、openSUSE、Gentoo、Slackware、CentOS、antiX、NixOS 和大多数 BSD。其中列出的最新版本是 4.1.0（2026-08-06），可通过 wget 和 lzip 从源码压缩包安装。

**讨论**: 最高票评论定下了基调：有几位读者把 IceWM 当作怀旧对象（一位在 2000 年代初提交过补丁，另一位称赞它在最低端硬件上有多么流畅），但排名最高的评论者坚称自己今天仍在使用它，作为一台无头远程桌面机器的一体化低资源桌面——面板、应用菜单和窗口管理器合为一体，无需配置——还有人从音频工作以及一个 2004–2005 年的商业 Linux 发行版的角度附和，那个发行版把它和 Nautilus 一起作为默认桌面。随后话题转向一场漫长的 X11 对 Wayland 之争：一方称 X11 是彻底的遗留技术，并称赞 Wayland、PipeWire 和 systemd-networkd/journald 是一次干净利落的割裂；另有数人回复说 X11 并非遗留技术，Wayland 仍缺少窗口定位能力和任何可移植的 wmctrl 式脚本，而截图和屏幕共享最终还是落到了合成器专属扩展和 portal 上；XLibre 分支既被引为火炬手，也被轻蔑地说成是受害者情结。配置是反复出现的抱怨点——一位前 fluxbox 用户说 IceWM 更成熟但更难配置（无法移除不想要的工作区），而且主要开发者无视功能请求，所以他们不再提交了。平铺式窗口管理器的用户（awesome、dwm、xmonad）和一位 openbox 爱好者表示那些更合心意，另有一条支线在争论软件透明效果究竟是被 GPU 真正取代了，还是仅仅因为编程粗糙而消失；没有人质疑 IceWM 仍是一个扎实、小巧、仍在维护的选择。

**值得一读的评论**
- [yjftsjthsd-h](https://news.ycombinator.com/item?id=50479019): 一位现役日常用户说明了具体用例：把 IceWM 当作单一免配置单元（面板、应用菜单、窗口管理器），用于低资源的无头远程桌面。
- [kiney](https://news.ycombinator.com/item?id=50479686): 主张 Wayland 永远不会真正可用——它现在的年龄已经和 Wayland 起步时的 Xorg 一样大，核心协议仍缺少窗口定位，而截图/屏幕共享不得不依赖合成器专属扩展和 portal。
- [shevy-java](https://news.ycombinator.com/item?id=50479662): 一段老用户的长篇比较：IceWM 比如今几近消亡的 fluxbox 更能干，但更难配置；维护者对已提交问题的不回应让他们放弃了提功能请求。

## 2. Rust 1.100 {#story-2}
*HN 第 3 名 · [blog.rust-lang.org](https://blog.rust-lang.org/2026/11/12/Rust-1.100.0/) · 627 分 · 240 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50472038)*

Rust 1.100.0 的官方发布公告（2026 年 11 月 12 日）。最重磅的内容是 never 类型 `!` 的稳定化——它现在可以出现在类型中的任何位置，而不只是作为返回类型——这历经了 10 年和 5 次失败的尝试；`Infallible` 成为它的别名，这迫使在 2015/2018/2021 版次中做出一项破坏性变更，把 never 类型的回退类型从 `()` 改为 `!`。本次发布还稳定了 `allocator_api` 的核心（`Allocator` trait，以及 `Vec` 和 `Box`）、`core::mem::DropGuard`、`std::mem::conjure_zst`，并带来了 Cargo 的改动：未使用依赖警告、重构的构建目录布局（一致地应用构建配置哈希以减少缓存冲突）、最短发布时长「依赖冷却」（`global-min-publish-age = “3 days”`，RFC 3923），以及 `cargo install` 现在默认使用 `.crate` tarball 内的 lockfile。

**讨论**: 讨论串整体是庆祝气氛——人们称这是多年来最大的发布之一，其中 never 类型招来的玩笑最多（包括一个说它是按稳定化日期命名的）。依赖冷却让评论者分成两派：一些人认为它会削弱对 0-day 的响应能力；另一些人（尤其是 Trail of Bits 的 woodruffw）则认为答案是在 resolver 自身内部既让普通更新冷却、又让安全公告走快速通道，而不是二选一。一个关于编译时间和 90GB+ target 目录的长子讨论串得到了 Cargo 维护者 epage 的具体回答，他列出了即将开展的工作（dev profile 中更少的调试信息、不再把 rlib 复制到 target-dir、build-dir 垃圾回收、跨 workspace 缓存），此外还有一个已在 nightly 上修复的 macOS 临时文件 bug。关于稳定 ABI 的常年愿望再次被提起，而围绕 `bool::toggle()` 的设计讨论——既然有了 `x = !x` 为何还要它、`&mut self` 在原生类型上如何工作——一直延伸到几十条回复。共识是：这是一次强劲的发布，而编译时间和 ABI 仍是长期存在的抱怨。

**值得一读的评论**
- [JoshTriplett](https://news.ycombinator.com/item?id=50473008): Josh Triplett 解释了为什么稳定的 Rust ABI 很难：泛型是在使用方从 MIR 编译的，因此 ABI 必须基于 `dyn`，而 `dyn` 无法表达许多 trait，还会让 `Vec<T>` 变得别扭。
- [epage](https://news.ycombinator.com/item?id=50473366): Cargo 维护者 epage 列出了正在推进的具体构建时间和构建目录修复——精简 dev profile 的调试信息、不再把 rlib 复制进 target-dir、对 rlib/rmeta 数据去重，接下来还有 build-dir 垃圾回收和跨 workspace 缓存。
- [woodruffw](https://news.ycombinator.com/item?id=50477439): woodruffw 主张冷却和安全快速修补都必须存在于 resolver 的状态机中，因为大多数工具会让冷却机制阻断由安全公告驱动的更新。

## 3. Brave Search API 现已通过 x402 协议接受 agentic 支付 {#story-3}
*HN 第 4 名 · [brave.com](https://brave.com/blog/search-api-agentic-payments/) · 76 分 · 37 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50477649)*
*原标题: Brave Search API now accepts agentic payments via the x402 protocol*

Brave 的开发者博客宣布，其 Search API 端点现在可以通过 x402 按请求付费；x402 是一种开放式支付协议，围绕长期休眠的 HTTP 402 Payment Required 状态码构建。未付费的请求会收到一个带价格的 402 响应；agent 在 Base 上签署一笔 USDC 支付，重试请求，然后获得结果和一张链上收据——无需账户或 API key。定价与 Brave 公布的价格一致：LLM Context、web、news、image、video 和 local 端点均为每次查询 $0.005（每 1,000 次 $5）；限时内 Base 的 gas 费用由 Brave 承担；建议使用 Stripe 的 Purl CLI 钱包进行最简便的设置；Brave 自己充当 facilitator，并承诺未来支持更多链和稳定币。

**讨论**: 讨论的主基调是怀疑是否真有人在付费：一位在抓取量很大的站点上部署了 x402 的评论者表示，他至今没见到一笔交易，并引用了 x402 subreddit 上的类似报告。其他人则认为，与替代方案相比这个价格太高——Kagi 的 API 为每 1,000 次 $12，Exa 为 $4，而 SerpApi 提供 Google 结果大约每 1,000 次 $15——并质疑当发起查询的是 agent 而非看广告的人类时，搜索经济学会变成什么样。一个反复出现的子讨论质疑：既然 Kagi 卖的只是一个普通 API key，为什么还需要区块链？支持方的论点是：卡组织和银行无法在不收取每笔交易费用和客服开销的情况下完成亚分级别的跨境收费，而加密货币支付不可撤销，从而同时绕开了这两个问题。有几个人重提了「用户讨厌微支付」的老论点，反驳者则称人们讨厌的只是摩擦，而不是按量计价——电力和公用事业计费被举为现成的模型——同时一位评论者指出，Brave 已经用 BAT 试过这条路，而一个每月百万独立访客的站点只赚到了几分钱。一位关注隐私的评论者抱怨说，一个隐私浏览器推出加密支付却不支持 Monero；另一位则链接了 2026 年 11 月 Ars Technica 的一篇报道，内容是关于 NYT 要求 Brave 关闭其付费墙绕过功能，并调侃说这就是那个「付钱给我们来跳过付费墙」的服务。

**值得一读的评论**
- [ddxv](https://news.ycombinator.com/item?id=50479355): 一位在抓取量很大的站点上实现了 x402 的评论者表示，至今一笔交易都没有发生，而且 x402 subreddit 上到处都是同一个玩笑：只有测试者在付费。
- [gkbrk](https://news.ycombinator.com/item?id=50479731): 具体的价格对比：Kagi 的 API 为每 1,000 次搜索 $12，Exa 为 $4，而 SerpApi 以 $75 出售 5,000 次 Google 搜索，公司整体使用还有批量折扣。
- [brodydung](https://news.ycombinator.com/item?id=50479133): 认为真正的缺口是预算额度，而不是支付通道——agent 会用改写后的问题反复查询，而去掉 API key 也就去掉了那个原本能暴露失控支出的月度账单；并追问 Brave 是否会对重复查询去重或缓存。

## 5. Switcher (2004) {#story-5}
*HN 第 8 名 · [folklore.org](https://folklore.org/Switcher.html) · 86 分 · 23 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50477714)*

这是 folklore.org 上 Andy Hertzfeld 的一篇回忆文章，讲述 1984 年他如何为 Macintosh 写出第一个多任务环境 Switcher。他在给 Byte 杂志记者 John Markoff 演示 Thunderscan 扫描仪时，看到对方在 IBM PC 上用 Memory Shift 快速切换驻留程序，当场决定为 Mac 做同样的事。Microsoft 的 Jeff Harbers 和 Neil Konzen 也想做这个项目（因为 512K Mac 会削弱 Microsoft 小程序的内存优势，而 Lotus Jazz 已能快速切换模块），于是请他去西雅图；Bill Gates 亲自压价，用「好程序员每周写 1000 行、十周搞定、每周 4000 美元」推出 4 万美元的报价，Hertzfeld 拒绝签约，坚持独立完成后把程序随 512K Mac 捆绑发布。

**讨论**: 讨论偏离技术细节，转向怀旧与经济换算：gwern 指出 1984 年的 4 万美元约合今天 32 万多美元，感叹当年「一个切换应用的小程序」值得如此投入，随后跟帖一路跑偏到标普 500 与苹果股票回报，以及 ChatGPT 算数是否可靠（有人建议让它写代码算而不是心算）。另一条主线是老兵回忆：曾在 Microsoft Windows Mobile 编译器团队的人说，那代工程师能从汇编调试、必要时上示波器，再在自建的地基上盖设计模式，如今这种「旧派水准」已经罕见；一位与 Hertzfeld 共事过的人补充说，他的本事是提想法并用蛮力把它实现出来，「像拿砍刀开路，后面的人再修路」。也有具体更正与考据：MultiFinder 只是 Switcher 的精神后继，代码完全无关，作者是 Erich Ringewald；文中提到的 DOS 工具 Memory Shift 被确认为真实存在，有 1983 年 12 月的 Creative Computing 文章为证，而不是 Borland Sidekick 的误记。整体氛围是敬佩与怀旧，对 Gates 的谈判手法则多带调侃。

**值得一读的评论**

## 20. 研究人员发现一个每 8 分钟发出一次射电信号的罕见恒星系统 {#story-20}
*HN 第 39 名 · [curtin.edu.au](https://www.curtin.edu.au/news/media-release/researchers-discover-rare-star-system-that-emits-radio-signals-every-eight-minutes/) · 128 分 · 63 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50465453)*
*原标题: Researchers discover rare star system that emits radio signals every 8 minutes*

科廷大学（Curtin University）与 ICRAR 发布的一篇媒体稿，介绍一篇发表于《Nature Astronomy》的论文《A long-period transient with a Sun-like companion》，报告了系统 GPM J071507−114153：一颗白矮星与一颗类似我们太阳的 G 型星互相绕转，距离约 5,000 光年。这是首次将射电脉冲与绕转类太阳恒星的白矮星联系起来；此前的长周期暂现源（自 ICRAR 于 2021 年发现第一个以来已知约有十几个）都涉及温度更低的红矮星。该发现利用 MWA 巡天找到目标，用 MeerKAT 定位，用 W.M. Keck 的光学观测确认伴星，并在 Pawsey 超级计算机上进行了超过 100 小时的处理；第一作者 Sam McSweeney 表示，脉冲清晰到足以看出白矮星在轨道上的运动，因此辐射来自白矮星附近或白矮星本身。

**讨论**: 最大的讨论串是一场语义之争：dekhn 认为标题有误，因为该天体持续发出辐射，只是它的波束每 8 分钟扫过我们一次；而 sandworm101 反驳说，「恒星」和「脉冲」向来都是相对于观测者而言的术语（脉冲星实际上也并非真的在「脉冲」），并且用视亮度来描述是标准做法。一位自称语言学家的评论者站在 dekhn 一边，称「发出」描述的是客观动作，而「夜空中最亮」则明确是主观表述；另一位评论者则指出，论文自己的共同作者就把这颗白矮星描述为发出脉冲。另外，评论者问这是否只是一颗脉冲星；回答是脉冲星自转快得多（有人提到一颗以 716 Hz 自转，赤道速度约为光速的 24%），已发现超过 4,000 颗，而长周期射电暂现源的周期为几分钟到几小时，编目的只有大约十几个。还有人纠正了双星是被俘获而来的假设——大多数双星和行星一样，是从同一片星云中一起形成的——讨论串中还有不少关于外星人、烟雾报警器电池和黑暗森林的玩笑。

**值得一读的评论**
- [dekhn](https://news.ycombinator.com/item?id=50467853): 核心纠正：该源持续发出辐射，但它的波束每 8 分钟才与地球对齐一次，因此把发出辐射与探测到信号混为一谈了。
- [villaaston1](https://news.ycombinator.com/item?id=50472292): 解释了为什么这不只是一颗脉冲星：脉冲星周期短得多，已知有数千颗，而长周期射电暂现源只发现了大约 12 个。
- [adolph](https://news.ycombinator.com/item?id=50472890): 指出论文自己的共同作者 Natasha Hurley-Walker 就把它们称为「脉冲」，这削弱了「标题完全错误」这一严格解读。
