## 3. Show HN：自动关闭 Mac OS「允许 <app> 在本地网络上查找设备？」提示 {#story-3}
*HN 第 5 名 · [github.com](https://github.com/johncassil/dontallow) · 23 分 · 11 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50294506)*
*原标题: Show HN: Auto Dismiss Mac OS "Allow <app> to find devices on local networks?"*

这是一个由 johncassil 开发的单文件式 Swift 小工具 dontallow，通过 Homebrew tap 安装，运行一个按用户启动的 launchd 代理，监听系统进程 UserNotificationCenter 创建的窗口，读取对话框文字，确认是「本地网络」提示后按下「不允许」按钮，默认在 0.25 秒内完成，空闲时零 CPU 占用，重启后仍生效。README 解释了弹窗反复出现的原因：Chrome、Brave、Edge、Arc 等 Chromium 浏览器每次启动会把应用包复制到随机临时目录以保住签名，macOS 把该权限绑定到那个随机路径，于是每次启动都像新应用；使用带版本号的安装路径（.../versions/1.2.3/）的应用则每次更新都会新增一条记录。它还提供暂停、allowlist、宽限时间、只记录不操作的前台模式，以及解读 Local Network 规则库的功能；但仅支持英文系统，构建需要 macOS 13 以上，弹窗本身只在 macOS 15 Sequoia 及以后存在，目前只在 Intel、macOS 26.6 上测试过。

**讨论**: 评论不多，主要分两拨。一拨关心安全：有人问普通人如何判断这种小型 brew 包是否恶意，回复认为这本质上是在权衡「去掉一个烦人弹窗」的收益和「经由极易被投毒的渠道分发」的风险，并指出这问题适用于所有未经独立审查的可执行代码。另一拨则称赞这类工具的价值，认为这正是 LLM 时代个人可以低成本解决小烦恼的典型例子，还有人贴出自己用 Claude 写的类似工具 Squeegee（按窗口而非按应用关闭残留窗口）。也有技术性纠正与归因分歧：有人指出宣称「一个 Swift 文件」实际是两个；有人把缺少全局开关归咎于 Apple 产品经理的决定，另一位评论者反驳说这更可能是权限键选择带来的意外后果，而非有意设计。整体没有形成共识，讨论很快转向了泛泛的信任与 AI 话题。

**值得一读的评论**
- [HughParry](https://news.ycombinator.com/item?id=50294763): 提出核心疑问：面对这种小型 Homebrew 包，除了自己读源码或让 AI 审一遍，普通人没有任何可靠办法判断它是否恶意。
- [sigmoid10](https://news.ycombinator.com/item?id=50294803): 给出务实框架：这是所有未经独立审查的可执行代码共有的问题，要问的是「消除一个烦人弹窗」的收益是否值得承担一个极易被投毒的分发渠道带来的风险。
- [klodolph](https://news.ycombinator.com/item?id=50294736): 对「Apple 产品经理故意不给开关」的说法提出反驳，认为弹窗反复出现更可能是权限绑定到临时路径这一选择带来的意外后果。

## 5. 在浏览器中编辑 SQLite 数据库 {#story-5}

*原标题: Edit an SQLite database in your browser*

editsqlite.com 是一个客户端网页工具，可用于打开 SQLite 文件、.sql 转储文件（MySQL、Postgres 或 SQLite）或 CSV，在表格网格中或通过 SQL 控制台（select 或 update 或 delete 或 insert，⌘⏎ 执行）编辑行，并下载重新写出的文件。其卖点是隐私：只读取一次，从不写入，从不上传，保存的查询只留在本设备上。页面上的示例数据是一张小的 employees 表（Ada Lovelace、Grace Hopper、Alan Turing、Katherine Johnson），展示的唯一 SQL 只是一条带 WHERE 和 ORDER BY 的简单 SELECT。

**讨论**: 这条讨论串很短，且多数持怀疑态度。最响亮的抱怨针对落地页文案——一位评论者（weakfish）说「loaded into the working model」这类说法读起来像聊天机器人的上下文泄漏到了产品里，让他立刻就完全不想用这个软件，并称这是未经审阅的 vibe-coded 产物的标志。其他人则想要网站漏掉的基本信息：源代码仓库的链接（推测是 github.com/sharma3361/editsqlite，讨论串中未确认），以及说明它与现有工具的关系。有一位评论者报告了一个真实的成功案例：从 Google Drive 备份的 zip 中取出 Android 应用 Note Everything 的 SQLite 数据库，在工具中打开，把笔记导出为 CSV，再用文本编辑器查看，并打算用 gawk 把笔记重建为文件。对于这个项目是否值得，没有共识；有一条回复只是对它居然上了首页表示不屑。

## 6. 16colo.rs – ANSI/ASCII 艺术档案库 {#story-6}
*HN 第 14 名 · [16colo.rs](https://16colo.rs/) · 53 分 · 5 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50291421)*
*原标题: 16colo.rs – ANSI/ASCII art archive*

16colo.rs 即 Sixteen Colors，是一个 ANSI 和 ASCII artpack 的公共档案库——这类 artpack 是 ACiD 和 iCE 等艺术家团体在拨号 BBS 时代按月发布的合集。该网站收录了至少从 2009 年到 2026 年的 artpack，并提供标签、高级文本搜索、自行发布上传、共享的 PabloDraw 和 Moebius 服务器，以及一个现代化的 SAUCE 元数据编辑器。它把这批收藏定位为一种公共利益档案，记录一种规模虽小但仍在持续创作中的 textmode 艺术形式。

**讨论**: 评论者一致认为这一媒介仍然活跃，而不只是纯粹的遗迹。一位评论者概述了一套现代工具链——Moebius、Durdraw、Icydraw 和 PabloDraw——并指出一些编辑器已经采用 UTF-8 和 xterm 256 色调色板，这引发了一场未有定论的争论：这类作品究竟该称为「ANSI art」，还是该叫「UNSI art」之类或现代终端艺术。其他人则举出仍活跃的团体：Impure 仍在发布 ASCII 作品，并以一个 ASCII 风格的 demo 在今年 Evoke demo party 上获得第二名；另一位评论者则推荐了 Galza。整个讨论串主要是推荐和 scene 动态，除了术语之争外并无真正分歧；一位评论者还链接了 2025 年的一次 HN 讨论。

v12.sh 的一篇分析文章指出，若干 PDF 实现从足够小、可以被穷举的状态空间中派生 AES-256 文件密钥，因此受保护的 PDF 无需任何一个密码就能被打开。MuPDF 1.28.5 之前的版本用当前 epoch 秒数给 drand48 系列的 LCG 播种，并输出第 17–24 位字节，因此只有 9 位熵进入密钥——共 512 种可能的密钥流，在未优化的 Python 中约 11 毫秒即可暴力破解，文档的 /ID 用作交叉校验。Foxit Reader 2026.1.3.36551 将时间戳与 32 个未初始化（填零）字节及一个常量一起哈希，OpenPDF 3.0.5 和 iText 9.7.1 则使用基于 ARC4 的 IVGenerator，以毫秒时间戳加 JVM 空闲内存播种；作者用 Rust/Rayon 写的 Foxit 破解器在 32 线程的 Ryzen 9 7950X 上每秒检查 3.7 亿至 3.76 亿个时间戳。这一模式似乎源自 PDFium 2014 年首个公开提交中就已存在的 Foxit 代码；MuPDF 已修复该问题，针对 MuPDF 和 Foxit 的解密工具已发布，而已经分发出去的文件仍然无法恢复。

## 20. 仅用逻辑漏洞打造 Microsoft Edge 全链路攻击 {#story-20}
*HN 第 50 名 · [blog.orange.tw](https://blog.orange.tw/posts/2026-10-the-last-proof-of-human-craft-browser-full-chain/) · 224 分 · 38 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50285319)*
*原标题: Forging a Microsoft Edge Full Chain with Logic Bugs Only*

DEVCORE 的 Orange Tsai 撰文讲述了他用来在 Pwn2Own Berlin 2026 上攻破 Microsoft Edge 的完整攻击链：五个漏洞加两个 Windows 特性，没有内存破坏，而且他强调全程没有 AI 协助，赢得 175,000 美元和 17.5 分 Master of Pwn，随后还获得 Pwnie Epic Achievement 奖。入口点是 EdgeCAGuidanceNavigationThrottle，这是 Entra ID 条件访问（Conditional Access）的一个导航节流器，只从 Microsoft 来源触发，但会通过浏览器的 Navigation API 重新导航到攻击者提供的 switch_profile URL；由于该调用没有传入 source_contents，Chromium 会把这次导航绑定到当前活动的标签页，从而形成 UXSS。随后他用跨窗口的 window.open 绕过来源检查，用硬编码的 Microsoft 白名单绕过弹窗拦截，用 OneAuth 自动登录绕过登录要求，并利用 assets.msn.com 上的 CORS 配置错误绕过邮箱要求；逃逸环节则来自 Edge 的 read:// Immersive Reader scheme 被遗漏在 Chromium 的 not_allowing_javascript_urls_schemes 黑名单之外，最终导致任意文件写入和沙箱逃逸。

**讨论**: 整个讨论帖几乎一致是赞赏，几位评论者（包括有安全背景的）说弹窗拦截绕过、UXSS 和最终的 ACE 每一样都令人震惊，并称赞文章信息密集、没有废话。最响亮的实质性抱怨是关于静默登录行为：一位评论者说这解释了他某次莫名其妙地发现自己已登录 Edge，另一位称自动创建配置文件是「disgusting behaviour, RCE chain or not」（恶心行为，不管有没有 RCE 链），第三位指出 Google 也在推行类似的默认设置。一个较小的子线程转向 Microsoft 对分叉 Chromium 代码的维护——一些人认为对 Microsoft 来源做特殊处理本身就是这类漏洞产生的方式，另一些人则认为这段代码显然优先级很低，没人在意。另一场争论围绕 AI 爆发：两位读者在作者那句「让你的 agent 去填细节」的玩笑处就停下了，被其他人纠正说文章确实完整走过了推理过程，并明确声明没有使用 AI；其中一人承认了这一点。

**值得一读的评论**
- [darkamaul](https://news.ycombinator.com/item?id=50286550): 指出了一个附赠的「reverse chain」（反向链路）视频，团队从 calc 开始攻破 Edge，几位回复者对此感到困惑，并希望有一篇文字说明。
- [adzm](https://news.ycombinator.com/item?id=50289458): 单独点出 assets.msn.com 的 CORS 漏洞——任何网站都能获取已登录 Edge 用户的邮箱——认为它本身就令人不安，与漏洞利用链无关。
- [russelg](https://news.ycombinator.com/item?id=50286749): 对在「ask your agents」玩笑处就放弃的读者的关键纠正：那句话只是指跳过 Chromium 导航内部细节，研究本身并未涉及 AI。
