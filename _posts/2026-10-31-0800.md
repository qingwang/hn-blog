## 2. Cloudflare Turnstile solver library (no headless browser required) {#story-2}
*#3 on HN · [github.com](https://github.com/chris124567/cfsolve) · 177 points · 51 comments · [HN discussion](https://news.ycombinator.com/item?id=50277379)*

cfsolve is an MIT-licensed Rust library and CLI that reverse-engineers Cloudflare's Turnstile widgets and interstitial challenge pages in pure HTTP requests, returning either a Turnstile token or a cf_clearance cookie. Rather than driving a real browser, it impersonates a recorded browser via a profile file (the bundled one is Safari on iOS, profiles/safari-26-ios.json) that replays captured responses to Cloudflare's browser-fingerprinting checks; only Safari and Chrome/Chromium profile types are supported, and profiles must be generated by recording a real browser's challenge traffic through a capture proxy. It ships as a CLI (--page, --solve, --sitekey/--action/--cdata, --blank-page, proxy support) and an async Rust API (Browser::read, solve_turnstile, clear, clear_fetched, solve), builds BoringSSL/CMake/libclang from source, and warns that the cf_clearance cookie must be replayed from the same IP and user agent as the profile.

**Discussion**: The dominant frame is arms race: several commenters compare it to yt-dlp, arguing that low-volume use from reputable IPs keeps working while high-volume scraping gets signatured, and one former solver author says a single bypass is easy but emulating behavior across Cloudflare's whole network at scale is not. Others split on who is winning — some say Cloudflare has already lost because bypass is the hello world of bots and it only stops hobbyists, while others say it just needs to keep pace. A second thread is principled complaint from ordinary users locked out of sites (Letterboxd, Dell's checkout, Russian sites behind Cloudflare), with sympathy for small sites under constant attack but not for large companies, plus a tangent on Anubis proof-of-work, where people note node.crypto solves it in under a second and that it only helps against layer-7 abuse, not volumetric DDoS. Reliability and maintenance got the sharpest exchange: one commenter says value lies in a pipeline that automatically re-reverses Cloudflare's obfuscated builds, others counter that a free MIT library shared as-is has no obligation to offer continuity. The author answers questions directly, credits Claude and 「Muse Spark」 for much of the reverse-engineering (persuaded he owned the test site), and describes telling an agent 「they changed something, please fix」 for each new Cloudflare build, spending most of the wait on Rust compile times.

**Worth reading**
- [costco](https://news.ycombinator.com/item?id=50311942): The author reports the solver works through US proxies but failed for a user on European ones, suspecting Cloudflare serves region-specific builds he still needs to handle.
- [manofmanysmiles](https://news.ycombinator.com/item?id=50312421): Someone who built a similar bypass a year ago argues a single solver is easy but scale is a different game, because Cloudflare correlates behavior across its whole network.
- [costco](https://news.ycombinator.com/item?id=50311867): The author explains his maintenance loop: he tells an agent Cloudflare changed something and waits hours, mostly on Rust compilation, and admits the codebase will get messy long-term.

The detail commenters single out is that the drift was visible only against the patient's own baseline — a resting heart rate moving from 44 to 49 bpm still reads as 「athletic」 against population norms, so static, cohort-based alarm thresholds would not have fired.

**Discussion**: The thread splits between enthusiasm for personal-baseline monitoring and scepticism about what one patient can prove. The top comment argues that cross-sectional comparison to an 「average human」 template forces a bad choice between uselessly wide normal bands and over-pathologizing narrow ones, and that the real diagnostic signal is synchronized change across several metrics relative to an individual's homeostasis — which requires high temporal resolution. ## 6. Sanstun: A sans-IO, parallel-friendly WireGuard implementation in Rust {#story-6}
*#12 on HN · [firezone.dev](https://www.firezone.dev/blog/introducing-sanstun) · 120 points · 20 comments · [HN discussion](https://news.ycombinator.com/item?id=50310398)*

Firezone 宣布开源 sanstun，一个用 Rust 编写的 WireGuard 状态机实现，采用 sans-IO 设计——把 IO、时间和随机数与协议状态机彻底分离，以 Apache 2.0 发布并已上架 crates.io。它脱胎于团队两年多来对 Cloudflare boringtun 的 fork，累计合并了 70 多个补丁 PR，官方现已弃用该 fork。核心卖点是把每个数据包的记账（预留计数器、推进计时器）与 ChaCha20-Poly1305 加解密拆开：begin_encapsulate 约 20.8 纳秒，而 1280 字节包的 encrypt 约 933 纳秒，记账仅占 2%，因此可把 PendingEncapsulate 送到其他线程做 crypto，理论加速比 45 倍以上。

**Discussion**: 最激烈的争论在 sans-IO 与 async 的关系上：一位评论者（Twey）指出 async 本身并非 IO，而是写纯确定性状态机的方式，去掉 async 反而让函数着色问题更糟；作者回应说 async 最终收敛到单一 poll 接口，而 Firezone 的核心需要同时处理入站 IP/UDP、WebSocket 控制消息、TURN 分配、计时器和用户命令，用一个大结构体的 &mut self 方法更易组合和测试，并解释了扩展为 Generator 并不能解决问题。另有人批评 Firezone 官网「硬件承担重任、电池更持久」的文案像 AI 生成的空话，质疑安全关键软件是否也在别处偷工减料；作者澄清那是指向量化加密指令与内核/网卡的校验和卸载、分段卸载，承认措辞可以更好，但不同意「面向技术人员的产品就该堆术语、不该用 AI 写文案」的反驳。有人提到 Mullvad 同样从 boringtun 分叉出自己的 gotatun，并有开发者在实际 VPN 管理器中使用了 gotatun，询问性能曲线、抖动与安全测试数据（未见答复）。还有人主张只该用 Jason Donenfeld 的参考实现（WireGuard 才约 2k 行，为何要三十个版本），作者反驳跨平台场景无法用 Linux 内核实现、官方用户态实现是 Go 不便从 Rust FFI，另一位则指出 sanstun 能在 ESP32 这类 no_std 环境运行，是参考实现做不到的。

**Worth reading**
- [Twey](https://news.ycombinator.com/item?id=50312268): 反驳「sans-IO 避免函数着色」的说法：async 不是 IO，而是把逻辑流聚在一起写纯状态机的方式，手动展开成状态转移反而使跨多转移的流程更难调用、着色问题更严重。
- [temp0826](https://news.ycombinator.com/item?id=50310928): 指出 Mullvad 也把 boringtun 分叉成了自己的实现 gotatun，说明这种分叉-重写路径并非 Firezone 独有。
- [lakeviewterrace](https://news.ycombinator.com/item?id=50311704): 直言非参考实现的 WireGuard 都是自找麻烦：协议只有约 2k 行，不需要三十个版本，审计现有的就好——引来作者与另一位评论者的反驳。

## 7. Infinite Mac: BeOS {#story-7}
*#13 on HN · [blog.persistent.info](https://blog.persistent.info/2026/10/infinite-mac-beos.html) · 147 points · 58 comments · [HN discussion](https://news.ycombinator.com/item?id=50309029)*

Infinite Mac 的维护者（博客 persistent.info）把多个版本的 BeOS 加入了可以在浏览器里直接启动的经典 Mac 系统合集，用的是 DingusPPC 模拟器和 Power Macintosh 7300 配置，磁盘镜像支持流式加载，还能挂载 Internet Archive 的光盘并把改动保存在 Saved HD 上。作者为此向 DingusPPC 上游提交了大量兼容性修复：ADB 模拟的修饰键 bug、切换色深时视频控制器与 DAC 的调用顺序、早期 BeOS 的小端显存写入、machfs 生成卷被 BeOS 严格校验拒绝，以及 SheepShaver 依赖的 ROM 内存映射边界情况；他认为这是目前唯一能跑 PowerPC 版 BeOS 的模拟器。文中还提到 DR8.2 带有 1997 年 4 月 1 日后无法启动的时间炸弹，因此用自定义日期硬编码绕过；新功能包括录制带声音的视频截图，以及在自建 Cloudflare R2 桶上镜像系统光盘。
