## 1. PHP 8.2.35 {#story-1}
*#1 on HN · [github.com](https://github.com/php/php-src/releases/tag/php-8.2.35) · 848 points · 476 comments · [HN discussion](https://news.ycombinator.com/item?id=50180873)*

The GitHub release page for PHP 8.2.35, a security release fixing two vulnerabilities (CVE-2026-109618 and CVE-2026-109619) that the PHP team describes as allowing unauthenticated remote code execution, with a blunt 「there are no complete mitigations, updating is the only safe choice」. It is part of a coordinated multi-version patch set (8.3.36, 8.4.27, 8.5.12) and reminds users that PHP 8.2 reaches end of life on 31 December 2026.

**Discussion**: Most of the thread is about how the disclosure was handled rather than the patch: critics say OpenAI, Wiz and Calif sat on the bug for two months, built hype sites like php2shell.com, lost the embargo, and forced a rushed release while distro and container packages lagged. Others push back hard, arguing Wiz reported on 24 August, the PHP security team did not acknowledge until 21 September, and publishing a fix is the same as publishing the details — the delay was PHP's, not the reporters'. A second cluster is pure operational pain: the official php Docker images took about three hours (with placeholder tags that could not actually be pulled), Ubuntu, Amazon Linux 2023 and Linode mirrors trailed Debian, PECL returned 504s, and people found freshly built images still shipping unpatched 8.4.26 and 8.3.35. Ondřej Surý's deb.sury.org PPA and Remi's RPMs draw loud gratitude plus calls for companies to fund them, and Debian is repeatedly praised for shipping within minutes. Technical skepticism surfaces too: a circulated PoC claiming RCE was withdrawn, and the fix is thousands of scattered ZEND_HAS_OOM() checks in a longjmp-based C codebase, which some doubt is exhaustive. Nobody thinks PHP will vanish; the consensus is patch, isolate, and accept that agent-assisted patch-diffing has broken the old embargo model.

**Worth reading**
- [tetraodonpuffer](https://news.ycombinator.com/item?id=50181334): Gives the timeline that reframes the blame: Wiz reported on 24 August 2026 and PHP only acknowledged and started fixing on 21 September.
- [benibela](https://news.ycombinator.com/item?id=50184174): Points to a withdrawn PoC and claims CVE-2026-109618 is not actually an RCE because an addref call prevents the use-after-free, while CVE-2026-109619 is memory-unsafe but has no RCE.
- [bombcar](https://news.ycombinator.com/item?id=50180939): A detailed interim mitigation checklist for WordPress boxes — disable session.upload_progress, block multipart bodies at the web server, set pm.max_requests=1, lower post_max_size — though another commenter immediately accuses it of being unverified LLM output.

## 3. Compromised LiteLLM 1.107.0 on PyPI Installs a Credential Stealer and Backdoor {#story-3}
*#3 on HN · [safedep.io](https://safedep.io/litellm-pypi-compromise-credential-stealer-backdoor/) · 254 points · 98 comments · [HN discussion](https://news.ycombinator.com/item?id=50181114)*

SafeDep's teardown of the LiteLLM 1.107.0 release on PyPI: all wheels shipped three files in site-packages — cook.pth, cook.py and sitecustomize.py — that run in every Python process on the host, even ones that never import litellm. The stealer harvests SSH keys, cloud credentials, CI/CD secrets, browser passwords, AI tool tokens (Claude Code, Cursor, Codex, opencode…) and the provider keys in a LiteLLM proxy database, encrypts them to an embedded RSA-4096 key, and POSTs them to www.litellm[.]dev; sitecustomize.py spawns a hourly daemon that reads a server address from a now-deleted GitHub repo (letters9813) and exec()s downloaded code. 1.106.2, rc1 and rc2 were clean, the release does not match its tag (pyproject version was rolled back from 1.108.0), no public GitHub Actions run built it, and PyPI had no provenance attestations.

**Discussion**: The dominant reaction is anger that this is LiteLLM's second supply-chain compromise this year, with several commenters calling a repeat incident malpractice rather than bad luck. A recurring thread argues for a 24–48h dependency cooldown by default in uv, npm and pip, but others push back that real attacks sit undetected for months, that cooldowns just delay discovery, that security updates get blocked, and that an attacker who knows about cooldowns can simply wait them out. On defenses, one widely-read comment points out that provenance attestations would not have helped here, since they prove which workflow published a wheel, not what source it built — only rebuilding from the public tag and diffing would catch it. The official incident response drew fire for telling users to pin 1.106.2 while pointing enterprise customers at a private registry containing an embargoed fix for a second vulnerability due October 27; defenders compare it to Red Hat and OpenSSL embargo practice, and a sub-thread argues that analogy is misleading because vendors prepare packages but do not ship embargoed fixes early. A parallel thread is about exit: people who never trusted LiteLLM ask what to migrate to, and answers range from Go rewrites (GoModel, sturnus, a homegrown key-injecting proxy) to Pydantic AI, with skeptics noting a gateway still buys failover, budgets and central config.

**Worth reading**
- [aakashpawar](https://news.ycombinator.com/item?id=50183906): Attestations would not have saved anyone here — they prove which workflow published the wheel, not which source it checked out; only independent rebuilds from the public tag would catch this, and almost nobody does that for Python wheels.
- [hmokiguess](https://news.ycombinator.com/item?id=50183423): Quotes BerriAI's issue #47826: OSS users should pin 1.106.2, while enterprise customers get an embargoed release fixing a separate vulnerability scheduled for disclosure October 27.
- [petesergeant](https://news.ycombinator.com/item?id=50183637): Corrects the Red Hat comparison: vendors receive embargoed notice so packages are ready when the embargo lifts, but they do not ship fixes for embargoed vulnerabilities to paying customers early.

## 4. The compiler was supposed to end programming too {#story-4}
*#4 on HN · [hrih.si](https://hrih.si/articles/the-compiler-was-supposed-to-end-programming/) · 30 points · 13 comments · [HN discussion](https://news.ycombinator.com/item?id=50185045)*

An essay argues that AI coding agents are the latest step in a 70-year pattern of automation, not the end of programming: IBM's 1954 FORTRAN report promised to 「virtually eliminate coding and debugging」, and the 1981 BASIC generator The Last One promised to be the last program anyone would buy. It cites Stack Overflow's 2025 survey (84% adoption, but favorable sentiment down from 77% to 60% and 66% frustrated by output that is 「almost right, but not quite」), METR's randomized trial in which 16 experienced developers were 19% slower with AI while believing they were 20% faster, and Faros AI data showing more pull requests but fivefold median review time and a 31% increase in PRs merged with no review. It then warns that the junior pipeline is being cut: Stanford/ADP data shows developer employment for ages 22-25 down nearly 20% from its late-2022 peak, raising the question of where future senior engineers will learn to judge code if agents take the routine tickets.

**Discussion**: The thread largely pushes back on the article's compiler analogy rather than engaging its METR, Faros or junior-hiring data. gonzalohm argues a compiler operates on a formally defined language, so a statement like float x = 3.1 has a determinate meaning, while a request such as 「create a variable x and assign it 3.1」 leaves type, precision and intent open; coldtea calls the comparison simply bad. cwoolfe and others counter that LLM coding is just the next abstraction layer, pointing to COBOL, SQL, 4GL and BASIC as earlier attempts to program in something closer to natural language. A side branch compares AI to the terminal shift: dvh says terminals ended the social computer-room culture and drove women away, while david-gpu attributes the change to people prioritizing paychecks. The mood is skeptical — misano asks whether the piece is 「copium」, and mbil jokes that its 2031 Tuesday already describes his mornings this year, except that he was not at work at 7:40.

**Worth reading**
- [gonzalohm](https://news.ycombinator.com/item?id=50185781): gonzalohm rejects the compiler comparison on formal grounds: compilers translate a defined language with determinate semantics, whereas natural-language instructions are ambiguous about type, precision and intent.
- [cwoolfe](https://news.ycombinator.com/item?id=50185667): cwoolfe argues that LLM-assisted coding is simply the next abstraction layer in a long search for natural-language programming.

## 5. Eight Bits of Trust; eMudhra's CA keys cracked in milliseconds {#story-5}
*#5 on HN · [scotthelme.co.uk](https://scotthelme.co.uk/eight-bits-of-trust-emudhras-ca-keys-cracked-in-milliseconds/) · 693 points · 329 comments · [HN discussion](https://news.ycombinator.com/item?id=50177916)*

Scott Helme 的一篇博文，内容是 eMudhra 八个中间 CA 私钥的恢复过程。这些密钥本应是 384 位的 P-384 椭圆曲线标量，结果却成了单字节整数（4、56、115……），任何人都可以通过逐一尝试最多 255 次点乘法，在不到一秒内找回来。被攻破的八个中间证书是 2025 年 4 月签发的六个 TLS 签发 CA（DV/OV/EV，两代）和两个代码签名 CA，2025 年 5 月又由 Sectigo 的 AAA Certificate Services 根证书交叉签名。Helme 只用本地服务器和一张伪造的 api.stripe.com 证书做测试，系统默认配置下的 curl、Python 和 Node 都接受了它；原因是大多数非浏览器客户端使用磁盘上自带的 CA 包，既不做证书吊销检查也不检查 CT。于是，无法更新的路由器、电视和 IoT 设备要到证书 2039 年 7 月过期之前，一直信任这些密钥。

**Discussion**: 讨论很快分成三类。第一类是影响范围：有人指出，大量工具会自己捆绑 CA 包，例如 pip、Node、bun、Java keystore.jks、Flatpak 运行时和容器基础镜像，因此只更新系统 ca-certificates 包并不能解决全部问题。Scott Helme 确认了这个“长尾问题”，并说这类固定包只包含根证书，不会检查证书吊销。第二类是出路：有人用泄露的密钥对 Google Home 音箱做中间人攻击，还有人成功提取了两台难以破解的 ESP32 设备的固件；也有人提出在自己的网络上架设反向代理，以保护无法更新的设备，Helme 认可这一做法。第三类是动机：几位评论者坚称只可能是蓄意或国家级行为，另一些人反驳说，CA 本来就持有可用于中间人攻击的密钥，没有必要故意制造容易被猜到的密钥；Mozilla 的 bug 报告显示，是密钥生成仪式脚本的一个缺陷在 HSM 上产生了第二对弱密钥，它和正常密钥的标签相似，被人误用来生成 CSR。有人发现，这些密钥中有两个连续数字，而且八个数写出来在键盘上都是自左向右的笔画，这支持“序列号或手工挑选”的推测。另外，多位评论者质疑文章是 AI 写的，因为某些段落读起来像大模型润色；Helme 回应说，全文由他本人撰写，只在最后让 Claude 做了一次微调。

**Worth reading**
- [mminer237](https://news.ycombinator.com/item?id=50180736): 引用 Mozilla bug 2083449 中 eMudhra 的解释：当日密钥生成脚本的一个偏差先创建了原本该有的 ECC 密钥，代码缺陷又生成了第二对弱密钥，由于标签相似，人误用了后者生成 CSR 并送去 Sectigo 交叉签名。
- [muvlon](https://news.ycombinator.com/item?id=50178723): 推测成因是序列号被当作私钥，或私钥被截断成 8 位；并用蒙特卡洛模拟指出，从 0..255 均匀抽 8 个数出现两个连续值的情况只有约 18% 的概率。
- [cromka](https://news.ycombinator.com/item?id=50180981): 第一手经验：评论者自称用 DeepSeek 快速复现了信任链攻击，发现 Google Home 音箱仍未更新证书链，正在做中间人抓包，尝试借此取得 root 权限，或做 Home Assistant 的模拟端点。

## 6. DuckDB 2.0.0 LTS “Cinnamon Teal” {#story-6}
*#6 on HN · [duckdb.org](https://duckdb.org/2026/10/21/announcing-duckdb-200) · 268 points · 29 comments · [HN discussion](https://news.ycombinator.com/item?id=50181136)*

DuckDB 团队发布了 2.0.0 LTS 版本（代号 “Cinnamon Teal”，支持至至少 2027 年 10 月），自称是迄今为止最大的功能版本，包含约 20,000 个提交。核心内容包括：完善后的 Quack 客户端/服务器协议及新的 CONNECT 语句、Parquet/CSV 的异步 I/O、成为一等公民的 VARIANT 类型、为编码代理准备的 agent mode（在 TPC-H 实验中宣称可将模型需读取的输出量削减 59%）、触发器、可扩展的 PEG 解析器（取代自 2018 年以来的 Bison/YACC 语法）、C API v2，以及自托管、可签名的扩展仓库。旧的 1.5 线支持期延长至 2027 年 3 月，1.4 支持至 2026 年 11 月下旬。

**Discussion**: 讨论基本上是正面反馈，并附有具体的第一手使用报告。RobinL 报告了在 EC2 上、最高约 128–192 vCPU 范围内接近线性的扩展能力（此前速度在约 64 个 vCPU 处就达到上限），并称这使得他的 Splink 记录链接工具能在 10 分钟内处理 10 亿条记录、完成 100 亿次比较——他认为对大多数工作负载来说 Spark 已不再必要，不过人们仍因平台或组织限制而继续使用它。另一位评论者指出，异步 I/O 带来的 CPU 占用提升是瓶颈从磁盘转移到 CPU/内存带宽时产生的自然副作用，而 RobinL 补充说，超过某个核心数后 DuckDB 会“过度并行化”，实际耗时反而变慢。有人称 Quack 的客户端/服务器模式是改变游戏规则的功能（可以把它放到负载均衡器后面，或通过 Cloud Run 扩展到零），但 nicoritschel 指出 Quack 的客户端支持仍然很少，因此他写了一个 Postgres wire / Arrow Flight 扩展。关于异步 I/O 是否覆盖 DuckDB 原生格式，出现了一段简短的更正：一位评论者引用文档说原生格式是同步的，随后一位 DuckDB 开发者回复说，原生格式实际上确实支持异步 I/O。

**Worth reading**
- [RobinL](https://news.ycombinator.com/item?id=50181617): 第一手生产环境数据：2.0 在最高约 192 vCPU 范围内扩展良好（此前在约 64 个 vCPU 处达到上限），使 Splink 能以 10 分钟、单机规模完成 10 亿条记录 / 100 亿次比较。
- [RobinL](https://news.ycombinator.com/item?id=50182776): Splink 维护者认为 Spark 对于大多数工作负载来说过于复杂、难以调优，现在会向有基础设施自由度的用户推荐 DuckDB，并解释说使用 Spark 通常是受 Databricks 等平台限制所致。
- [pdet](https://news.ycombinator.com/item?id=50185157): 一位 DuckDB 开发者更正了上面的文档引用：DuckDB 原生存储格式确实支持异步 I/O，该功能正是他本人实现的。

## 7. Patch the Planet: global response coordination as agents uncover vulnerabilities {#story-7}

## 8. Tiny possum and glider thought extinct for 6000 years found in remote West Papua {#story-8}

A BBC report on two species long thought extinct — the pygmy long-fingered possum, a ~200g striped marsupial whose fourth finger is twice the length of its other digits and is used to dig out wood-boring larvae, and the ring-tailed glider, a tree-hollow-dwelling relative of Australia's greater glider — found alive in remote West Papuan rainforests. The findings, published in the Records of the Australian Museum, were pieced together from decades-old fossils, rare photos and museum specimens, then confirmed on site with help from elders of the Tambrauw and Maybrat clans; co-authors include Tim Flannery, Kris Helgen and Rika Korain. Flannery calls two simultaneous 「lazarus taxon」 rediscoveries remarkable, and warns that logging is encroaching on the glider's habitat, prompting efforts to secure native title so logging requires local consent.

**Discussion**: The small thread starts with relief that the rediscovery might precede protection: one commenter hopes native title is settled before logging companies make the species extinct a second time. Others expect more finds, arguing Papua's interior is so unexplored and so little touched by modern development that further surprises are likely soon. The discussion then turns political, with one commenter describing Indonesian control of the island as systematic ethnic cleansing and cultural erasure of the indigenous Melanesian Papuan population, plus an ecocide driven by military occupation and resource extraction. That framing is contested: another commenter questions what 「cultural erasure」 concretely means, suggesting it can amount to elders lamenting that children adopt other ways of life, and when accused of minimizing state violence, replies that land ownership and tribal conflict are a separate problem from cultural change. No consensus is reached; the thread has only seven comments.

**Worth reading**
- [anon84873628](https://news.ycombinator.com/item?id=50184737): Sets out the political context the article omits: the island's split between Indonesia and Papua New Guinea, allegations of ethnic cleansing and ecocide in West Papua, and the argument that this is among the least recognized humanitarian and ecological crises.
- [red75prime](https://news.ycombinator.com/item?id=50185479): Pushes back on the 「cultural erasure」 claim, asking what it specifically means beyond children adopting other ways of life and separating land-ownership and tribal-conflict disputes from cultural change.

A short post by Michael Steil (pagetable.com) presenting Diorama64, an open-source port (github.com/mist64/diorama64) that puts each Super Mario 64 level on a real table inside the Vision Pro, with the headset acting as the camera while you play with a controller — lean in or walk around to change the view. It is built on the SM64 decompilation and sm64coopdx, plus the SM64 Reloaded (GhostlyDark), Render96 (pokeheadroom) and SwagSkeleton95 texture and model packs. Steil contrasts Xbox CEO Asha Sharma calling decompilation and re-porting 「unmistakably good outcomes for players」 with Nintendo's DMCA takedowns of the SM64 PC port in 2020 and its 2024 Yuzu lawsuit, asking whether Nintendo should be more like Microsoft.

**Discussion**: The thread's biggest agreement is that diorama-style VR is the comfortable corner of the medium: commenters cite Moss, Brass Tactics, Triangle Strategy and Glassbreakers as proof that a fixed, table-scale camera avoids motion sickness, and several say they would rather see Civilization, Fire Emblem or Mario Kart 64 battle mode this way than as first-person VR. A counter-current runs through it — some find headsets claustrophobic, sweaty and too much hassle versus just turning on a monitor, while one long tangent weighs the Steam Frame (Linux, LCD, low pixel density, weak passthrough) against the Quest 3 and Vision Pro. The Microsoft comparison drew the sharpest split: one commenter calls it 「completely unhinged」 and asks who will fund new IP if Nintendo-style risk-taking erodes, others list Nintendo's enforcement record (Gary Bowser's lifetime payments, emulator takedowns, key-cards) and argue piracy has never stopped new franchises. Side threads cover Apple now allowing emulators on the App Store (minus JIT), nostalgia for SM64 and GoldenEye, and annoyance that HN's title filter rewrote 「Best」 to 「Way to Play」 — with replies saying 「best」 was clickbait regardless.

**Worth reading**
- [jerf](https://news.ycombinator.com/item?id=50181183): Argues the VR industry made a mistake by chasing VR rather than plain stereoscopic 3D in a window, citing happy hours with Super Mario Galaxy 2 in 3D and the Wii-era 「waggle」 trap.
- [jmiskovic](https://news.ycombinator.com/item?id=50182783): Pushes back hardest on the post's framing, calling the Microsoft-as-role-model line unhinged and asking what incentives would remain to create new franchises.
- [and0](https://news.ycombinator.com/item?id=50180853): First-hand account of building a similar NES-on-HoloLens diorama, noting Microsoft engineers added Xbox controller support at a hackathon and that AI-assisted decompilation has overtaken his own decade of porting ideas.

## 20. Show HN: Sumi.css – CSS Framework {#story-20}
*#29 on HN · [github.com](https://github.com/vladocar/Sumi.css) · 57 points · 13 comments · [HN discussion](https://news.ycombinator.com/item?id=50180039)*

Sumi.css is a single-file, dependency-free CSS framework by vladocar that styles plain semantic HTML with no classes required — headings, forms, tables, cards, accordions, modals and nav all work from markup alone. It ships at 6.7 KB minified and gzipped, follows the system light/dark setting (overridable via data-theme on any element), exposes every color, font, radius and spacing value as a --s-* custom property, and wraps element styles in :where() so they have zero specificity and are trivially overridden. It relies on :where(), :has() and color-mix(), meaning Chrome/Edge 111, Firefox 121 and Safari 16.2 or newer; the minified build is produced with lightningcss-cli.

**Discussion**: The thread is mostly appreciative and quickly turns into a link swap: people mourning that PicoCSS is now deprecated, and pointing to alternatives including Sakura, the classless-css GitHub list, dropin-minimal-css, and Neat CSS, whose author notes it is only 3 KB. The sharpest criticism is about semantics rather than code: Harry Roberts (csswizardry) objects to the docs' example of an anchor with a destination given role=button, calling it a source of false affordances. Blades CSS, suggested as the Pico successor, gets skeptical treatment — one commenter says the site does nothing to explain itself to newcomers, another complains that its new components are class-based (contradicting Pico's premise), that it keeps the Pico name in its fork path despite the original author asking forks to rename, and questions the odd em-wrapped first letters in headings. Elsewhere a commenter reports a small bug filed as issue #1, and one developer describes a concrete win: handing a non-technical colleague an HTML file plus a classless stylesheet to edit weekly and upload to S3. No real disagreement about the framework itself — the consensus is that it looks good and that the genre is quietly thriving.

**Worth reading**
- [csswizardry](https://news.ycombinator.com/item?id=50185022): Harry Roberts argues that giving a link with a real destination role=button is wrong, because it advertises button affordances the element does not have.
- [xd1936](https://news.ycombinator.com/item?id=50185228): A detailed takedown of Blades CSS as a Pico successor: class-based components, a fork still named anyblades/pico against the original author's request, and confusing site design.
- [elicash](https://news.ycombinator.com/item?id=50182400): A first-hand use case: a classless framework let a non-technical coworker safely edit and re-upload a single HTML file to S3 every week.
