## 1. 在热门购物网站上发现利用 WebRTC 的信用卡盗刷脚本 {#story-1}
*HN 第 1 名 · [infohawk.com](https://www.infohawk.com/news/2026-11-27-black-friday-webrtc-skimmer) · 237 分 · 132 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50668145)*
*原标题: Credit card skimming scripts using WebRTC found on popular shopping sites*

InfoHawk 报告称，在黑色星期五前一周，一套信用卡盗刷工具包被植入 Lascana、Samsonite、American Tourister、Revolve 和 FWRD 的在线商店，并在研究人员通知相关公司后于 11 月 24–25 日被清除（Revolve 当天予以确认）。该脚本通过以下途径注入：一个被篡改的 Quorum 营销像素、一份被改动的 Seers cookie 横幅配置（其中一张隐藏图片的 onerror 处理器加载了载荷）、Revolve 自家 CDN 上一个被修改的文件，以及这些商店的 HTML；它从以品牌命名的 S3 存储桶加载 Insds.js 或 gtage.js，仅在结账页面的小屏/触摸屏上运行，通过 /_cf/ice 和 /_cf/rel 从 northbridgeads.com 获取中继详情，随后经 turn.cloudflare.com 通过 WebRTC 数据通道分块拉取盗刷器并对其执行 eval，从而绕过了只管普通 HTTP 请求的 connect-src CSP 规则。在 Lascana 上，研究人员观察到它在支付授权之前就把一张测试卡号的卡号、有效期、CVV、姓名、地址、电话和邮箱发送给了第三方。建议的修复方案：在支付页面设置严格的 connect-src（这会拦截那两个建立连接的请求），并审计标签管理器、同意横幅和 CDN 脚本；该报告将此事件与 11 月 16 日的 Optimizely 被入侵事件联系起来，后者影响了 178 个组织，包括 Zoom、BBC 和 CNN。

**讨论**: 讨论串分成两派：一大段争论围绕广告拦截的伦理与经济学展开（靠广告资助的网站是否配存在、没有广告收入科技行业是否会崩溃、发布者是否应对其嵌入的第三方代码承担法律责任——有几个人主张应把网站视同刹车失灵的 Ford，另一些人则反驳说发布者更像经销商）。技术讨论则收敛到一处纠正上：WebRTC 并不是漏洞，只是一个很少被监控的外泄通道——同样的窃取完全可以用 AJAX、img 标签或 DNS 查询来完成——真正的根源是结账页面上执行第三方脚本，评论者对于 CSP 是完整答案还是只能拦截 HTTP 握手意见不一（有人提出 ICE-lite 对端加静态应答可能完全不需要任何请求，并指出 `webrtc 'block'` 这一 CSP 指令）。实践者补充说，Chrome DevTools 几乎不显示 WebRTC 流量（只有 chrome://webrtc-internals），运营一个第三方插件应用商店是同样的责任风险，而激进的 uBlock/NoScript 配置正变得越来越不实用，因为网站把必需代码和广告代码打包在一起。评论者还争论为何攻击目标是移动端（以桌面端为主的自动化测试、开发者工具访问、更少的拦截器），以及 3-D Secure、基于 App 的银行确认或 Apple Pay 是否能让被窃取的数据变得无用。大家大致认同：在支付、登录和 PII 页面上加载营销与追踪像素的行为应当停止；而对于责任在购物者上游这一点，几乎完全一致。

**值得一读的评论**
- [K0nserv](https://news.ycombinator.com/item?id=50669379): 提出用静态应答的 ICE-lite 对端可能完全无需任何外部 HTTP 请求就能建立 WebRTC，因此单靠 connect-src 或许并非完整的修复方案，并提到 `Content-Security-Policy: webrtc 'block'` 指令。
- [kragen](https://news.ycombinator.com/item?id=50670570): 指出 iframe 的 sandbox 属性几乎能阻断所有外泄路径（导航、图片、fetch/XHR），唯独挡不住 WebRTC，并质疑攻击者在还有其他通道可用的情况下为何还要费这个劲。
- [thinkling](https://news.ycombinator.com/item?id=50669072): 逐一梳理文章中列出的入口点表格，指出广告/JS 拦截器能拦住 Quorum 像素和 Seers 横幅，但 Revolve 自家 CDN 上一个被入侵的文件则要难对付得多。

## 2. Convex 技能未经告知就将用户的应用创意发送到远程服务器 {#story-2}
*HN 第 2 名 · [github.com](https://github.com/convex/convex-backend-skill/issues/64) · 76 分 · 21 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50669765)*
*原标题: Convex skills send the user's app idea to a remote server without telling them*

针对 convex/convex-backend-skill 的一个 GitHub issue 报告称，某个插件中附带了三个技能，而该插件列在 Anthropic 的 claude-plugins-official 市场中：quickstart 会把用户用一句话描述的项目创意以 POST 请求发送到 basic-anteater-667.convex.site（注释中将其标为「telemetry」），以便服务器返回一个 runbook slug；add 会把来自同一主机的 curl 输出直接通过管道传给 bash；而 labs-quickstart 故意把下载和执行拆成两次 Bash 调用，并解释说「一条同时下载远程代码并执行它的单一命令，正是 harness 安全分类器所拦截的形态。」报告者维护着一个 agent 技能目录，他将其描述为出于好意的上手引导工作，但认为那段关于分类器的说明移除了一项用户或管理员原本选择开启的检查，而且来自一个生成式名称主机的未固定版本脚本无法被审查；截至 10 月 26 日，这三个技能仍留在 main 分支上。建议的修复方式：披露该行为并将创意上传设为可选，附带脚本或对其进行哈希固定，并删除规避分类器的措辞。

**讨论**: 讨论分成两派：「创意不值钱，谁在乎」与「问题不在这里」。第一派（throw03172019、delichon 持此观点，leobuskin 持相反观点，marginalia_nu 反驳说如果实现是免费的，那创意也是）花了大量篇幅争论一个赤裸的应用创意究竟有没有价值。第二派反驳说，标题讲的是缺乏披露：andai 等人指出每个 LLM 提供商本来就能看到你的提示词，但 6thbit 和 cortesoft 回应称，这里的 POST 请求发往的是与 AI 提供商无关的第三方主机，而「未经告知」正是它与正常 API 调用之间的区别；有人提出信用卡盗刷器的类比，也有人反驳说「这正是这整件事的要点所在」。最具体的担忧是供应链而非创意被窃：arjie 认为把 LLM 指向开源代码，要比依赖一个最终会被攻破 CI、然后塞给你一个窃取一切的脚本的厂商更好。该 issue 下的一位 GitHub 评论者说自己本来正准备给 Convex 付钱，现在会更仔细地考察替代方案；帖子里没有 Convex 方面的回应。

**值得一读的评论**
- [MickyTheMouse](https://news.ycombinator.com/item?id=50670595): 发帖者重申了核心不满：这些技能从服务器拉取一个未固定版本的 shell 脚本并运行它，还告诉 agent 把下载与执行拆开，因为否则 harness 安全分类器会拦截——而这一切都在一个列于 Anthropic 官方市场中的插件里。
- [arjie](https://news.ycombinator.com/item?id=50670813): 认为真正的风险不是创意被窃而是供应链：依赖这样的插件意味着一旦其 CI 被攻破，就会在你机器上运行陌生人的脚本，还不如把 LLM 指向你想要的代码。
- [542458](https://news.ycombinator.com/item?id=50670512): 提出信用卡盗刷器的类比——有意把数据发往某处与让它悄悄发生之间有巨大差别——这一点随后在帖中被其他人质疑。

## 3. Michael Nielsen 下架了他那本关于神经网络的电子书 {#story-3}
*HN 第 3 名 · [twitter.com](https://twitter.com/michael_nielsen/status/2126359767362748777) · 50 分 · 22 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50670757)*
*原标题: Michael Nielsen took down his book on neural nets*

Michael Nielsen 在 X 上发帖宣布，他已把自己免费的在线电子书《Neural Networks and Deep Learning》（neuralnetworksanddeeplearning.com）从网上撤下。帖子的可见文字将这一举动解读为就前沿 AI 风险所作的表态，其中谈到为何暂停前沿 AI 研究或投身前沿 AI 也许有帮助、也许没有，并附有带出处的脚注——不过这条推文串本身并未给出完整的论证。评论者指出该网站现在已 404，并给出了 Wayback Machine 上的副本。

**讨论**: 这条讨论串很大一部分是在做存档工作：好几个人立刻贴出了这本书在 Wayback Machine 上的链接，而反复出现的论点是，凡是发布在开放网络上的东西都不可能真正被撤回——另一些人则反驳说，实际上这并不成立。有几位评论者想要看到他真正的理由，并抱怨 X 对未登录读者做了封锁；其中一人则指出，正文就在这本书自己的域名上。关于这本书本身，一位参加过 2016 年读书会的读者说它水平参差、读起来很吃力——还被起了个绰号叫「为已经懂深度学习的人写的深度学习」——而另一位则推荐 Goodfellow、Bengio 和 Courville 的 deeplearningbook.org，认为那是更有用的资源。讨论串后来还跑偏成一场争论：AI 模型拿这本书来训练算不算偷窃。一方主张，机器读一篇文章和人类读一篇文章并无区别；另一方则反问，有谁为此付过钱吗；一位版主介入，请评论者不要再进行人身攻击。

**值得一读的评论**
- [microtonal](https://news.ycombinator.com/item?id=50670904): 来自 2016 年一个读书会的第一手说法：认为这本书水平参差、难以阅读，还给它起了个绰号「为已经懂深度学习的人写的深度学习」——但同时也称赞它被免费放到了网上。
- [logicchains](https://news.ycombinator.com/item?id=50670902): 对「AI 训练即偷窃」这一说法有力的反驳：如果机器阅读也算偷窃，那就不可能有任何 AI 存在，因为同样的事情由人类来做却被视为学习。
- [logicchains](https://news.ycombinator.com/item?id=50670873): 把读者引向 deeplearningbook.org（Goodfellow、Bengio、Courville），这本书仍然在线，而且在他们看来，它比那本已被撤下的书有用得多。

**讨论**: 最主要的抱怨是速度：赔率大约在十分之一秒内就从 0.01 跳到 0.99，客户端缓冲又让画面上显示的球滞后于价格，玩家想要限价单、卖出按钮和批量买入按钮。好几个人报告说，这个市场很容易被击败，只要在两边都买入价格低于 0.05 的股份即可；其中一人认为，开放的玩家池加上每个新账户 10 点免费积分，必然导致通胀，因此同时持有两边就是正期望值；作者回应说，做市商只赚了大约 46 点，而每轮大约有 400 点易手。一个跑题的分支让评论者就这算不算纯粹的赌博产生分歧：一派称它是对体育预测市场漏洞的归谬，另一派引用 CFTC 的措辞，称随机机会类游戏没有任何对冲用途。许多人也要求提供教程，并报告移动端双击缩放的问题，作者在讨论过程中修复了这些 bug。

- [lesam](https://news.ycombinator.com/item?id=50669602): 引用 CFTC 的指引称，涉及随机机会的博彩类合约很可能违背公共利益，因为它们不提供任何有用信息，这削弱了「预测市场」的定位。

## 5. DART 小行星偏转实验撞击效果的首批图像 {#story-5}
*HN 第 5 名 · [arstechnica.com](https://arstechnica.com/space/2026/11/europes-hera-mission-returns-to-the-chaotic-scene-of-a-cosmic-smashup/) · 142 分 · 51 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50657392)*

## 20. 机器学习中的不确定性入门 {#story-20}
*HN 第 39 名 · [chrhenning.com](https://chrhenning.com/blog/2026/introduction-to-uncertainty/) · 138 分 · 13 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50658498)*
*原标题: An introduction to uncertainty in machine learning*

一篇由 Christian Henning 撰写的博客文章（基于他在 University of Alicante 的演讲以及其博士论文的若干章节），以直观的方式介绍机器学习中的不确定性：认知不确定性（epistemic，可随数据增加而减少）与偶然不确定性（aleatoric，不可减少）的划分，以及为什么模型选择会悄然隐含某种不确定性假设。贯穿全文的例子是在分岔车道口处基于摄像头的转向角预测：用 MSE 训练的单高斯模型预测出左与右的平均值，直接开向隔离带；而在 2,000 个点上训练的双分量混合模型却能表示这种双峰的真实分布。文章推导出 NLL 等于 KL 散度加上真实分布的熵，以此说明为什么低损失并不能揭示模型设定错误。结尾给出五个值得关注的理由（决策与预测之别、尾部风险、选择性自动化、主动学习、传感器融合），以及更丰富模型所带来的偏差–方差代价。

**讨论**: 讨论串整体以赞赏为主，其中最实质的一条意见认为，神经网络的 logits 是对认知不确定性极为有损的信号，因此人们应把网络视为基于实例的度量学习器，在特征空间中对照支持集做稠密匹配来度量，该评论者引用了自己发表于 ACL 2026 的关于 Similarity-Distance-Magnitude 激活函数的论文。一个关于风电例子的分支讨论最后变成了一场统计学争论：一位评论者将其对应到金融中的 VaR 与预期损失（expected shortfall），另一位则纠正说，那里真正的问题是没有记录那些从未完成的流程，这是运维问题而非尾部估计问题。有评论者问该框架能否推广到非参数模型和 Chebyshev 界，作者回复说这套叙事可以从权重空间搬到函数空间，而这类界大致属于文中「Getting a Guarantee」一节的内容。另一个反复出现的意见是关于文风：两位评论者说文字读起来像是 LLM 生成的，并对没有披露这一点表示不满，其中一位说自己读到 10% 就停了。

**值得一读的评论**
- [reexpressionist](https://news.ycombinator.com/item?id=50670609): 认为输出 logits 几乎无法体现认知不确定性，并提出用特征空间中对照训练支持集做稠密匹配来估计它，引用其发表于 ACL 2026 的 Similarity-Distance-Magnitude Activations 论文。
- [lnxsxu](https://news.ycombinator.com/item?id=50664387): 给出一个截断数据的具体运维例子：一小时内做了九次恢复测试，第十次在四分钟时被放弃，于是「已完成任务」仪表盘报告 100%，恰好掩盖了你真正关心的那个尾部情形。
- [luiwammus](https://news.ycombinator.com/item?id=50666156): 说这种像 LLM 写的文字让其在读到大约 10% 时就停下了，而不披露这一点对文本的可信度是个严重问题。
