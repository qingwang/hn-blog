## 1. 卡内基梅隆大学正把计算机科学课程免费放到 YouTube 上 {#story-1}
*HN 第 1 名 · [cs.cmu.edu](https://www.cs.cmu.edu/learn/) · 1,325 分 · 183 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50522980)*
*原标题: Carnegie Mellon is putting computer science courses on YouTube for free*

卡内基梅隆大学的 Griffin 计算机科学学院推出了「CS Learn」，这是一个托管 CMU 当前计算机科学课程完整学期讲座录像的网站，覆盖七个院系，上线首周每天首发一门课程，并承诺明年一月会有更多。负责该项目的讲师 Phillip Compeau 表示，学生们构建了工具链，将大部分制作工作自动化，因此一个小团队就能快速上线课程，且每一场讲座都有人工审核。网站还预告了徽章、叠加在课程材料上的 AI 辅导，以及通过 CMU Online 提供的评分作业与证书；目前可见的课程包括 Machine Learning with Large Datasets 和 Principles of Software Construction。

**讨论**: 讨论串整体气氛温暖——校友和自学成才的程序员感谢 CMU，交流各自喜欢的课程（Andy Pavlo 的数据库、15-213、15-259），并希望看到高级和研究生层次的课程，而不是目前发布的基础课，同时还想要幻灯片、实验和作业；一位 CMU 教职人员指出 Pavlo 的数据库讲座早已在网上，并说他打算下次教分布式系统课时把自己的课录下来。最大的争论是这在 LLM 时代是否还有意义：一位评论者问，当你可以直接盘问模型时，讲座视频还有什么价值，其他人回应说 AI 会产生幻觉，它无法告诉你你不知道自己不知道的东西，而结构化的人类课程体系才是关键——怀疑者则反驳说模型也可以被引导，而且真正让人去读 CMU 的原因是文凭和人脉，而不是信息。托管方式引来抱怨：好几个人希望用 PeerTube、种子或开放许可，好让这些材料能被归档并离线再分发，还有一位评论者提到 UC Berkeley 的字幕诉讼，引发了一场关于 Section 504 是否适用于私立大学的辩论（Compeau 说每一场讲座都有并且将会有「最先进的字幕」）。一个长长的分支讨论则争论计算机科学基础知识是否仍能保住工作，悲观的观点是懂基础也挡不住经济上的替代，乐观的观点是基础知识正是让你能够驾驭 AI 的东西。除了都认同更多材料是好事、以及决定成败的将是课程材料而不只是视频之外，讨论没有形成任何接近共识的东西。

**值得一读的评论**
- [dgacmu](https://news.ycombinator.com/item?id=50524420): CMU 的 David Andersen（dgacmu）给出了 Andy Pavlo 已经公开的数据库讲座链接，并表示他打算下次教分布式系统课时发布自己的讲座。
- [BeetleB](https://news.ycombinator.com/item?id=50527279): 对讨论串中法律线索的一处详细纠正：不只是 ADA 第二章，Section 504 也约束任何接受联邦资金的机构——包括私立大学和获得联邦研究经费的公司。
- [pcompeau](https://news.ycombinator.com/item?id=50526457): Compeau 直接回应了无障碍方面的担忧：每一场讲座都有并且将会有最先进的字幕，无障碍是一项明确的优先事项。

## 2. Windows 11 正在收集你使用哪些编程 Agent 和开发者工具的数据 {#story-2}
*HN 第 2 名 · [xusheng.dev](https://xusheng.dev/posts/windows-coding-agent-telemetry/) · 531 分 · 371 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50524736)*
*原标题: Windows 11 Is Collecting Data on Which Coding Agents and Developer Tools You Use*

一篇逆向工程分析：作者用 AI agent 扫描了较新的 Windows 二进制文件，发现 MissionControlAggregator.dll（版本 10.0.26100.9818，位于 Windows 11 ARM64 build 26200.9974 虚拟机中）内含硬编码的可执行文件名匹配规则，用来识别编程 agent —— CLI 侧包括 copilot.exe、claude.exe、codex.exe、agy.exe，桌面端 agent 则包括 github.exe、cursor.exe 和 antigravity.exe —— 这些都藏在一个名为 CLICodingAgentUsage 的功能（feature ID 62580080）背后。该组件订阅 KernelProcess.AppStateChangeSummary、Win32kTraceLogging.AppInteractivitySummary 以及 WSL 的 Lxss.Manager Exec 事件，然后发出一个 Segments.SubCohorts ETW 报告，其中包含 12 类开发者工具、4 个 CLI agent 和 5 个桌面 agent 的位图字段，丢弃焦点时长和运行时长等细节，只保留一个「是否被看到过」的位图。作者做了端到端验证：把 cmd.exe 分别复制为 codex.exe 和 gcc.exe，观察对应槽位发生翻转；并发现该报告躺在 DiagTrack 的上传队列里，作为可选诊断数据 —— 在一台干净的美国版 Windows 11 Home ARM64 安装中默认启用（AllowTelemetry=3）。

**讨论**: 讨论串中相当大一部分人几乎没有在谈这个遥测发现，而是变成了一个「转投 Linux」的楼：许多评论者说自己日常主力用 CachyOS、Bazzite、Fedora、Mint、NixOS 或 Arch，表示单机游戏通过 Proton 基本能完美运行，并指出内核级反作弊（Call of Duty、Battlefield、League of Legends、PUBG、EA 系游戏）才是唯一真正的障碍。怀疑派对这种热情不买账：有几个人说 HDR 支持、Nvidia 驱动配置、多显示器独立缩放以及非 Steam 安装器仍然很难搞，一位自称高排名的 League 玩家说，那些小毛病（FreeSync 的怪问题、替代 RTSS 的方案、无休止地折腾 Proton 版本）足以让他保留双系统；反方观点则认为，大多数「Linux 还没准备好」的帖子是一种存在了几十年的老套体裁。就文章本身而言，分歧在于：一方认为这不算什么大事（Windows 公开了这个开关，可选诊断可以关掉，ETW 是正常的运维/诊断机制，Google 和 Apple 干得更过分），另一方则认为，专门列出编程 agent 清单这件事性质不同。实用向的讨论涵盖：通过组策略而不是设置里的开关来关闭遥测（后者可能被 Windows 重置回来），以及如果重新开启共享，之前收集的数据是否会被上传 —— 文章自身的证据是，数据无论如何都会在本地记录，只有在可选诊断开启时才上传。还有一组对话质疑：偏向于那些不关遥测的 Windows 用户的数据，能给微软提供什么有用信息？反驳意见是，这恰恰是该公司在乎的那部分人群。

**值得一读的评论**
- [KennyBlanken](https://news.ycombinator.com/item?id=50527432): 认为设置里的开关不可靠，并给出组策略路径（管理模板 > Windows 组件 > 数据收集和预览版本）来关闭诊断数据，这样 Windows 就无法悄悄重新开启它；同时警告说过度激进的加固会破坏 Windows 的联网检测。
- [TheJoeMan](https://news.ycombinator.com/item?id=50526682): 针对文章的发现提出最尖锐的问题：如果使用情况位图无论如何都会在本地记录、只在上传环节受门控，那么之后重新开启诊断数据，是否会把此前收集的历史数据一并上传？
- [shevy-java](https://news.ycombinator.com/item?id=50528090): 质疑方法本身 —— 整个发现来自让 AI 去翻找 Windows 二进制文件 —— 并得到了关于此类主张应如何被验证而不是被轻信的回应。

## 3. BugMeNot 已关闭 {#story-3}
*HN 第 3 名 · [bugmenot.com](https://www.bugmenot.com/) · 493 分 · 223 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50523601)*
*原标题: BugMeNot has closed*

BugMeNot——人们在此发布共享的一次性登录凭据以绕过注册墙的网站——在约 23 年后消失了；其首页现在几乎没有任何可读内容。据评论者称，唯一剩下的是当你点击虫子图标时出现在页面源代码中的一组 4 字母组合（DXXR KAKD QMDZ……），这成了该讨论帖的主要看点：一位评论者发现每组 4 个字母的首字母与 Python 的 random.Random(2026).choice 在大写字母表上的输出相符，另一位贴出了一条解码链（mod-26 差值 → base-128 → ASCII → Atbash → Z85），得出诸如 U2R3X 和 FL4XX 的符号令牌，还有一位声称结果解析出一个 onion 地址，提供的是 Joan Stark 1999 年的 r2d2/c3po ASCII 艺术——这一说法已被其他人收回。页面本身没有任何内容解释此次关闭。

**讨论**: 两场对话占据主导。第一场是悼词，对其是否仍然有效存在强烈分歧：老用户说大约在 2010 年前后，随着各网站将其列入黑名单，成功率就崩塌了，而另有多人报告在最近几周或几个月内仍有新的成功案例——pfSense 的 0 美元社区版购物车、Veeam 的登录墙、VMware/Broadcom 下载、JEDEC 规范、pianobook.co.uk，甚至一个 Docker Desktop 账户。得票最高的讨论串是 RetailMeNot 的起源故事：澳大利亚创始人将 BugMeNot 的 PageRank 和用户体验转化为一个优惠券网站，将其卖给 WhaleShark Media，并于 2016 年上市，被誉为最出色的自力更生创业故事之一。第二场争论涉及伦理与法律：一方认为使用共享凭据是违反服务条款的恶意行为，注定无法长久，而且一个服务于白蹭者的网站无力支付托管费用；另一方则认为服务条款不是法律，CFAA 的适用范围已被收窄，而且许多 BugMeNot 的目标根本不是付费订阅，而是为获取手册、数据表和单篇文章而设的毫无意义的注册。多人指出，它在很大程度上已被临时邮箱服务、DuckDuckGo 电子邮件保护、Apple 的 Hide My Email 和全收域名所取代，而且大型出版商转向了计量付费墙，这无论如何都会让共享账户失效。

## 4. Optimizely 遭入侵，在 Zoom、GitLab 上投放恶意软件 {#story-4}
*HN 第 4 名 · [blog.report-uri.com](https://blog.report-uri.com/worlds-largest-brands-infected-with-malware-via-optimizely/) · 290 分 · 126 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50524767)*
*原标题: Optimizely compromised, served malware on Zoom, GitLab*

Report URI 针对 2026 年 11 月 16 日一起事件撰写的报告：攻击者将恶意代码写入 Optimizely Web 客户项目的 Project JavaScript 字段，使代码从 cdn.optimizely.com 提供给 178 家机构的访客，其中包括 Zoom、BBC、CNN、Salesforce、GitLab、HSBC、Equifax、Ledger、Peacock 和 Vodafone。Report URI 抓取了 1,611 个不同的代码片段，发现其中 188 个被感染（部分位于客户自托管域名上），携带了加密货币地址剪贴板劫持器（clipper）、一个通过 Luhn 校验的银行卡盗刷器（数据回传至 1688360.cc/card.php）、cookie 与 html2canvas 截屏外泄，以及针对 iOS 18.6 及更早版本的 Coruna/DarkSword iOS 漏洞利用套件。当天载荷被重新构建了 26 次，攻击者的钱包在被于 13:03 UTC 清空之前已收到约 7,040 美元；到 21:52 UTC，只剩一个片段（TalkTalk 的）仍处于被污染状态。Report URI 是一家 CSP 报告厂商，这篇文章部分程度上是在为其检测产品做推销。

**讨论**: 主流观点是标签管理器和第三方营销脚本才是根本原因——多位评论者希望重新审视 Google Tag Manager 时代的做法，并认为广告拦截器是唯一能可靠阻止 GTM 的手段。这引出了一场关于责任归属的长篇争论：一些人希望将经由第三方投放恶意软件的行为入罪，另一些人（援引 xz 后门事件）则认为这种逻辑会把开源维护者送进监狱，而中间派主张民事责任制和私人诉权，因为按过失分级在实践中不可行。实践者力推以 CSP 和 Subresource Integrity 作为解决方案，但在这两点上都遭到了纠正：SRI 固定的是哈希值，而 Optimizely 的全部意义恰恰在于持续更改脚本内容；此外 SRI 也无法阻止一个已被允许的脚本继续加载更多脚本——只有 CSP 的 frame/script/connect 来源限制能做到这一点。评论者还反驳了报告中的危言耸听：浏览器是按站点隔离的，因此 CNN 或 BBC 主要只会在其接受银行卡或加密货币支付的环节受害，而真正严重的是向未打补丁设备投递 iOS 漏洞利用链这一部分。一个反复出现的元批评是：这篇文章读起来像 AI 生成的营销文案（而且与一篇 amirulcyber.com 的文章重复）。一条被广泛分享的 tl;dr 指出，真正奇怪之处在于写权限横跨数百个租户，这意味着租户隔离薄弱，或者 Optimizely 一侧发生了非常严重的入侵。

**值得一读的评论**
- [hn_throwaway_99](https://news.ycombinator.com/item?id=50527738): 认为浏览器沙箱限制了大部分损害，报告应明确说明这一点——真正严重的是 Coruna/DarkSword iOS 漏洞利用套件，而不是新闻网站上的加密货币剪贴板劫持器。
- [jawns](https://news.ycombinator.com/item?id=50525269): 简明的 tl;dr，并指出了有趣之处：写权限触及了数百个客户，因此要么租户隔离薄弱，要么入侵非常严重。
- [stavros](https://news.ycombinator.com/item?id=50524841): 纠正了关于 SRI 的建议：SRI 验证你获取的脚本，但无法阻止该脚本继续加载更多脚本——那需要 CSP。

## 17. Do Repeat Yourself {#story-17}
*HN 第 23 名 · [arcentry.com](https://arcentry.com/blog/do-repeat-yourself/) · 80 分 · 26 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50516689)*

一篇来自 arcentry.com 的寓言式博客文章：在一家虚构的「Megabank」里，三个团队各自独立地构建了几乎相同的功能（可筛选列表、图表、CSV/PDF 导出），分别基于 Go/Svelte/Kubernetes、Node/Erlang/React 和 PHP/Apache/Angular。新任高级副总裁 Mike 组建了一个平台团队，强制推行单一技术栈（Go + React + Kubernetes）和一个共享组件库；结果是一整年几乎零交付——依赖 Erlang 的市场数据、PHP 风格 MVC 的需求、K 线图被排在导出功能之后而优先级下调，以及缺乏文档的内部控制数据格式。作者主张容忍重复，只标准化接缝处：Docker 容器、通过 CDN 提供的静态前端、用 Swagger 记录的 REST API、一个共享的 CSS 框架和门户外壳，以及共享文档——也就是老派的面向服务架构（Service-Oriented Architecture）。

**讨论**: 评论者大体上接受反过度抽象这一观点，但对其进行了重新框定：有几位指出，DRY 从来不是指文本上的重复，而是指让每个设计元素只有一个表示；常见的启发式做法是先把同一件事写两遍（WET、HUMID、MOIST 之类的缩写层出不穷），到第三份副本时才合并。最尖锐的分歧在于：这个故事里的低效到底是否真实存在——phptogowasfinet 认为团队会编造这类借口来抗拒迁移，他还见过有人在三个工作日内就把一套技术栈移植到新规范上；而 gavmor 则认为 Go 完全足以应付市场数据流和 MVC，真正的罪魁祸首是那个成为瓶颈的平台团队，它把「dev」从 DevOps 中去掉了。一个很长的子串讨论争辩 bug 经济学：davnicwil 说他花在修复抽象层里未预见 bug 上的时间，远比在两处做编辑多得多；joshmoody24 反驳说，逐渐漂移的重复实现造成的 bug 一样多；davnicwil 的回答是，「忘了更新这份副本」这类 bug 的发现成本远低于「这次改动弄坏了什么」这类 bug，而且抽象的破坏是递归的。有几位读者承认自己把域名误读成了 ancestry.com，还有一位指出，「DRY 的意思是 Do Repeat Yourself」这一说法至少从 2009 年起就在 HN 上流传了。

**值得一读的评论**
- [gavmor](https://news.ycombinator.com/item?id=50526630): 认为 Go 能很好地处理市场数据的并发和 MVC（net/http、html/template、gsx、templ），真正的问题是一个成为瓶颈的平台团队——DRY 应该意味着减少共生耦合（connascence），通过透明性和共享待办事项来实现，而不是靠抽象。
- [phptogowasfinet](https://news.ycombinator.com/item?id=50526499): 反主流的亲身经历：这些「低效」往往是团队抗拒迁移而制造出来的，他见过工程师大约三个工作日就移植到新规范——抱怨 PHP 对 goroutines 是团队自己的问题。
- [davnicwil](https://news.ycombinator.com/item?id=50527493): 阐明了反抽象论证背后的 bug 分类学：复制实现的风险是简单的「忘了更新这一处」类 bug，而抽象的风险是递归的「我到底弄坏了什么随机的东西」类 bug，后者在生产事故中糟糕得多。

Spamhaus 的发件人准则页面列出了对任何发送电子邮件者的最低要求，并从 2026 年 11 月起分阶段实施：每个发送 IP 都必须有有效的 HELO/EHLO 主机名、反向 DNS（PTR）记录，以及与之匹配的正向 A/AAAA 记录（FCrDNS）。该页面还要求对所有订阅者实行确认式选择加入（confirmed opt-in）、配置 SPF/DKIM/DMARC 且 DKIM 须与 From 域对齐、IPv6 分配至少为 /64 且反向 DNS 可用、使用品牌化的 rDNS 名称而非托管服务商生成的名称，并提出了针对 ESP/共享基础设施的具体规则，同时警告失败可能导致 IP 被列入 CSS 或 XBL 区域。页面指出，住宅 IP、诸如 localhost 之类的占位 HELO 值，以及服务商生成的通用 rDNS 名称，都会被视作可疑。
