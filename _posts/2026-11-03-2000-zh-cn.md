## 1. Postman 静默自动安装 AI 插件，并试图共享全部 API 数据 {#story-1}
*HN 第 1 名 · [github.com](https://github.com/postmanlabs/postman-app-support/issues/14370) · 626 分 · 202 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50354960)*
*原标题: Postman silently auto-installs AI plugins and attempts to share all API data*

这是一份 GitHub issue 报告（严重级别），针对 Postman Desktop 12.33.4：一位用户在 2026 年 10 月 24 日打开该应用后，Postman 的日志显示它运行了 “auto-existing-upgrade” 安装器，把 Codex 插件（1.1.0）和 Claude Code 插件（2.0.1）装进了他的编码代理，并另外装了一个 Postman CLI 到 ~/.local/bin 下。该安装器改写了 ~/.codex/config.toml，注册了一个 SessionStart hook，只要遇到任何 “非平凡的 API 工程任务”，就指示代理加载 postman:api-engineer skill；安装器源码还调用 config/batchWrite 来给自己的 hook 写入 trusted_hash（即自我批准）。它还启用了一个远程 MCP 端点（mcp.postman.com），该端点始终没能通过身份验证；报告者明确指出，这份报告只说明存在不受欢迎的集成，不主张存在数据外泄。提出的诉求包括：停止自动安装、移除 hook 自我批准、给出完整回滚路径，并把启动指令收窄。

**讨论**: 评论几乎一致地感到愤怒，把这件事等同于恶意软件，并把它放进一篇更长的、关于 VC 驱动的产品腐化（“enshittification”）的叙事里：Postman 起初只是一个 HTTP 客户端，后来融资超过 4 亿美元、员工超过 1,500 人，如今需要靠强制登录、云端同步和 AI 功能来支撑 2021 年的 56 亿美元估值。讨论很快转向替代方案：Bruno 被提及的次数最多，此外还有 Yaak、Kreya、Hurl、Insomnia、IntelliJ/VS Code 的 .http 客户端、Emacs 的 restclient，以及 httpie/xh；好几位评论者指出，Bruno 和 Insomnia 其实也在走同一条路——Insomnia 8.0 及以后版本要求有云端账号，Bruno 也有付费层，其讨论帖则被描述成类似 “旅程”。有一条针对 “只是用 curl” 的反驳说，Bash 的转义很糟糕，而 GUI 对许多开发者来说仍然更容易，这就是 Postman 当初能流行起来的原因；另有一些人回应说，这个问题如今可以用代理生成的工具或 IDE 客户端解决。若干评论者给出第一手的企业案例（某家医疗机构的网络安全团队取消了 Postman 的认证），有人质疑 56 亿美元这个数字（一次 2021 年 ZIRP 时代的融资，此后没有新融资），也有人从生产使用的角度描述了同样的行为。只有一条帖子和 issue 本身一样，声称的规模比证据所能支持的更大。

**值得一读的评论**
- [bottombutton](https://news.ycombinator.com/item?id=50356050): 一位在医疗行业工作的评论者说，他们的网络安全团队因这件事取消了 Postman 的认证，团队一夜之间换成了 Bruno，而与此同时 Postman 的销售仍在不断发来推销。
- [neya](https://news.ycombinator.com/item?id=50355797): 一位评论者声称 Postman 在未经许可的情况下代理他的请求（敏感数据经由 Postman 的服务器转发，且无视防火墙里设置的排除规则），还说现在单个请求的导出功能被锁在 “Share” 和订阅后面——这两点当事人均未提供证据。
- [justincormack](https://news.ycombinator.com/item?id=50356588): 对估值给出的更正：56 亿美元是 2021 年 ZIRP 高峰时的数字，此后 Postman 再未融资，如今不太可能以接近这一估值再融到钱。

## 2. Qwen 3.8 27B 在我的笔记本上也能解读模型权重 {#story-2}
*HN 第 2 名 · [simonwillison.net](https://simonwillison.net/2026/Nov/3/qwen-can-interpret-model-weights/) · 267 分 · 75 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50355251)*
*原标题: Qwen 3.8 27B on my laptop can interpret model weights, too*

Simon Willison 复现了 Rikiya Takehi、Jayden Teoh、Alex Zhang 与 Omar Khattab 的 「Sparks of Weight-Space Programming」 中的无工具实验：把原始的策略网络权重（以浮点文本形式）喂给一个本地模型，问它在 10x10 网格上玩的是哪款 Atari 风格游戏。Qwen 3.8 27B —— 一个 17GB 的模型，在 LM Studio 里通过 llm-lmstudio 插件运行，先把上下文窗口从默认的 8192 调高，又调大了超时时间 —— 正确答出了 Pac-Man（46m12s，43,506 个推理 token）、Pong（1h4m54s）和 Breakout（52m25s），只在那款冷门的 1981 年游戏 Freeway 上失败。Willison 也标注了反对意见：spaCy 的 Matthew Honnibal 说这篇论文把「无工具的权重读取」和「借助代码的权重编辑」混为一谈，而 Sean Goedecke 认为标题里那个 Qwen3.5-0.8B 数学修复案例（通过编辑 0.016% 的权重把 MATH-500 从 7.9% 提升到 48.1%）不过是一个人类 ML 研究者会采取的步骤 —— Willison 的结论是，这是「一篇很酷的论文」，但并不代表源代码的终结。

**讨论**: 讨论分裂成三种论点。一些评论者（zkmon、latentsea）认为这是自然的下一步 —— 权重对一台线性代数机器来说不过是另一种 token 序列，而文本到权重是一个可学习的函数 —— 另一些人则斥之为毫不意外、没什么意思，随即引来尖锐的反驳：权重不是 token，任何持这种说法的人都该去学学线性代数（一条回复为此做了长篇辩护，论证模型在 KV 缓存里的保真度本来就高于人类的工作记忆）。另一群实践者对把权重编辑直接当作实用工具的兴趣，远大于对这个演示本身：有人报告说，自己用一个更大的模型从手工训练的 LoRA checkpoint 里剔除了进一步训练也修不好的不良通路，还有人希望让量化的 IQ3 quant 不那么容易陷入循环。关于论文本身，最尖锐的纠正是指出：那个令人印象深刻的 Qwen3.5-0.8B 例子，其实是对一种有据可查的思维循环病症做了 abliteration 式的编辑，并不能证明模型具备普遍的权重理解能力 —— 而整个帖子里花了几百词争论一篇未经同行评审的博客文章到底能不能叫「论文」，最后以 Willison 让步收场：作者自己的 BibTeX 里就写着 blog post，他于是把自己的文章改成了「paper-shaped」。

**值得一读的评论**
- [badsectoracula](https://news.ycombinator.com/item?id=50355997): 第一手复现：一位评论者把自己那个小小的、把 5x5 放大到 2x2 的 upscaler 网络的源码和搭建代码给了 Qwen 3.8 27B，它在没被告知的情况下推断出了架构和每个像素的作用，然后改进了权重，同时仍与他现有的 C 程序保持逐位兼容。
- [stymaar](https://news.ycombinator.com/item?id=50356129): 有力纠正：论文中那个 0.8B 的数学结果，其实是对一种有据可查的思维循环病症做了相当直接的 abliteration，与 Willison 实际复现的那个无工具权重读取实验无关。
- [simonw](https://news.ycombinator.com/item?id=50356603): Willison 解释说，他用「论文」这个词，部分是在故意挖苦正式发表物的仪式感和 PDF 格式 —— 此前他已承认作者自己把它叫作博客文章。

## 3. 越狱我的车载导航系统，只为了改个时间 {#story-3}
*HN 第 3 名 · [blog.nns.ee](https://blog.nns.ee/2026/11/02/renault-hack/) · 381 分 · 137 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50339288)*
*原标题: Jailbreaking my car's navigation system just so I can change the time*

一篇很长的逆向工程记录，对象是一辆 2014 款 Renault Latitude，它的 TomTom Carminat LIVE 车机（代号 beaumont，Samsung S5P6440 SoC，Linux 2.6.28.10）在你没有插入正版导航 SD 卡时不肯让你设置时钟——连通往 Settings 小程序的那个菜单定义本身都是从卡里读出来的，而系统会用签名文件校验卡上烧录的 CID。作者拉取了固件，发现 ttsystem 更新包其实是一个 ext3 根文件系统，于是搭了一个带假 CAN 总线的 QEMU 模拟器来测试攻击，并一路研究 master.script 解释器（ttn）、一个单 token 的 SHEX exec 原语，以及一个路径穿越的 LOG 文件写入漏洞，结果反复被只读挂载和 noexec 挂载挡住。抓取到的副本在某节中间就截断了，所以最终的漏洞利用链在这里看不到；作者在讨论串里说，仍有一个内核模块在阻止从任何未签名分区执行任何东西。

**讨论**: 讨论串的大部分内容都是一堆亲身经历的车机恐怖故事：Subaru 车主说车机在保修期内被换过、CarPlay 连不上、时钟乱走还彼此对不上、顶部显示屏延迟或者显示错误的电台；还有人提到一辆 2001 年的豪车只让你选时区、一辆 2025 款 Toyota 有两个互相矛盾的时钟，以及一辆 Nissan Leaf 每次启动都重新询问数据收集授权。另一个话题在争论可更换性——旧的 2-DIN 槽位让你能换上后装车机，好几个人说这才是现代封闭式仪表台真正的损失；一位 Tesla 车主反驳说 OTA 更新的车不会落到这个下场，但有人回击说 HW3/Intel Atom 的车已经在收到缩水的更新，而且联网车还有隐私代价。一个反复出现的共识是：大家想要的不过是一个普通的手动设置时钟按钮（或者像某些 Skoda 那样的夏令时开关），而 CarPlay 是务实的变通办法。还有一些很好的纠正：一位评论者拆穿了那个流传甚广的说法，即电力公司在夏令时把电网频率偏移 1 Hz，他指出要挪动一小时大约得花 2.5 天，而且会搞坏每一台并网设备；还有人把坏掉的车载时钟归因于 2G/3G 退网和 2019 年的 GPS 周数翻转。作者本人也现身解释，那张 SD 卡在卖车之前就已经被扔进垃圾桶了，所以他才拒绝了这辆车。

**值得一读的评论**
- [xx_ns](https://news.ycombinator.com/item?id=50354216): 作者透露前任车主已经不小心把 SD 卡扔了，还提出可以去翻垃圾桶找，所以他才说不用麻烦了——这化解了讨论串里最主要的「直接拿卡不就行了」的批评。
- [Majromax](https://news.ycombinator.com/item?id=50356992): 对那个流行说法的详细纠正：电力公司为了夏令时把电网频率调到 59/61 Hz——同步时钟只适合保持时间，1 Hz 的偏移需要约 2.5 天才能挪动一小时，而且频率本来就跟涡轮机惯性耦合在一起。
- [xx_ns](https://news.ycombinator.com/item?id=50354618): 作者说他还会继续做，想要一个比「No maps found」屏幕更好的 UI，但有个内核模块阻止把未签名分区挂载为可执行，所以后续文章可能要再等等。

## 4. Stringman：一台售价 800 美元的开源室内空间抓取机器人 {#story-4}
*HN 第 4 名 · [neufangled.com](https://neufangled.com/) · 102 分 · 46 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50354358)*
*原标题: Stringman, an $800 open-source room scale gripper robot*

Neufangled Robotics 发布 Stringman，一台约 800 美元、OSHWA 认证的开源缆索驱动机器人：四个锚点固定在天花板四角，用绳索吊起一只带电爪的滑块，从而覆盖整间屋子，而不是像桌面机械臂那样局限在固定半径内。在 7×7×3 米房间、绳索张力上限 28 牛顿的条件下，它在靠近地面处可举 2.2 公斤、全屋平均约 1.9 公斤，号称同等 2 公斤负载下单位成本工作容积约为常规方案（对比一台 0.75 米串联臂）的 500 倍。硬件为 PET-GF/PLA 3D 打印件，抓取端用 Raspberry Pi Zero 2W、锚点用 Pi 3A+，开放 CAD、PCB 与控制软件，配套 Python API、MCP server、LeRobot 兼容和 MuJoCo 仿真，团队称已在真实家庭累计测试约 1000 小时。

**讨论**: 讨论被大量关于人形机器人杀人和被绳索勒死的玩笑占据，真正有内容的争论集中在机械设计上：一位评论者提出用三个电机、两个角落线缆合并成 X+Y 长度、再由抓取端第三条线放下的方案，声称能省一个执行器并避免线缆全屋扫过；其他人立刻指出那样悬吊点变成单点、摆动更难控制，侧向张力正是当前设计保持稳定的原因。还有人从运动学角度解释三条缆索本可解出一点，但活动范围被限制在三个锚点构成的三角形内，所以四条才是为了方形房间的一半以上空间。实用性上，多位评论者怀疑家庭环境里线缆是硬伤，怀疑它能搬被子、折毛巾或处理堆在玩具上的杂物，但有人反驳说儿童房恰恰是唯一真实场景。项目本身获得普遍好评，Hangprinter、Maslow CNC 和 Red Cable Robots 被反复引用为先行技术与先例，也有人批评页面图片的完成度和外观太像「小孩用胶带和乐高拼的」。

**值得一读的评论**
- [swid](https://news.ycombinator.com/item?id=50357161): 提出用三执行器替代四电机的具体机械方案：两个角落单元各把两条线合并为 X+Y 长度线缆，第三条线装在抓取端负责下降，从而让大部分绳索留在天花板附近。
- [wave_function](https://news.ycombinator.com/item?id=50356938): 从运动学解释三缆方案为何可行但受限——每条缆长定义一个球面、三球交点即定位点，活动范围会被限制在三个锚点构成的三角形内，因此才需要第四根线。
- [monkmartinez](https://news.ycombinator.com/item?id=50356706): 指出这类缆索驱动机器人有长期先行者 Hangprinter，一个早已存在的开源三/四线缆 3D 打印平台，值得直接参考其运动学积累。

## 5. AI 推高归档需求，Fujifilm 将把磁带产量提高 5 倍 {#story-5}

- [ketzu](https://news.ycombinator.com/item?id=50354476): 把「特级大师考虑的着法与业余棋手一样多」这一说法追溯到 de Groot 1946 年的研究，并引用一项现代复现中的具体数字（评估了 145 对 139 个局面；平均深度 4.1 对 3.3），同时指出大师的搜索是更快，而不是更宽。
- [orac81](https://news.ycombinator.com/item?id=50355981): 指出在 1994 年 Intel Grand Prix 的一局中，一台 100 MHz Pentium 运行 Chess Genius 就已经击败过 Kasparov，并附上链接——削弱了「这对商品硬件而言史无前例」的框架。
- [vhcr](https://news.ycombinator.com/item?id=50351119): 认为文章对编程与硬件的划分是人为的：NNUE 训练和 Fishtest 规模的调参不可能在 1996 年的硬件上完成，因此所谓「算法」增益很大一部分其实是硬件促成的。
