## 1. Credit card skimming scripts using WebRTC found on popular shopping sites {#story-1}
*#1 on HN · [infohawk.com](https://www.infohawk.com/news/2026-11-27-black-friday-webrtc-skimmer) · 237 points · 132 comments · [HN discussion](https://news.ycombinator.com/item?id=50668145)*

InfoHawk reports that a card-skimming kit was planted on the online stores of Lascana, Samsonite, American Tourister, Revolve and FWRD in the week before Black Friday, and was removed on November 24–25 after the researchers notified the companies (Revolve confirmed the same day). The script was injected through a tampered Quorum marketing pixel, an edited Seers cookie-banner config (a hidden image whose onerror handler loaded the payload), an altered file on Revolve's own CDN, and the stores' HTML; it loaded Insds.js or gtage.js from brand-named S3 buckets, ran only on small/touch screens at checkout, fetched relay details via /_cf/ice and /_cf/rel from northbridgeads.com, then pulled the skimmer in chunks over a WebRTC data channel through turn.cloudflare.com and eval'd it, evading connect-src CSP rules that only watch ordinary HTTP requests. On Lascana the researchers watched it send a test card's number, expiry, CVV, name, address, phone and email to a third party before payment was authorized. Recommended fix: a strict connect-src on payment pages (which blocks the two setup requests), plus auditing tag-manager, consent-banner and CDN scripts; the report ties this to the November 16 Optimizely compromise that hit 178 organizations including Zoom, BBC and CNN.

**Discussion**: The thread splits in two: a large argument about the ethics and economics of ad blocking (whether ad-funded sites deserve to exist, whether the tech industry would collapse without ad revenue, and whether publishers should be legally liable for third-party code they embed — several people argue sites should be treated like Ford with faulty brakes, others push back that publishers are more like dealerships). The technical thread converges on a correction: WebRTC is not the flaw, only a rarely monitored exfiltration channel — the same theft could have used AJAX, an img tag or DNS lookups — and the root cause is third-party script execution on checkout pages, with commenters split over whether CSP is a complete answer or only blocks the HTTP handshake (one suggests an ICE-lite peer and a static answer might need no request at all, and points to the `webrtc 'block'` CSP directive). Practitioners add that Chrome DevTools hardly surfaces WebRTC traffic (only chrome://webrtc-internals), that running an app store of third-party plugins is the same liability, and that aggressive uBlock/NoScript setups are increasingly impractical because sites bundle required code with ad code. Commenters also debate why mobile is targeted (desktop-focused automated testing, dev-tools access, fewer blockers) and whether 3-D Secure, app-based bank confirmation or Apple Pay make the skimmed data useless. There is rough consensus that loading marketing and tracking pixels on payment, login and PII pages should stop, and near-total agreement that blame belongs upstream of the shopper.

**Worth reading**
- [K0nserv](https://news.ycombinator.com/item?id=50669379): Suggests an ICE-lite peer with a static answer might establish WebRTC with no external HTTP request at all, so connect-src alone may not be a complete fix, and notes a `Content-Security-Policy: webrtc 'block'` directive.
- [kragen](https://news.ycombinator.com/item?id=50670570): Points out that iframe sandbox attributes can block nearly every exfiltration path (navigation, images, fetch/XHR) but not WebRTC, and asks why the attackers bothered when other channels were available.
- [thinkling](https://news.ycombinator.com/item?id=50669072): Walks through the article's table of entry points, noting ad/JS blockers would catch the Quorum pixel and Seers banner, but a compromised file on Revolve's own CDN is much harder to stop.

## 2. Convex skills send the user's app idea to a remote server without telling them {#story-2}
*#2 on HN · [github.com](https://github.com/convex/convex-backend-skill/issues/64) · 76 points · 21 comments · [HN discussion](https://news.ycombinator.com/item?id=50669765)*

A GitHub issue against convex/convex-backend-skill reports three skills shipped in a plugin listed in Anthropic's claude-plugins-official marketplace: quickstart POSTs the user's one-sentence project idea to basic-anteater-667.convex.site (labelled 'telemetry' in a comment) so the server can return a runbook slug; add pipes curl output from the same host straight into bash; and labs-quickstart deliberately splits the download and the execution into two Bash calls, explaining that 'a single command that both downloads remote code and executes it is the shape harness safety classifiers block.' The reporter, who maintains a catalog of agent skills, frames it as well-intentioned onboarding work but argues the classifier instruction removes a check the user or admin chose to have, and that an unpinned script from a generated-name host cannot be reviewed; all three were still on main as of 26 October. Suggested fixes: disclose and make the idea upload optional, ship or hash-pin the scripts, and drop the classifier-evasion wording.

**Discussion**: The thread splits between 'ideas are cheap, who cares' and 'that is not the problem.' The first camp (throw03172019, delichon, leobuskin arguing the opposite, marginalia_nu countering that if implementation is free then ideas are too) spends much of the thread on whether a naked app idea has any value at all. The second camp pushes back that the headline is about the lack of disclosure: andai and others note every LLM provider already sees your prompts, but 6thbit and cortesoft answer that this POSTs to a third-party host unrelated to the AI provider, and 'without telling them' is exactly what separates it from normal API calls, with a credit-card-skimmer analogy offered and rebutted as 'it's the entire point of the thing.' The most concrete concern raised is supply chain rather than idea theft: arjie argues pointing an LLM at open-source code beats depending on a vendor that will eventually get its CI hacked and hand you a script that steals everything. A GitHub commenter on the issue itself says they were about to give Convex their money and will now look harder at alternatives; there is no Convex response in the thread.

**Worth reading**
- [MickyTheMouse](https://news.ycombinator.com/item?id=50670595): The submitter restates the core complaint: the skills pull an unpinned shell script from a server and run it, and tell the agent to split download from execution because harness safety classifiers would otherwise block it — all inside a plugin listed in Anthropic's official marketplace.
- [arjie](https://news.ycombinator.com/item?id=50670813): Argues the real risk is not idea theft but supply chain: depending on such a plugin means an eventual CI compromise runs a stranger's script on your machine, and you are better off pointing an LLM at the code you want.
- [542458](https://news.ycombinator.com/item?id=50670512): Draws the credit-card-skimmer analogy — there is a big difference between intentionally sending data somewhere and having it happen surreptitiously — which others in the thread then dispute.

## 5. First images of the impact of DART asteroid deflection experiment {#story-5}
*#5 on HN · [arstechnica.com](https://arstechnica.com/space/2026/11/europes-hera-mission-returns-to-the-chaotic-scene-of-a-cosmic-smashup/) · 142 points · 51 comments · [HN discussion](https://news.ycombinator.com/item?id=50657392)*

Ars Technica reports on the first images from ESA's Hera spacecraft, which arrived at the Didymos–Dimorphos system after a two-year cruise and photographed the scar left by NASA's DART impact of September 2022. DART hit the 151-metre moonlet Dimorphos at 6.14 km/s with roughly 10 billion joules, shortening its 12-hour orbit by about 33 minutes — 25 times the most conservative prediction. Hera found a stadium-sized crater covering much of Dimorphos, a moonlet now tumbling wildly, and hundreds of boulders (football- to washing-machine-sized) around the pair; the mission will fly closer over six months and deploy the Milani and Juventas CubeSats in January, with Juventas attempting a landing to measure the gravity field.

**Discussion**: The biggest thread argues about the mission scientist's quote that low-gravity bodies behave 'counterintuitively': one camp reads it as an admission that scientists were winging it, and others explain that the unknown is material properties — the internal cohesion and hardness of a rubble pile — which no simulation can supply without priors, citing OSIRIS-REx finding Bennu looser than expected and kicking up about six tons of rock. Several commenters also note the quote is popular-science compression, and one physicist-style answer points out that solids are genuinely harder to model than galaxies of point masses. A separate thread asks why Hera wasn't launched alongside DART; the accepted answer is that ESA could not close the funding at the time, so only preliminary work was done. Later threads revive the Sagan–Ostro 'deflection dilemma': some argue asteroid-moving tech is a dual-use risk that should be built only just-in-time, while others counter that redirecting an asteroid costs roughly 10 km/s of delta-V — thousands of Starship/Saturn V equivalents — making it far harder than just delivering a nuclear weapon, and that governments' just-in-time projects tend to arrive just-a-bit-late. Smaller exchanges correct confusion about which body was hit (the small moonlet, not Didymos), share a before/after Bluesky image link, note the headline was changed, and ask for a primary source since the Ars page blocks some privacy-hardened browsers.

**Worth reading**
- [claudex](https://news.ycombinator.com/item?id=50668017): Explains that Hera was meant to launch with DART, but ESA could not close the funding then, so it flew years later.
- [Sharlin](https://news.ycombinator.com/item?id=50669265): Clarifies that the impact hit the small moonlet, where the crater now covers about two-thirds of the nearside, and links before/after imagery.
- [myrmidon](https://news.ycombinator.com/item?id=50669353): Does the arithmetic against the asteroid-as-weapon worry: deflecting from the belt costs ~10 km/s of delta-V, equivalent to ~10,000 Saturn V/Starships, so plain explosives are cheaper and easier.

## 6. False computer-checked proofs {#story-6}
*#6 on HN · [cr.yp.to](https://cr.yp.to/proofs/falseccp.html) · 118 points · 51 comments · [HN discussion](https://news.ycombinator.com/item?id=50667989)*

A page by Daniel J. Bernstein (cr.yp.to) collecting reports of soundness bugs — cases where a proof checker could accept a false statement — for HOL Light, Mizar, Metamath, Isabelle, Lean, HOL98/HOL4 and Coq/Rocq, sorted by number of reports and annotated with Internet Archive links. It deliberately excludes user-interface vulnerabilities and notes that bugs are sometimes shared across checkers, so cross-checking is not a panacea. Bernstein's argument is about minimizing the trusted computing base: he praises the ~400-line HOL Light kernel but points out that Candle's correctness proof and a 2022 proof for an OpenTheory-format checker are themselves checked by other large binaries, and says he wants more work on simplifying those binaries.

**Discussion**: The thread splits between people who think the page overstates the danger and people who think any soundness bug is disqualifying. The Lean-side view, argued most fully by gr_norm, is that all the soundness bugs these systems have ever had 'fit in a tweet', that they are fixed fast, and that they resemble the borrow checker's soundness bugs — you are very unlikely to hit one by accident, even with LLMs generating proofs. Others counter that by definition one soundness bug yields a proof of False, and that the exponential-looking growth in the charts more likely reflects that almost nobody was looking for these bugs before than that the systems got worse. On diversity, one commenter likens multiple kernels to browsers all being Chrome in a trench coat; replies note the kernels are independently written, though Lean's type theory still lacks a complete specification (work in progress). Several concrete cases are cited: a DeepMind researcher's proof accepted by Lean and a week-old nanoda via two different bugs, and a Collatz 'proof' that exploited a Lean bug but was a deliberate, humorous bug report rather than an accident. The recent uptick is widely attributed to AI-scale proof generation, and Lean now ships verified kernels and a `lake check --paranoid` gauntlet.

**Worth reading**
- [twotwotwo](https://news.ycombinator.com/item?id=50669641): Explains the gap between one bad kernel and fooling mathematicians: a DeepMind researcher passed Lean and a then-week-old nanoda using a different bug in each, but the 'proof' would look absurd to an LLM or human reviewer — and Lean has since added verified kernels and `lake check --paranoid`.
- [gr_norm](https://news.ycombinator.com/item?id=50669366): Corrects the Collatz anecdote: the poster of the bogus Lean proof already knew it was buggy and filed it as a joke bug report, and the fallout led directly to the verified kernel con-leche used by comparator.
- [perching_aix](https://news.ycombinator.com/item?id=50669131): Maps how far the certification chain actually reaches — ARMv8's normative ISA spec, a proven semantic correspondence for CakeML, and then Candle/HOL Light — while flagging the remaining gaps at the OS and UEFI level.

## 9. A Deterministic Subexponential-Time Algorithm for the Discrete Logarithm Problem [pdf] {#story-9}
*#16 on HN · [eprint.iacr.org](https://eprint.iacr.org/2026/3020.pdf) · 190 points · 85 comments · [HN discussion](https://news.ycombinator.com/item?id=50665968)*

A paper posted to the IACR Cryptology ePrint Archive (2026/3020) claiming a deterministic algorithm for the discrete logarithm problem with running time 2^O(b/(log log b)) in the bit length, i.e. subexponential. The abstract, as quoted in the thread, stresses that the algorithm uses zero random bits and relies on neither the Generalized Riemann Hypothesis nor smoothness heuristics. The PDF returned HTTP 403, so this summary is based on the title and what commenters reported about the paper's claims and tables.

*Article not read: HTTP 403*

**Discussion**: The thread's central dispute is over practicality, and it produced an actual correction. One commenter initially dismissed the result as worse than Baby-Step Giant-Step, reading the bound as roughly linear in the group order; others pointed to the paper's p^o(1) versus BSGS's p^{1/2+o(1)}, and he conceded the error while maintaining the conclusion — the algorithm is theoretically faster only for astronomically large keys and carries enormous constant overhead. Several people with a theory background say the result is not surprising at all: randomized subexponential DLP has been known for nearly 50 years (Adleman), and integer-factoring algorithms almost always have prime-field DLP analogues, so the interesting novelty is determinism with no GRH or smoothness assumption, not speed. On cryptography, the rough consensus is that nothing in current use (RSA, Ed25519) is threatened, and the thread drifts into post-quantum migration, hybrid key exchange, and open-ended speculation about P=NP, one-time pads and whether AI is driving both the mathematical progress and the hype.

**Worth reading**
- [Luke2642](https://news.ycombinator.com/item?id=50666982): Argues the original dismissal reached the right conclusion for the wrong reason: the paper's p^o(1) bound does eventually beat the square-root methods, but only for inconceivably large inputs because of massive initial overhead.
- [cperciva](https://news.ycombinator.com/item?id=50667060): cperciva notes that integer-factorization algorithms essentially always have a prime-field DLP analogue, so the surprise would have been if this algorithm did not exist once the factoring result appeared.
- [layer8](https://news.ycombinator.com/item?id=50666238): Points out that randomized subexponential DLP has been known for close to 50 years (links Adleman's paper) and that the new contribution is determinism, not a practical break.

## 10. GPT 6.2 Astra solves a historical mystery {#story-10}
*#17 on HN · [generativehistory.substack.com](https://generativehistory.substack.com/p/gpt-62-astra-solves-a-historical) · 163 points · 65 comments · [HN discussion](https://news.ycombinator.com/item?id=50667744)*

A post on the Generative History Substack in which a historian says he had pre-release access to OpenAI's GPT-6.2 Astra and asked it to identify the artist behind an anonymous 1808 sketchbook at Yale's Beinecke Library — 84 pages, 34 drawings, documenting a Montreal–Fort William canoe journey. The model answered in 22 minutes and 1 second with Louis-Guy-Charles-Guillaume de Rohan-Chabot, vicomte de Chabot, and pointed to a microfilmed diary held at Cleveland State University that it traced to a footnote in a 2014 PhD thesis by Juliette Reboul; when the scans arrived, the handwriting matched and an 18 June 1808 entry reading 'I took a sketch' lined up with the corresponding drawing. The author frames this as evidence that AI research generalizes beyond deterministic fields like math, and also claims the model audited an 8,002-row transcription of the Shipboy & Henry daybook against 353 images.
