## 1. Build your own decision model {#story-1}
*#1 on HN · [nishtahir.com](https://nishtahir.com/build-your-own-decision-model/) · 230 points · 57 comments · [HN discussion](https://news.ycombinator.com/item?id=50037949)*

Nish Tahir's blog post explains how to turn an off-the-shelf LLM into a single-pass 「system one」 decision model: run Qwen/Qwen3-1.7B, mask the vocabulary down to the token ids for options A–E, and take the argmax of the softmax over just those tokens instead of generating text token by token (11 passes in his illustrative example). He benchmarks the 1.7B model on a random holdout of CommonsenseQA, gets a small gain from a quick finetune, then shows it is badly miscalibrated — correct ~70% of the time in its 0.9–1.0 confidence bin and only ~40% in the 0.8–0.9 bin — and fixes this with temperature scaling fitted at T≈3.797. A companion GitHub repo walks through dataset building, evaluation, finetuning and calibration.

**Discussion**: Much of the thread argues the terminology: mastazi, make3 and an MLE ('howunfortunate') point out that 「decision models」 are zero-shot classifiers, and that Laya is just a finetuned ModernBERT, while others counter that the difference is real — flexible/open-ended label sets, text and image inputs, and an API that feels like a switch statement rather than a chat call. several commenters dispute the architecture claim, with 2bitencryption and kombinatori noting token masking is just constrained generation that caps compute (and thus accuracy), and asking whether Jev does something fundamentally different. Practitioners report concrete wins: Jev in Claude Code hooks to flag dangerous commands, classifying research-paper sections, and a quiz game pipeline that uses it to pre-filter chunks and cut LLM token usage roughly 10x; a Jeffy author adds that once a classification task is fixed, a small locally trained classifier on CPU (94%+ on banking77, 95% F1 email classifier with 50–100 examples) usually beats a general decision model. There is sharp disagreement over calibration — demibabs calls post-hoc temperature scaling 「p-hacking esque」, JMKH42 shrugs 「if it works it works」, and shawntan argues at length that tuning any system component against the reported test set is overfitting and questions what Jev's calibration claim even means. Side threads cover speed (one commenter claims sub-200ms for a browser decision model while another says Qwen 1.7B should already be that fast) and an iOS Safari reload bug traced by a reply to the browser's ~400MB memory cap.

**Worth reading**
- [shawntan](https://news.ycombinator.com/item?id=50040410): A detailed argument that tuning calibration against the test set is overfitting, invoking the old train/validation/test split discipline — 'How Jev manages to claim calibrated probabilities is beyond me. Calibrated to what?'
- [howunfortunate](https://news.ycombinator.com/item?id=50038233): An MLE who has pitched classifiers for years argues plain LLMs have long been cheap, serviceable zero-shot classifiers, so the Jev hype is mostly ergonomics and timing rather than something new.
- [xavortm](https://news.ycombinator.com/item?id=50040366): First-hand use: a quiz-game developer uses Jev to classify whether text chunks can be questions, cutting LLM token usage at least 10x by only escalating pre-filtered content.

## 2. 2D Vehicles {#story-2}
*#2 on HN · [patkerr.co.uk](https://patkerr.co.uk/2d-vehicles/) · 435 points · 94 comments · [HN discussion](https://news.ycombinator.com/item?id=49991852)*

这是 Pat Kerr 的博文与可玩 demo：1996 年 8 月的一个周末，他在 Atari ST 上用 GFA BASIC 写了一个 2D 刚体物理演示（后来移植到 C），成为《Grand Theft Auto》车辆系统的雏形。为纪念 30 周年，他把这个原型用 JavaScript 重制成「remastered」版本，浏览器里可直接玩，并提供 Car、Ship（致敬 1986 年游戏 Thrust）和 Brick 三种模式，以及碰撞墙（B 键）、重力（G 键）、相机死区和速度变焦（Z/X）等开关。技术核心是一套标准 2D 刚体动力学（含力矩），叠加一层刻意近似的轮胎模型——轮胎在自身朝向方向阻力很小、侧向阻力很大，作者承认这更像粘性阻尼而非真实摩擦，是为了「好玩」而做的有意 hack。

**Discussion**: 讨论分成两条主线。第一条是对文章「AI 味」的质疑：不少人（如 tsukikage、carlos256、m00x、frou_dh）指认图表和部分文字是机器生成，whateveracct 称 Pangram 判定前半人类、后半生成式 AI。作者 Pat Kerr 本人下场回应，坦承图表确实由 AI 依据代码生成、只有串联文字是机器写的，正文与代码还原的是 30 年前手工原型的逻辑，并自嘲是「ChatGPT 轻度协助的 PatSlop」；也有人（fxtentacle、forrestthewoods）力挺，认为其中有真正的架构洞见，值得鼓励更多人分享作品。第二条是技术与怀旧讨论：zeroq、Hydraulix989、tonyarkles 补上 Marco Monster 2003 的 Car Physics 和 Brian Beckman 的 The Physics of Racing 等经典资料；许多人对 GTA 1/2 的俯视驾驶手感和电台念念不忘，认为 3D 化后反而失去了那种感觉。也有玩家实测反馈：撞墙判定、开车后切到 Brick 不会减速等细节被作者确认为有意为之。

**Worth reading**

- [baw-bag](https://news.ycombinator.com/item?id=50037988): 一位开发者描述多年未能解决的实操难题：低速倒车入库时车辆会朝轮胎方向侧向滑动，并提到 Multibody Systems Approach to Vehicle Dynamics 一书。

The in-game rulebook claims every rule, vote count and case is drawn from the public record, with sources in docs/research/, and says the politics scores and economics are simplified for play. Commenters say the win condition in Developer mode took roughly 4,000 units against a stated city need of about 82,000, and several assume it was vibe-coded with Claude.

## 4. AI agents in a stand-up call {#story-4}
*#4 on HN · [atoll92.github.io](https://atoll92.github.io/agent-standup/) · 29 points · 31 comments · [HN discussion](https://news.ycombinator.com/item?id=50039630)*

The linked page is the landing page for Agent Standup, a toy dev project that turns a Claude Code session into a live team meeting: a lead agent gives orders, sub-agents join, 「share their screen」 and report back, with a context gauge, token counts, replay/recap/tree views, voices, custom characters and 8 languages. It ships as a macOS app (Apple Silicon and Intel, unsigned), a VS Code panel and side bar, or can be launched from the command line; it requires that Claude Code has been run on the machine at least once, and it is not a native plugin. The author is upfront that it's 「mostly for fun」 and 「made by a bored dev and his robots」, though calls it 「weirdly useful」.

**Discussion**: The thread splits between finding the gag charming and questioning whether the whole premise makes sense. The most substantive critique argues that standups exist to fix a human information-flow bottleneck — agents can pull whatever context they need at any moment, so a scheduled sync is unnecessary, and one should just write a harness where a manager agent continuously reads sub-agents' files and course-corrects them. Others defend the idea that agents do get stuck or loop and hold divergent context, so periodic sync (perhaps every 1M tokens rather than daily) could help them help each other. A recurring practical counterpoint: agent-shipped code still needs review — one commenter says 25–30% of agent output needs fixes, another stopped delegating unreviewed code after finding subtle misunderstandings in plans, and a third cheerfully reports running persistent offices of 5–10 role-defined agents with better code quality than ever. A few dismiss it outright as a gimmick or bubble-era clownery, while a minority note how much the tooling landscape has changed in five years.

**Worth reading**
- [Olscore](https://news.ycombinator.com/item?id=50040211): A commenter building correctness-critical software with the open-sourced Pullboard workflow argues agents code better than most humans but can't see how changes ripple through a codebase, so the real work is process — test-driven development plus an adversarial 「prove it」 review step.
- [necovek](https://news.ycombinator.com/item?id=50040461): The strongest defense of the concept: standups exist because isolated people don't realize they're stuck, and agents get stuck or loop too, so a sync cadence tuned to token budgets rather than days might genuinely pay off.
- [Olscore](https://news.ycombinator.com/item?id=50040281): A concrete number from practice: roughly 25–30% of things shipped by agents need fixes.

## 5. The Lightbulb Computer {#story-5}
*#6 on HN · [lightbulbcomputer.com](https://lightbulbcomputer.com/) · 360 points · 58 comments · [HN discussion](https://news.ycombinator.com/item?id=50029487)*

A design-prototype project by Guillaume Ardaud (Héliographe), a former Apple prototyper in Tokyo, proposing a 「Lightbulb Computer」: a projector plus computer-vision module in the shape of a large bulb, screwed into an Edison socket or a portable lamp base. Demos (kitchen recipe overlays, reading-a-page Q&A, shared maps, smart-home pointing, ambient family board) run on a Mac with custom projection-mapping software, a small consumer 4K laser projector of about 1100 ISO lumens and a basic webcam; Ardaud says the videos are real footage with no AI generation, and frames the concept as an alternative to smart glasses/headsets.

**Discussion**: A large camp praised the concept as one of the more genuinely novel ideas on the front page, with the author dropping in to answer questions, confirm the prototype is real but bulky, and stress that the UX question matters more than the specs. Skeptics questioned whether the 「what does this word say」 demo could be real from a webcam at that angle (he clarified the unit sits under a meter from the page) and, more sharply, that the lightbulb is only a prop, since the videos were shot with an ordinary projector and no bulb-shaped device exists. Prior art dominated a subthread: Animats cited the 2014 Samsung projector phone, Moviphone's 2027 model, ultra-short-throw optics and the difficulty of fighting ambient light, while others countered that revisiting old ideas is legitimate and that a 1-4 steerable-projector bulb form factor makes sense; Johnny Chung Lee's Wii project, MIT's Sixth Sense, Amazon's 2015 room-projection patent, Dynamicland and Folk Computer were all named as ancestors, and Ardaud said Dynamicland visits were a direct inspiration. A recurring worry was always-on cameras and mics — several compared it to a telescreen, an always-listening 「jinn」 or Flock cameras — with the author replying he cares more about a local-processing, open-source version than a Meta/Amazon one; a parallel thread argued printing/drawing beats beaming because projection is not persistent and has shadows, surface and ambient-light problems. One commenter described a working DIY equivalent built from ONVIF security cameras, Kasa smart bulbs, Qwen tool calls and an Nvidia GPU for roughly $100, but with poor latency and image quality.

**Worth reading**
- [heliographe](https://news.ycombinator.com/item?id=50037315): The author gives the actual setup — Mac, custom projection-mapping/rendering software, Apple's hand-tracking framework, a 4K laser projector, a basic webcam — and says it is primarily a research/design prototype, not a product.
- [dbeardsl](https://news.ycombinator.com/item?id=50040166): A sharp criticism that the lightbulb is only a prop, since neither camera nor projector could work through a frosted shell, so the demos imply the bulb does everything when an ordinary projector did the work.
- [heliographe](https://news.ycombinator.com/item?id=50037336): The author's first-hand correction on the daylight objection: most videos were shot in summer daylight with a 1100 ISO-lumen projector, and mostly-white content stays readable, though direct sunlight outdoors would be a different matter.

## 6. PSPi 6 – Raspberry Pi in a PSP {#story-6}
*#7 on HN · [github.com](https://github.com/othermod/PSPi-Version-6) · 66 points · 6 comments · [HN discussion](https://news.ycombinator.com/item?id=50038623)*

这是一个将 PSP 1000 改造成现代掌机的激情项目：一块定制电路板取代 PSP 1000 的原装主板，让 Raspberry Pi 充当大脑。它支持 Pi Zero、Zero 2W 以及配 CM4 载板的 CM4，配备 800x480 LCD、电池监控与省电模式，沿用全部原装按键和摇杆并额外增加两个按键和一个摇杆，可运行 RetroPie、Lakka、Ubuntu、Raspberry Pi OS、Batocera、Kali 等系统。硬件以 CC BY-SA 开源（PCB 文件可自行送厂打样），开发已完成、成品板正在 othermod.com 出货。

**Discussion**: 讨论基本围绕「还有必要吗」展开：有人质疑 PSP 本身就有大量自制模拟器，何必换成树莓派；答复是 CM4 的性能大约比 PSP 高一个数量级，而能真正塞进原壳的只有 Pi Zero/Zero 2。有评论者给出了具体对比——Pi Zero 内存约为 PSP 的十倍、CPU 频率约三倍，但担心模拟器本身的额外开销会抵消掉这部分优势；因此他认为 Cortex 架构、四核的 Pi Zero 2 W 才够用。另一条实用提醒是：闲置多年的 PSP 电池普遍已经鼓包（所谓的「辣枕头」），这反而让更换主板的改造更有吸引力。整体没有明显分歧，更多是对树莓派这类邮票大小的板子如今能提供多少算力的感叹。

**Worth reading**
- [erk__](https://news.ycombinator.com/item?id=50040187): 提醒所有翻出旧 PSP 的人：原装电池几乎都会鼓包，这反而成了改造的额外理由。
- [doodlesdev](https://news.ycombinator.com/item?id=50039542): 给出可量化的对比：Pi Zero 内存约为 PSP 十倍、频率三倍，但担心模拟器开销抵消优势，因此推荐四核 Cortex 的 Pi Zero 2 W。
- [kiririn](https://news.ycombinator.com/item?id=50039198): 指出 CM4 的性能大致比 PSP 高一个数量级。

## 7. Decade-old RAM is making a comeback {#story-7}
*#8 on HN · [theverge.com](https://www.theverge.com/games/1009140/ram-shortage-intel-amd-ddr4-comeback) · 22 points · 6 comments · [HN discussion](https://news.ycombinator.com/item?id=50028647)*

A Verge news post reporting that Intel and AMD are reviving last-generation DDR4 support because of the global memory shortage. Gigabyte says two motherboard lines will support “upcoming” LGA 1700 processors expected in early 2027 — the socket debuted in 2021 with 12th-gen Alder Lake and was DDR5-only from 2024 — and AMD’s AM4 platform got new motherboards alongside a 10th-anniversary Ryzen 7 5800X3D relaunch. The writer’s own price check: a 32GB Corsair Vengeance DDR5 kit is $620 versus $260 for the DDR4 equivalent.

**Discussion**: Commenters mostly treat the premise as an inevitable side effect of the AI-driven memory shortage rather than a boon. One commenter supplies the strongest supporting data point, noting a 2024 eBay purchase of 512GB of DDR4 ECC registered memory for about $537, and that 256GB of DDR5 ECC now costs more than that. Another argues that for ordinary desktop work capacity matters far more than speed, since unused RAM becomes disk cache and wait times come from disk, not memory type. The most pointed response is a question rather than a claim: was there ever a previous case in tech where the technology available to the less affluent literally regressed? Commenters note DDR4 remains fast enough for most uses, with one saying latency feels similar to DDR5 and only bandwidth differs.

**Worth reading**
- [Sesse__](https://news.ycombinator.com/item?id=50040489): Concrete price history: 512GB of DDR4 ECC registered memory cost $536.86 on eBay in 2024, while 256GB of DDR5 ECC now exceeds that.
- [t0mas88](https://news.ycombinator.com/item?id=50040481): Argues that for daily office use more RAM beats faster RAM, since spare memory is used as disk cache and disk waits dwarf memory speed differences.
- [avaer](https://news.ycombinator.com/item?id=50040412): Asks whether tech has ever before regressed for the have-nots — the shortage pushing budget builders backward rather than forward.

## 8. Nix wrote half of my debugger {#story-8}
*#9 on HN · [fzakaria.com](https://fzakaria.com/2026/10/07/nix-wrote-half-of-my-debugger) · 178 points · 38 comments · [HN discussion](https://news.ycombinator.com/item?id=50017247)*

Farid Zakaria 的这篇博文介绍了 Rewind VM：一个确定性的虚拟机，让 Nix 构建的每一次运行都成为其输入的纯函数——包括线程调度——因此竞态条件可以精确复现。它在 stock KVM 上运行一个 vCPU，每 0.25 秒墙钟时间对机器做一次快照（使用 KVM 脏页日志，页面经 BLAKE3/zstd 存放在内容寻址存储中，并在 keyframe、运行和 fork 之间共享），并复用 Nix derivation 来提供输入、源码、调试符号（通过 debuginfod 和 cache.nixos.org 上的 debug 输出），因此每个新的调试器功能——源码面板、栈帧、gdb fork、书签、Compare 标签页、Check from here——都几乎不费吹灰之力。在银行账户丢更新示例中，16 核笔记本上 1000 次运行有 396 次丢了钱，而用 taskset 固定到单核时，1000 次运行一次都没丢；rewind check 将首次失败定位到单个步骤（第 3237 步），整个检查只需 11 秒。

**Discussion**: 评论区大多偏离了调试器本身，转向一个说法：LLM 正在推动 Nix 的采用，因为 agent 现在能写出人们过去不愿学的 Nix 配置。多人（pmarreck、pavo-etc、cedws、bentcorner、POiNTx）描述自己多年来因人体工学问题一直抗拒 Nix，后来让 Claude 写配置、人工审查并提交到 git；jeremyjh 重新表述为：他想要一个 agent 代为管理机器配置，又不想给它太多权限。怀疑者则认为问题在于 Nix 本身，而非技能：nine_k（自称日常用户）指出可发现性和透明度差，模块系统很不简洁；Nihmie 抱怨文档几乎不存在、做事方式太多，并称 Nix 用一个可能更大的问题换掉了一个真问题；pjmlp 说读完这篇文章后仍然不想碰它。目标的反对者也有：iwannakms 报告说写一个复杂 flake 时 nix 把自己删掉了，并抱怨远程缓存超时时间过长；chickensong 反驳说把系统搞成那样很不寻常，NixOS 并不比 Debian 更不稳定，只要保留配置总能恢复，并发帖鼓励试一试。关于 Rewind，saagarjha 问 Nix 与它有什么关系，认为它本质上是在重新实现 rr，而 Cyph0n 和 iwixon 将其与 Antithesis 的确定性运行时相比，只是认为它是一个功能较弱、本地化的版本。

**Worth reading**
