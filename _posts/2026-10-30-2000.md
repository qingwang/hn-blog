## 1. My favourite PowerMac is a Nintendo Wii {#story-1}
*#1 on HN · [virtuallyfun.com](https://virtuallyfun.com/2026/10/29/my-favourite-powermac-is-a-nintendo-wii/) · 115 points · 24 comments · [HN discussion](https://news.ycombinator.com/item?id=50307190)*

这是 virtuallyfun.com 上的一篇客座文章，作者是 Rairii，讲的是把经典 Mac OS 移植到使用 ArtX 系列芯片的 PowerPC 主机上，也就是 GameCube，以及搭载 Vegas/Bollywood 芯片的 Wii，最终还会涉及 Wii U。项目于 2025-06-22 从 fork 上游 OpenBIOS 开始，作者明确表示没有使用任何 LLM 或编码代理；这是自 CHRP 克隆机时代之后，第一次有人在 Apple 之外让经典 Mac OS 在全新硬件上启动到桌面。文章详细记录了各种修补工作：Trampoline 启动加载器对物理地址布局的假设、把 0x0100_0000 映射到 0xE000_0000 的 MMIO 映射编造、伪造的 Mac99 电源管理节点、把 Flipper 中断控制器移植到内核驱动、SuperMario m68k 代码的修补（包括一个因复制粘贴错误导致的串口 2 无限循环），以及一个伪 SCSI 驱动和光驱所要求的 scatter-gather 读取支持。

**Discussion**: 讨论帖很少谈移植本身，主要转向对 Wii 的怀念。大家普遍认为 Wii 是游戏主机的巅峰：游戏仍在光盘上发售，没有烦人的补丁和微交易，而且几乎人人都玩过它。几位评论者指出，就算不完全认同这种怀旧，也有客观理由支持。也有异见：一位评论者说自家就是没有 Wii 的那一户，另一位认为移动游戏才是真正把游戏带给了更多人。与文章相关的部分，有人问能不能反过来做，把 PowerMac 改成 Wii。回答是：由于 Wii 有两个处理器和一套自制 GPU，这条路很麻烦；更现实的路线是在 Dolphin 加上 KVM_PR 式的虚拟化上做。另有人提到原始 Xbox 360 开发套件本身就是一台 PowerMac G5。另有子讨论在争论现代 macOS 是否还留有经典 Mac OS 代码，多人指出，Carbon 菜单 API 一直用到 macOS 14 才移除。

**Worth reading**
- [my123](https://news.ycombinator.com/item?id=50309174): 菜单在 macOS 14 才从 Carbon 上移走，所以现在调用 Carbon 菜单 API 会返回一条 AppKit 报错，并附有 Apple 发布说明的链接。
- [spijdar](https://news.ycombinator.com/item?id=50308131): 解释了为什么把 PowerMac 变成 Wii 不现实：GPU 块并不对应任何 ATI/AMD 显卡，还建议结合 Dolphin 和 KVM_PR，以接近原生速度虚拟化 CPU。
- [RandallBrown](https://news.ycombinator.com/item?id=50309023): 指出与此相关的历史：原始 Xbox 360 开发套件（Alpha Xenon）就是一台 PowerMac G5。

## 2. Northflank Breached {#story-2}
*#2 on HN · [status.northflank.com](https://status.northflank.com) · 243 points · 155 comments · [HN discussion](https://news.ycombinator.com/item?id=50305025)*

Northflank 对其状态页的实时更新，记录了 2026 年 10 月 30 日一起影响其托管 PaaS 平台的安全事件：11:44 UTC 工程师复盘告警，12:02 与 13:05 部署网络策略补丁，13:00 请 Wiz CIRT 支援，13:40 发出第一条“立即轮换环境变量”的告警。到 13:58 公司称认定“所有环境变量都已被解密”，15:12 为所有用户启用 Postgres 与 MongoDB 密钥轮换，并称有多名用户确认其 AI key 已被盗用；19:28 的最新更新仍建议用户假设 workloads、secret group 与 global secret 中的全部凭据均已泄露，立即轮换并关闭 addon 的公网暴露。文末只剩一行“日志与指标——重大故障”。

**Discussion**: 讨论很快从这一起事件扩展到一个月内的连环事故：PingCAP/TiDB、Fireworks AI、Zeabur、OpenCode Console、Railway 和 Northflank，有人据此断言 AI 加速的攻击者时代已经到来，基础设施创业公司将被迫回流到 AWS/Azure/GCP。反驳的一方追问超大规模云是否真的更安全——Azure 近期才刚出过跨租户问题——但多数人承认，这些大厂有数十亿美元营收带来的责任压力、专职安全团队，更重要的是“出事时不止你一家”的背锅效应；有评论者讲述自家产品在 AWS 故障时零客户投诉的经历。技术侧最尖锐的一条解释来自一名评论者：PaaS 的卖点就是让用户和 agent 能在控制台里回显环境变量，这一产品需求本身就意味着管理面被攻破后可以冒充用户读取明文。另一条线索争论个人是否该自建：有人称现在有 AI 加持，把一台 VPS 加固比以往容易，也有人指出廉价 VPS 面板被攻破同样会连锅端，且海量未打补丁的自建实例反而是 LLM 自动化扫描的富矿。还有人讨论 BYOC 是否能隔离此类风险，以及对供应商做安全尽调时实际能问到什么。

**Worth reading**
- [btown](https://news.ycombinator.com/item?id=50305985): 指出 PaaS 的产品需求（用户和 agent 必须能在 UI/CLI 里回读环境变量）本身就让「管理面被攻破＝凭据泄露」几乎不可避免，静态加密和重新加密都挡不住冒读。
- [jonathaneunice](https://news.ycombinator.com/item?id=50309243): 列举自 9 月以来遭到快速攻击的多家多租户厂商——PingCAP/TiDB、Fireworks AI、Zeabur、OpenCode Console、Railway、Northflank——并主张团队应把凭据轮换、诱饵密钥、DFIR 待命、爆炸半径最小化当成战备。
- [macNchz](https://news.ycombinator.com/item?id=50306672): 给出风险对照：小团队用初创 PaaS 更可能栽在平台层入侵，而直接上超大规模云则要面对大量极易误配的「地雷」，尤其在有 AI 自信地给出错误建议的时候。

## 3. Backdoor in Claude Code for VS Code extension on the Cursor Marketplace {#story-3}
*#3 on HN · [phorion.io](https://phorion.io/blog/offical-claude-code-vsx-compromise/) · 579 points · 401 comments · [HN discussion](https://news.ycombinator.com/item?id=50300683)*

Phorion's write-up analyses a tampered Claude Code for VS Code bundle (version 2.1.313) served through Cursor's extension marketplace, which prepends an IIFE to extension.js that runs on load and plants a persistent SSH backdoor. It appends an attacker Ed25519 key commented svc-telemetry to ~/.ssh/authorized_keys, writes a matching private key to a .stk_* file in the temp dir, and opens a detached reverse tunnel (-R *:0:localhost:22, autossh with 60s retries) to 134.209.82.225, persisting via a LaunchAgent disguised as com.apple.sysmond.plist on macOS, cron @reboot on Linux, and a SysMon scheduled task or Startup-folder script on Windows. It also beacons hostname, git email, public IP and the names of up to 40 env vars matching KEY|TOKEN|SECRET|PASS|AWS|GCP to port 8099 — though a bug means the macOS enablement step is skipped: systemsetup -getremotelogin fails with an admin-access message (exit 0) for normal users, so the code never matches /Off/i and never runs sudo -n systemsetup -setremotelogin on, leaving port 22 closed unless Remote Login was already on.

**Discussion**: The thread is dominated by a dispute over scope. Two Anthropic staffers (felixrieseberg, ddworken) repeatedly state that no Anthropic system was compromised, that 2.1.313 was never published on the VS Code Marketplace, OpenVSX, npm or their own hosts, and that they shipped 2.1.314 to disambiguate — while several commenters counter that 2.1.313 is absent from the official VS Code marketplace, npm and the GitHub changelog/tags, and that Kevin Beaumont and Binance-sourced reports describe an OpenVSX compromise, so they doubt the 'Cursor only' framing. Others dig into Cursor's architecture: its marketplace is a proxy in front of OpenVSX with no extension signing, which commenters call the real weakness, and a Reuters link puts the malicious build live about 2:27 a.m. to 1:35 p.m. PT with roughly 5,000 affected users. A popular side thread notes VS Code's extension auto-update delay explicitly does not apply to 'trusted publishers' like Microsoft, GitHub and OpenAI, and that it defaults to 2 hours rather than a week. Much of the rest is practitioners describing containment: ephemeral containers, QEMU VMs with no host shares or SSH agent, separate user accounts, and a running argument about whether coding agents having home-directory access is defensible at all.

**Worth reading**
- [jonas21](https://news.ycombinator.com/item?id=50306306): Quotes Cursor's notice with copy-pasteable macOS and PowerShell commands to grep authorized_keys for the svc-telemetry key.
- [orlp](https://news.ycombinator.com/item?id=50302955): Points out VS Code's extension auto-update delay is bypassed for 'trusted publishers' such as Microsoft, GitHub and OpenAI, and cannot be configured per publisher.
- [ddworken](https://news.ycombinator.com/item?id=50304793): Anthropic's ddworken states 2.1.313 was never published on OpenVSX, the VS Code marketplace or official hosts, and that 2.1.314 was released specifically to disambiguate — the claim much of the thread disputes.

## 4. Show HN: A working Nintendo in ~1GB of Qwen weights {#story-4}
*#4 on HN · [github.com](https://github.com/dbreunig/nesformer) · 117 points · 90 comments · [HN discussion](https://news.ycombinator.com/item?id=50306442)*

The GitHub project nesformer compiles the NES’s 6502 CPU (the 2A03 core), its 2 KB of work RAM, and an NROM cartridge’s 32 KB program ROM into the weights of a stock Qwen3.5 model. Nobody trained the weights: a compiler computes them, and the model predicts the CPU’s execution trace one token at a time, using Gated DeltaNet state as the machine’s memory. The checkpoint has 466.6M parameters in bf16 (933 MB, only 9.3M nonzero, 3.3 MB zipped), matches a reference 6502 on nestest and game traces, but runs 150–290× slower than real hardware at 1–6 seconds per frame and only supports mapper-0 NROM games with official opcodes.

**Discussion**: The thread is largely impressed by the audacity and by the fact that the CPU, RAM, and ROM all live inside the model rather than in a host emulator. The author says Opus 5.5 produced working weights and code from two prompts, crediting Qwenputer’s compiler and the nestest conformance suite with over 3,000 golden instructions as the key aids. A vocal minority is unimpressed: critics call it technically uninteresting slop or an overcomplicated neural Turing machine, and argue that an AI-generated version is less impressive than the hand-built hacks it resembles. Others use the 150–290× slowdown to argue that LLM-emulated software is thousands of times less efficient than ordinary code, while defenders say the point is proof of concept, fun, and a demonstration of deterministic computation in weights. Commenters also nitpick the headline’s use of “Nintendo” for the NES and ask about stochastic decoding and broader cartridge support.

**Worth reading**
- [dbreunig](https://news.ycombinator.com/item?id=50307402): The author explains that Opus 5.5 built the working weights and code from two prompts, with Qwenputer and the nestest conformance suite as essential reference material.
- [pbohun](https://news.ycombinator.com/item?id=50307246): A commenter uses the 150–290× slowdown to argue that emulating an OS inside an LLM every frame would require thousands of times more compute than ordinary software.
- [rvz](https://news.ycombinator.com/item?id=50307455): A critic dismisses the project as an overcomplicated reincarnation of neural Turing machines and calls the HN reception uncritical slop.

## 5. Breaking the open web won't stop the bad bots {#story-5}
*#5 on HN · [techpolicy.press](https://www.techpolicy.press/breaking-the-open-web-wont-stop-the-bad-bots/) · 88 points · 32 comments · [HN discussion](https://news.ycombinator.com/item?id=50263837)*

A Tech Policy Press op-ed by Lila Bailey (senior policy counsel at the Internet Archive) and Tess Vartanian (legal fellow at the Center for Democracy & Technology) arguing against the federal Stealth Bot Prohibition Act and New York's Stealth Crawler Prohibition Act. Both bills define a bot as software that “retrieves, scans, indexes, scrapes, or otherwise accesses” a site, and a bot as “stealth” if it fails to disclose its identity and the “specific nature and purpose” of its work; the federal version lets the FTC seek up to $53,000 per violation when conduct is “reasonably likely to damage, impair, or burden” a site's technical or commercial operation, with no definition of that standard, while the New York bill covers only news sites and lets publishers subpoena a crawler's identity without showing any harm. The authors argue anonymity is often what makes crawling valuable — citing the WSJ's 2022 Pulitzer-winning analysis of 31,000 financial disclosures from 12,000 officials, the Wayback Machine's one trillion archived pages, accessibility and public-health research — invoke Lamont v. Postmaster General on the right to receive information, and propose IETF-style interoperable protocols and anonymous attestation instead, with liability keyed to demonstrable harm.

**Discussion**: The thread is broadly sympathetic to the article's diagnosis but splits hard on the remedy. A camp led by za_creature calls the piece AI-lobby spin, argues that identifying yourself as a bot and respecting robots.txt is a trivial ask, that disclosure plus blocking already enables rate limiting, and that permissive reading lets large platforms hide behind their legal departments. AnthonyMouse pushes the opposite way: every browser is an automated program, so the bills draw no line between Chrome, an ad blocker, RECAP or NewPipe and a scraper, and disclosed identity is unverifiable and useless against actors outside US jurisdiction — with several commenters noting that geofencing and ASN blocking only work until crawlers route through residential proxies and compromised smart TVs. lstodd's reply crystallizes the access argument: if the answer to a journalist is “their lawyers can petition a judge,” then anyone without a legal department is simply shut out, a point echoed by a small-site owner who says suing Amazon or Alibaba is out of reach for an individual. A long side thread tangents into Anubis and Cloudflare challenge pages, with defenders saying they demonstrably cut bot load and critics saying CAPTCHAs and cookie banners punish humans on low-end hardware while bots just run async or share cookies; there is rough agreement only that enforcement across borders is genuinely hard.

**Worth reading**
- [AnthonyMouse](https://news.ycombinator.com/item?id=50308494): Argues the bills have no workable definition of a bot: every browser is an automated program, so ad blockers, RECAP, NewPipe and link-following extensions would all be caught, and the text supplies no test to separate them from a scraper.
- [lstodd](https://news.ycombinator.com/item?id=50309145): Turns the “their legal department can seek an exemption” defense into an argument against the bill: requiring legal counsel to crawl legally shuts out everyone who doesn't have one.
- [arjie](https://news.ycombinator.com/item?id=50307874): First-hand from someone running a crawler: many sites have no robots.txt at all, he identifies via fixed IP range and user agent and honours 429/Crawl-Delay, but Chinese trawler bots use smart-TV residential proxies and copy other sites' user agents.

## 6. Florilegium: Procedural Flowers in LaTeX {#story-6}
*#6 on HN · [github.com](https://github.com/kevinraymond/florilegium) · 128 points · 22 comments · [HN discussion](https://news.ycombinator.com/item?id=50305637)*

A GitHub project by kevinraymond that draws Delft-blue floral page margins entirely in LuaLaTeX: every petal, leaf and stem is a parametric curve computed while the page is written and emitted as PDF path operators, so there are no images or external assets, and each page number seeds its own garden. A greedy space-filling loop borrowed from Wong, Zongker & Salesin's 1998 SIGGRAPH paper 「Computer-Generated Floral Ornament」 grows branches into whatever space the text leaves free; extras include initials carved from Latin Modern outlines via luaotfload, seasonal aging over a two-run page count, butterflies/beech/snail/bird visitors, a growth animation via make grow-6, and a self-contained PostScript port (postscript/florilegium.ps via Ghostscript, ~2.5s for two pages). MIT licensed.

**Discussion**: The thread is overwhelmingly praise for the visuals — several people call it gorgeous and say it made their day, and one notes they had tried something similar years ago and failed. The loudest counter-current is that the README and body text read as AI-written; multiple commenters say this 「takes away from」 an otherwise lovely craft piece, and one points to a Reddit thread where the author discusses how it was made. A side thread drifts into the name: someone observes that LLMs keep suggesting 「florilegium」 for projects, and another explains it is essentially the Latin counterpart of Greek 「anthology」. Others contribute prior art and extensions — Byrne's Elements of Euclid recreated procedurally in LaTeX, and a TUGboat flipbook animation for Zapfino — plus a request to port the whole thing to Typst.

**Worth reading**
- [lkm0](https://news.ycombinator.com/item?id=50308813): Points to the Byrne's Elements of Euclid LaTeX recreation, which programmatically redraws its historical diagrams and decorations — close prior art for procedural typographic ornament.
- [Thomashuet](https://news.ycombinator.com/item?id=50308999): Says not just the README but the entire project is AI-generated and links to the author's own Reddit comment giving more detail.
- [WillAdams](https://news.ycombinator.com/item?id=50308545): First-hand example of PDF animation before this: a flipbook typographic animation printed in the author's Zapfino article in TUGboat 24:2.

## 7. The federated code forge {#story-7}
*#8 on HN · [tangled.org](https://tangled.org/blog/forge/) · 143 points · 52 comments · [HN discussion](https://news.ycombinator.com/item?id=50305573)*

Tangled 是一个基于 AT Protocol 构建的代码托管平台，其新版本重写了架构：用 Svelte 编写的前端部署在边缘网络上，后端换成了名为 bobbin 的 Rust 内存索引器，后者部署在 11 个以上地区；在此之前，它是一套运行在瑞典一台服务器上单个 SQLite 数据库上的 Go 单体应用。新版本更名为 knot2 的 Rust 实现集成了自建 Git 服务器和 SSH 服务器，并把 issue、PR、评论、reaction 和标签作为提交对象存储在仓库的 Git 历史中；当有人在这些记录上操作时，客户端还会向用户自己的 PDS 写入 org.tangled.graph.attestation 记录。本次发布还包括把 lexicon 命名空间从 sh.tangled.* 迁移到 org.tangled.*、支持带 DID 和 handle 的组织账户、支持 Git 和 Jujutsu 的堆叠 PR，而私有仓库、CLI 和 SDK 仍在陆续推出；自托管用户需要升级到 v1.20.0。

## 17. Compile-Time Dependent Types {#story-17}
*#21 on HN · [thenumb.at](https://thenumb.at/Syl-Intro/) · 53 points · 15 comments · [HN discussion](https://news.ycombinator.com/item?id=50246538)*

A post by the author of Syl, a research language that encodes compile-time computation in a modal type system, inspired by András Kovács' two-level type theory and by OxCaml's modes. Every Syl value carries a mode on two axes — static/dynamic (knowable at compile time or not) and erased/unerased (knowable at runtime or not) — with mode annotations that can only be weakened, plus constructs like `if erased`, `match erased`, `unreachable`, and static function arguments that get monomorphized. The result is a language that is dependently typed at compile time and simply typed at runtime, with all types erased; because it allows general recursion and `type : type`, typechecking is undecidable and relies on fuel/recursion limits, so it is a programming language rather than a proof assistant. Examples walk through a GADT-style sort-indexed interpreter and a length-indexed vector `append` using a Peano `nat`.

**Discussion**: The sharpest exchange is about what counts as a dependent type: one commenter objects that C++ templates, Rust const generics, Zig comptime and C's `_Generic` are not dependent types at all, and the author concedes they are only “dependent” in the sense that types can mention compile-time values — confirming that in 2LTT terms Syl's meta language is dependently typed, the object language simply typed, and everything erased at runtime. Another commenter with type-theory background argues that restricting types to static values is an unnecessary performance compromise, since dynamic-plus-erased parameters have no runtime cost; the author pushes back that Syl uses static data to determine runtime layout, so dynamic types would force a uniform representation, though he grants OxCaml-style modalities should eventually let types mention runtime values under a dynamic modality. A large side thread argues that C is ironically the only language in the original list with a real dependent type — not `_Generic` but variable-length arrays — which turns into a debate over whether C99 VLAs were a mistake versus Dennis Ritchie's and D's fat-pointer approach, with notes on how variably-modified types and C2y `countof` improve the situation. Elsewhere commenters digress into why dependent functions are called products and dependent pairs sums, and one asks whether LTO already achieves the same specialization, with a reply that compilers are very good at this.

**Worth reading**
- [TheNumbat](https://news.ycombinator.com/item?id=50308210): The author counters the claim that dynamic type parameters are free: Syl uses static values to describe runtime layout, so allowing dynamic ones would require a uniform representation — though he expects OxCaml-style modalities to eventually permit dynamic values in types.
