## 1. Ultramarine 1 Flash {#story-1}
*HN 第 1 名 · [paperinstruments.com](https://www.paperinstruments.com/ultramarine) · 166 分 · 50 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50106747)*
*原标题: Ultramarine 1 Flash*

Paper Instruments 发布了 Ultramarine 1 Flash，一个面向专业知识工作（金融、法律、咨询、运营）的 agentic 模型，其构建方式是对开源基础模型 GLM-5.3 Flash 施加大规模强化学习，API 定价与其基础模型相同，按每百万 token 计费。它声称以每任务 $0.13 的成本达到「Fable-class」水平——击败每任务 $8.19 的 Claude Fable 5 (max) 和每任务 $2.09 的 GPT-5.6 Sol (max)——同时与 Claude Opus 5.5 (max) 和 GPT-6 Sol (max) 的差距在三个百分点以内，衡量依据是该公司的内部 PI Knowledge Work 基准（他们称其与 Artificial Analysis Intelligence Index 的相关性为 r = 0.81）。它还表示，在六个基准上，该模型输出的 token 数比其基础模型少 6.5%。

**讨论**: 最主要的讨论线索是对营销的不信任：评论者指出，结果部分只把 Ultramarine 与它在每一项指标上都胜过的模型相比较，随后每任务成本图表却突然重新引入更强但更贵的模型（Fable 5.1、GPT-6 Astra、Opus 5.5），还有几个人称「Fable-class」这一标签是错误的——其中一人说图表显示它属于 Luna 级。一个反复出现的反应是，这看起来像是给 GLM-5.3 Flash 套了层皮／做了后训练，一位评论者引用技术报告的措辞，证实了在 GLM-5.3 Flash 基础上做强化学习的说法；另一位指出，它在编码上其实略差一些（DeepSWE 61.5，基础模型为 63.4，TerminalBench 2.1 也更低）。人们争论「frontier model」到底意味着什么——是智能前沿（Fable、Astra、Opus 5.5），还是成本／性能的帕累托前沿——还有几个人问是什么 harness 生成了 Excel/PowerPoint/Word 输出，由此引出一个名为 Radix 的「knowledge work harness」的自我推广，以及 Paper Instruments 自家 Feather 的链接。有人提出更便宜推理带来的隐私担忧，并得到了部分回应（可以从符合 ZDR/GDPR 的供应商那里购买开放权重推理）。总体氛围：性价比确实有趣，基础模型也有用，但基准测试和定位被认为经过了挑选。

**值得一读的评论**
- [CobrastanJorji](https://news.ycombinator.com/item?id=50128230): 对图表挑选数据的详细批评：结果图表省略了更好的模型，随后成本图表又把它们放回来，而这个模型本应直接以第二名来呈现。
- [randomblock1](https://news.ycombinator.com/item?id=50127783): 引用数据说明它在编码上略逊于其 GLM-5.3 Flash 基础模型（DeepSWE 61.5 对 63.4，TerminalBench 2.1 也更低）。
- [nl](https://news.ycombinator.com/item?id=50128064): 认为「frontier model」指的是推进智能前沿，而帕累托式的每任务成本是个弱的衡量标准，因为微调一个小模型在任何重复性任务上都能胜过一个大模型。

## 2. Llama.cpp 在已越狱的 PS5 上：在主机上原生运行任何 GGUF 模型 {#story-2}
*HN 第 3 名 · [github.com](https://github.com/cobanov/PS5LM) · 264 分 · 64 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50122431)*
*原标题: Llama.cpp on a jailbroken PS5: run any GGUF model natively on the console*

PS5LM 是一个以 GPL-3.0 授权的 GitHub 项目（作者 cobanov），在已越狱的 PS5 上以 llama.cpp 的 Vulkan 后端驱动主机的 RDNA 2 GPU，开放 11.4 GB 共享内存给模型与上下文。它在区网上提供 OpenAI 的 /v1/chat/completions、Anthropic 的 /v1/messages（可用 Claude Code 连）以及浏览器聊天页，并加上电视界面、温度／功耗监控与 Hugging Face 下载器；另可载入 Ollaya 的决策模型走 /v1/systemone。需求是固件 7.00–13.60 的越狱主机与特定 payload，实测约 20 tokens/s、64k context，跑的是低量化（2-bit）的 Qwen 27B 级模型。

**讨论**: 最长的一条讨论串是「不该把这种项目放在 GitHub」，有人主张自架网域、有人说 Sony 根本不在乎你跑 llama.cpp、只在乎盗版游戏，也有人说 2026 年除了 TOR 或 torrent 之外无法真正规避 DMCA，最后走向 radicle、自架 Git 等去中心化方案。硬件经济学是另一大战场：有人贴出 $385 的 Beelink N150 mini PC 比 $600 的 PS5 划算，随即被反驳两者 GPU 性能差一个数量级、N150 连小模型都很慢，也有人指出 BC-250（PS5 APU 的降规版）才是便宜又合理的替代品。多位实际用过 Qwen 3.8 27B 的人表示该模型本身接近 Opus 4.6 水准，但 2-bit 量化明显退化，且需要极长推理时间，因此不同意「20 tps 完全没用」的说法——有人说拿它来读 codebase、找问题已经够用。整体没有共识，但气氛偏向「有趣的成就」，同时提醒这台主机规格其实不划算。

**值得一读的评论**
- [sourweasel](https://news.ycombinator.com/item?id=50127127): 指出 PS5 硬件几乎等同 AMD BC-250 矿卡机（同为降规 APU，只是 VCN 媒体引擎被锁），玩家已能把 8 核中的 2 核与 GPU 的 24 个 CU 还原到 40 个，价格曾经低于 $100。
- [kadoban](https://news.ycombinator.com/item?id=50127584): 有实际经验者说 Qwen 3.8 27B 大约在 Opus 4.6 等级，但 2-bit 量化明显变差，是「还能假装能用」的最小量化，不会取代 Claude。
- [p1necone](https://news.ycombinator.com/item?id=50125649): 反驳 mini PC 比 PS5 划算的说法：两者 GPU 性能差一个数量级（PS5 约 10 TFLOPS vs N150 几乎跑不动模型），但也认为自组一台配 16GB 9060 XT 的机器会更好。

## 3. Claude 揭示 ECDSA 曲线种子的来源 {#story-3}
*HN 第 5 名 · [anthropic.com](https://www.anthropic.com/research/ecdsa-curve-origins) · 817 分 · 309 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50122800)*
*原标题: Claude reveals ECDSA curve origins*

Anthropic 的一篇研究文章（帖子中还指向 Filippo Valsorda 关于该悬赏的博客文章）给出了长达数十年之久的 NIST/ANSI 椭圆曲线“种子”从何而来的答案。Claude 并没有找到“给 Bob 和 Jerry 加薪”这类幽默密码短语的哈希值，而是发现这些种子是 lrand48 C 库 PRNG 的原始输出，并用 Unix 时间戳作为种子——P-256 种子是第 1842 个候选项，时间戳如 1997-08-16 01:52:34，而二进制的种子映射到 1984 年 2 月的日期，加倍后为 1998 年 4 月 17 日。文章还解释了六条曲线的基点，其中来自 Lenstra 的 FreeLIP 生成器，种子为 20000、20420、20507、20509、20512、20517，并指出 B-163 以及 P-224/P-256/P-384/P-521 的基点仍无法解释；36,864 美元悬赏金捐给了 ISRG。

**讨论**: 最大的分歧在于这一发现是否真的排除了蓄意弱化。fidotron 认为这没有证明任何东西：生成发生在数月之内，被丢弃的候选项不可见，也没有人披露时间戳作为证据，因此不能排除存在“未披露的选择标准”。Filippo Valsorda 反驳说，即使 NSA 在 1997 年尝试了每一个时间戳，挑选可行的候选项也只会带来大约 30 比特的自由度，而一类可随机撞上如此多弱曲线的弱 256 位曲线，将构成与 ECC 被攻破同等量级的突破——随后像 tptacek 这样的密码学评论者也指出，Koblitz 和 Menezes 在 2015 年就提出了同样的论证。几位评论者都赞同，对于使用同一个 PRNG、由时间播种的代码而言，“没有解释的跳过”和可疑之处都在意料之中；有人（cyphar）指出，被跳过的大多是不产生有效曲线的 n 值。一个大型并列话题是 Anthropic 的防护措施：一些评论者说，他们曾因与密码学、bio 或“C&C 服务器”相关的问题被降级或拒绝回答，而 sweis、tptacek、Retr0id 和 dogben 都表示，他们或其他人曾尝试过这个确切的种子问题，并没有被阻止——他们据此主张，开放权重模型才是答案。较轻松的话题包括多年来关于后门和 NSA 的阴谋论，以及 Jerry Solinas 的轶事遗产：sweis 说，他找了四位消息源（其中两位是前 NSA 人员）核实了那个密码短语的故事，结果大家都错了。

**值得一读的评论**
- [FiloSottile](https://news.ycombinator.com/item?id=50125469): Filippo Valsorda 计算得出，即使完全尝试所有 1997 年的时间戳，加上挑选可行候选项，也只会得到约 30 比特的自由度，因此任何基于种子来蓄意安装后门的理论都必须假设 ECC 已经被攻破。
- [nullc](https://news.ycombinator.com/item?id=50128379): nullc（libsecp256k1 的合著者）认为，发现这个方案并不能使 NIST 曲线变得“刚性”：它仍然留有 20–25 比特的自由度，外加方案选择上的自由度，因此偏好刚性参数的理由并未改变。
- [sweis](https://news.ycombinator.com/item?id=50124233): sweis 报告了他实际提交的 FOIA 请求（NIST 以没有记录为由关闭；NSA 无视），并说他不确定如何让请求足够具体以得到答复。

## 4. 你本可以从记忆中发明出 transformers {#story-4}
*HN 第 6 名 · [alexwang.ai](https://alexwang.ai/posts/associative-memory/) · 241 分 · 63 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50122878)*
*原标题: You could have invented transformers from memory*

Alex Wang（HN 用户 ketothekingdom）在 alexwang.ai 上的一篇博文，通过将 LLM 视为联想记忆存储来建立直觉，并以干扰信号比和容量来框定每种架构。文章从线性外积记忆 W = Σ vᵢkᵢᵀ（容量 ≈ d_k）讲起，再到最小二乘最优线性存储——它通过 (KᵀK)⁻¹ 对键做白化，将容量大致翻倍到 ≈ 2d_k，然后是 MLP，用非线性抑制低相似度的键，最后是自注意力，文章声称它能存储潜在无上限数量的记忆。在 64 维键的情况下，文章引用的容量从约 64 条记忆跃升到约 2,700 条，再到超过一百万条，还包含交互式动画（吉祥物是一只 kea 鸟），并附带一个旁注：在线性层上做单步梯度下降本身就是一次记忆写入，并引用了 Irie、Csordás & Schmidhuber。

**讨论**: 讨论串分裂为赞美与一场关于可及性的漫长争论。许多读者称这是他们见过写得最好的科普之一，还有几人赞赏那只动画 kea 吉祥物；另一些人喜欢「AI 记忆是一个通信信道问题」（干扰信号比、容量）这一框定方式，一位电子工程师说他们用 Gemini Argon 把文章翻译成了 DSP 术语。最大的子讨论串是 craftkiller 的抱怨：文章对程序员受众没有帮助，因为它使用数学符号却没有具体的数据结构或完整示例，而伪代码加一次逐步跟踪的插入／查询会触达更多 HN 读者；saghm、Nevermark 和 soulofmischief 反驳说 HN 的既定宗旨是任何能满足智识好奇心的内容，数学本身就是内容，作者选择什么符号是他的权利；mrandish 则部分站在批评者一边，说那个平易近人的开头让他们以为会在符号出现之前先看到核心思想。craftkiller（被大量点踩）认为这些踩证明 HN 敌视反馈，并称他的立场被误读了。另外，一位读者问 LLM 注意力里的值是什么，得到澄清：Q、K、V 都是 X 乘以学到的矩阵，K/V 构成一个以相似度匹配的字典，softmax 给出的是加权求和而非单次命中——有几人指出这才是与「外积记忆的联系所在，而不是精确的字典查找。

**值得一读的评论**
- [wilkystyle](https://news.ycombinator.com/item?id=50126542): 回答了那个悬而未决的问题——LLM 中的键和值是什么意思——明确写出 Q = XW_q、K = XW_k、V = XW_v，以及基于相似度查找和值的加权求和的字典类比。
- [craftkiller](https://news.ycombinator.com/item?id=50127950): 可及性批评最尖锐的版本：问题不在于数学本身，而在于未定义的数据结构和没有完整的示例，把脱离上下文的符号比作被塞给一篇日文文章，而母语者却说「学着点日语就行了」。
- [kccqzy](https://news.ycombinator.com/item?id=50127355): 为想自己运行干扰实验的读者指出了博文图表背后的实际代码（KeAWang/associative-memory-blog，crosstalk.py）。

## 5. 加利福尼亚正在为优胜美地最危险的公路建造一座 4 亿美元的防护屏障 {#story-5}
*HN 第 7 名 · [sfchronicle.com](https://www.sfchronicle.com/california/article/yosemite-national-park-highway-140-22463847.php) · 32 分 · 20 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50088937)*
*原标题: California is building a $400M shield for Yosemite's most dangerous highway*

Eli Bendersky 的博客文章用三个例子介绍蒙特卡洛方法：用投掷飞镖估算 π（他指出约需 100 亿个样本才能可靠地精确到小数点后 4 位，误差随 1/√N 下降）；估算 SET 纸牌游戏中随机抽 12 张牌没有「set」的概率——Knuth 的 setset-all 精确枚举出 2,284,535,476,080 种无 set 牌型，占 C(81,12)=70,724,320,184,700 总数的 3.23%，而他跑 1000 万次模拟得到 0.0323，15 张牌的情形约为 0.00037；以及退休金提取模拟：100 万美元、每年取 30,000 美元、4% 收益/2% 通胀的朴素算法显示钱能撑约 55 年，但基于历史分布抽出收益与通胀、跑 100 万次模拟后，约 25% 的情景在 22 年内耗尽资金，能撑满 30 年的概率只有约 60%。代码已发布在 GitHub。

## 17. 什么是 Token Ring 网络？ {#story-17}
*HN 第 33 名 · [dfarq.homeip.net](https://dfarq.homeip.net/what-was-a-token-ring-network/) · 109 分 · 83 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50118318)*
*原标题: What was a Token Ring network?*

一篇回顾性文章，来自复古科技博客 dfarq.homeip.net，讲述 IBM 的 Token Ring 局域网——环形拓扑、令牌传递的 Ethernet 替代方案——从它的起源（功劳归于 Datapoint；这家办公自动化先驱推出的 8 位 Datapoint 2200 促使 Intel 开发出 8008/8080/x86 这一产品线），到 4 Mbit/s 和 16 Mbit/s 的 IBM 部署、MAU 与结构化布线，直至它被 Ethernet 击败。所链接的正文无法抓取（返回的是二进制乱码），因此文章的具体内容只能从 HN 评论者引用的句子中得知：Token Ring 也有同轴连接器，但在 Ethernet 上更常见；一个 16 Mbit 环网只要接入一个 4 Mbit 节点，就会导致整个网络瘫痪；以及作者的论断——Ethernet 胜出是因为更便宜，也因为规模效应；廉价版 Ethernet 是垃圾；更高速的 Token Ring（大约 100 和 128 Mbit）确实存在，但很少部署。

**讨论**: 这场讨论主要是怀旧和一线实战故事，开场是有人感叹标题里用了过去时——Token Ring 在 1990 年代的计算机课程、CompTIA 和 Microsoft Networking Essentials 考试，甚至英格兰的 GCSE 课程中都被当作主流技术讲授，尽管许多评论者从未见过它实际运行。几位从业者证实，它在生产环境中留存的时间比预期更长：银行、医院（1998 年还有一家医院在用 Token Ring 布线）、Merck 在 90 年代后期的迁移，以及需要 Ethernet-over-Token-Ring 适配器的 IBM 办公室。评论者对文章的叙述框架提出反驳：kjs3 认为 Ethernet 胜出的唯一原因就是成本，而更高速 Token Ring 的说法（尤其是 128 Mbit）看起来像是 LLM 幻觉；其他人补充说，IBM 押注的是 ATM 用于扩展，而不是 Token Ring；baud9600 引用早期 Ethernet 研究，指出在竞争条件下可用利用率约为 37%，因此尽管 4 Mbit Token Ring 的原始速率更低，其确定性访问在营销上仍是一个站得住脚的论点。关注技术的发言者指出，令牌传递提供了确定性访问，这支撑了速率单调调度理论，并以令牌桶限流的形式延续至今；2019 年的 10BASE-T1S 车载以太网标准还使用了虚拟令牌环；而一位评论者反驳说，ARC156 Token Ring 在 2026 年仍在部署，用于 Automated Logic 的 WebCTRL 楼宇自动化系统。大致共识是：Token Ring 输在价格和生态，而不是设计；就细节而言，这场讨论比文章更有价值。

**值得一读的评论**
- [kjs3](https://news.ycombinator.com/item?id=50120358): 一位实际用过这套设备的人对文章准确性所做的直率批评：Ethernet 赢在成本和芯片简单性，智能 MAU 与 UTP 集线器大约在同一时期让速率不匹配问题不再重要，100 Mbit Token Ring 几乎没能出货，因为 IBM 转而力推 ATM，而 128 Mbit Token Ring 的说法闻起来像是 LLM 幻觉。
- [Animats](https://news.ycombinator.com/item?id=50125766): 对奇特同轴基带网络的亲身经历：Apollo Domain 的 RCA 莲花插头令牌环、粗缆与细缆 Ethernet、Hyperchannel 和 DECNET 三同轴电缆，以及为什么非差分基带同轴需要射频工程师级别的知识，从来不适合普通办公室。
- [quickthrowman](https://news.ycombinator.com/item?id=50120669): 纠正文章的过去时：ARC156（ARCNET）在 2026 年仍在使用，包括 Automated Logic 的 WebCTRL 楼宇自动化系统，并以一份厂商 PDF 为证。

## 20. /dev/null：面向开发者的社交网络 {#story-20}
*HN 第 40 名 · [dev-null.sh](https://dev-null.sh) · 146 分 · 129 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50121004)*
*原标题: /dev/null: social network for developers*

/dev/null（dev-null.sh）是由 Matthieu Napoli（mnapoli）和 Nuno Maduro（nunomaduro）打造的面向开发者的 Twitter 风格社交网络，据称是在为期两天的直播鏖战中、距离上线还有 48 小时时以零行代码起步写成的。它是 Laravel 后端配 TypeScript 前端，仅通过 GitHub OIDC 认证用户，并把帖子重新包装成共享日志里的 commit：你的第一个 commit 需人工审核通过，之后的则由 AI 审核者放行，其宣传语是「没有点赞、没有转发、没有算法」。抓取到的页面并不是一篇文章，而是上线当天帖子的抓取信息流（Taylor Otwell 为 Laravel 叫好、作者在直播、PR 链接），源码在 github.com/nunomaduro/dev-null.sh 开源，有评论者称它在不到 48 小时内吸引了 200 多个 PR。
