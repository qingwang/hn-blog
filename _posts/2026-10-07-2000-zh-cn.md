## 1. Claude Haiku 5.5 {#story-1}
*HN 第 1 名 · [anthropic.com](https://www.anthropic.com/claude-haiku-5-5) · 240 分 · 102 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=49996437)*

Anthropic 发布了 Claude Haiku 5.5，这是其迄今最便宜、最快、能力最强的小型模型，面向摘要、压缩（compaction）、分类和子代理任务等高频大批量工作。定价采用分级制：提示词在 100k token 以内时，输入/输出为每 Mtok $0.10/$0.50，超过该阈值则跃升至 $0.50/$2.50——Anthropic 称这平均便宜约 75%，而在 100k token 以内比 Haiku 4.5 便宜 90%，并称 90% 的 Haiku 4.5 请求都落在这个区间内。该公告还将 Sonnet 5.5 的缓存读取费用减半至每 Mtok $0.10，并为 Max 5x（$100）、Max 20x（$200）和 Team（最高 $500 共享额度）订阅用户推出每月 API 赠金，此外还在 Python 和 TypeScript SDK 中新增了 computer-use/browser-use 支持。

**讨论**: 最热门的讨论主线是定价：许多人认为 100k token 的门槛对于智能体（agentic）用途而言低得离谱，而另一些人则指出 Anthropic 自己声称 90% 的 Haiku 4.5 流量都在该门槛之下，并提到 GPT-6 Luna 也有类似但更高的 272k 门槛（评论者补充说，分词器差异使得 Claude 的 100k 大约相当于 60-65k 个 GPT token）。几位用户表示，在同样 $0.10/$0.50 的 100k 以内定价下，Haiku 5.5 看起来比 Luna 更聪明，OpenRouter 显示其 P50 速度为 131 tok/s；不过怀疑者认为，只有在忽略其输出极其耗 token 的情况下，便宜的中国模型（GLM、MiMo）才在每完成一个任务的成本上仍然占优。一个反复出现、被提了两次的批评是：每月 API 赠金恰好与 Claude Agent SDK 从 Claude 订阅制转向 API 计费同时发生——而这一变动 Anthropic 曾在 6 月退缩过。在实用层面，评论者欢迎这些赠金，称 Haiku 的最佳适用场景是低推理强度的体力活和文档解析，并指出它清楚自己的局限：在一次 image-to-HTML 测试中，它立刻把任务交给 Opus 处理。

**值得一读的评论**
- [minimaxir](https://news.ycombinator.com/item?id=49996502): 详细分析了分级定价，认为其激进得有些奇怪——100k 的截断点只有 Haiku 才有，智能体工作负载必然会突破它，但仍比 Haiku 4.5 便宜得多，且与 GPT-6 Luna 有竞争力。
- [thepasch](https://news.ycombinator.com/item?id=49997143): 认为 API 赠金是以后门方式重新引入 6 月那项让 Claude Agent SDK 脱离订阅计划的变动，并附上 Anthropic 支持文章的链接。
- [jjcm](https://news.ycombinator.com/item?id=49996898): 做了 image-to-HTML 的 UI 测试并附上输出链接：Haiku 5.5 生成的结果与设计稿完全不同，而 Opus 5.5 几乎像素级还原，不过 Haiku 知道该把任务交出去。

## 2. GPT‑6 与面向所有人的 Intelligent UI {#story-2}
*HN 第 2 名 · [openai.com](https://openai.com/index/gpt-6-for-everyone/) · 135 分 · 56 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=49996425)*
*原标题: GPT‑6 and Intelligent UI for everyone*

OpenAI 为 ChatGPT 中的 GPT‑6 发布的公告，该版本随附 Intelligent UI：模型从一组原生可流式传输的组件库（图表、滑块、表单、可点击按钮）中组合出回答，另有一个编译器在生成过程中逐步渲染界面。它还把思考与作答交织在一起——OpenAI 称 GPT‑6 Instant 在网页搜索类问题上比 GPT‑5.6 Instant 早 44% 开始作答，并称 GPT‑6 Extra High 的首次作答时间与 GPT‑5.6 Medium 相当，同时在内部 agentic 评测中胜过 GPT‑5.6 Extra High。今天向 Plus、Pro、Business 和 Enterprise 推送，明天向 Free/Go 推送，由 GPT‑6 Sol（付费）和 GPT‑6 Luna（免费）提供支持；Work 和 Codex 模型保持不变。

**讨论**: 最主要的反应是审美和产品层面的反对：若干用户表示生成的版式——卡片、清单、留白、标语——显得居高临下或臃肿，有人明确要求提供纯文本输出，以便导出和进一步处理。一个反复出现的抱怨是，聊天由 GPT‑6 Sol 驱动，而不是更新、更强的 GPT‑6.1 Sol；用户猜测（没有给出出处，还有人明确要求提供出处）6.1 是一个换名推出的、更重的模型，用来掩盖 GPT‑6 较弱的 agentic 表现；也有人指出，他们在 200 美元的 Pro 和企业版 Codex 账号上都碰到了 6.1 Sol 的容量上限。从业者指出这并不新鲜：GUI 环境中的模型早就能按要求内联渲染 HTML/artifacts，Codex/Astra 也已经会为非线性数据写出完整的 HTML 文档，所以这主要是把已有行为产品化——真正的问题在于延迟，以及模型如何判断何时该使用 UI。少数人对无障碍性（老年人、残障人士、ADHD 用户）表示欢迎，而怀疑者指出，用户无从判断生成的可视化是否准确；文章自身的页面/播放器也招来抱怨：视频播放器坏了，拆解自行车的图示在解剖上看着是假的。获得最多认同的观点是：Bartosz Ciechanowski 手写的 WebGL 讲解器依旧无人能及（而且他现在在 OpenAI 工作），以及 GPT‑6 与 6.1 之争才是这篇报道里最有实质性的问题。

**值得一读的评论**
- [FLeXMurphy](https://news.ycombinator.com/item?id=49997098): 认为 Ciechanowski 的走红以及手绘讲解的消亡，源于 CAD 和短视频扼杀了严谨的技术写作，因此他的风格已经注定被历史淘汰。
- [MikhailTal](https://news.ycombinator.com/item?id=49997112): 在没有引用来源的情况下断言：GPT‑6.1 是一个更重的「Astra 次要」模型，在 GPT‑6 发布令人失望后于慌乱中被改名为 Sol，因此二者实质上是两个不同的模型。
- [wincy](https://news.ycombinator.com/item?id=49996798): 第一手报告称，搭载 Astra 和 Sol 的 Codex 工作模式在无人提示的情况下，就已经会为复杂的非线性数据写出完整的 HTML 文档——这证明了 Intelligent UI 是在把已有行为产品化。

## 3. Visa、Mastercard 及多家大银行因「反竞争」费用面临新的诉讼 {#story-3}
*HN 第 3 名 · [classaction.org](https://www.classaction.org/news/visa-mastercard-major-banks-facing-new-litigation-over-anticompetitive-merchant-credit-card-transaction-fees) · 297 分 · 165 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=49993914)*
*原标题: Visa, Mastercard, Major Banks Facing New Litigation over 'Anticompetitive' Fees*

这是一篇 ClassAction.org 的报道，介绍 Pizza Standard LLC 诉 Visa 等公司一案（2026 年 9 月 30 日提起，加州南区法院，案号 1:26-cv-06087）。这份 134 页的诉状指控 Visa、Mastercard 以及美国银行、Capital One、Chase、花旗和富国银行数十年来合谋统一设定交换费（interchange），并称商户每年为此支付超过 1000 亿美元；案件代表自 2019 年 1 月 25 日起接受 Visa/Mastercard 信用卡的所有美国商户。诉状称此前和解（约 50 亿美元，2019 年 12 月获批）只覆盖 2019 年 1 月 24 日之前的『集体诉讼期』，因此 2019 年之后被收取的费用没有任何补偿。

**讨论**: 讨论迅速从本案转向一个更广泛的争论：最高票评论认为支付、物流这类中间商已无多少附加价值，甚至应作为公共服务运营，随后大量回复则强调支付网络要承担欺诈、合规（PCI-DSS）和争议处理成本，不能只看「转发一个数据包」的成本；有加拿大从业者指出 Interac 借记每笔仅约 10 加分、欧洲和中国等地的替代系统证明低费率可行。另一场争论围绕费率构成：有人纠正说收单机构（而非卡组织）设定商户折扣率，但这些诉讼从不把收单机构列为被告，也有人贴出 Stripe 2.9% + 30 美分的拆解，指出固定费用在小额交易中占比极高，而 EU 对借记 0.2%、信用卡 0.3% 的费率上限以及美国 Durbin 修正案被反复引用。关于争议处理／拒付（chargeback）的体验也两极分化，多人抱怨 Amex Platinum 和 Chase 的拒付流程漫长、被反复要求提供同样材料，另一些人则说能为拒付多付 3% 完全值得。多处评论批评集体诉讼和解的结构：钱大多归律师和第三方机构，商户与消费者拿不到钱，还有人对反复抱怨『跑题』的元评论表示不满。

**值得一读的评论**
- [tiffanyh](https://news.ycombinator.com/item?id=49996621): 用 Stripe 的 2.9% + 30 美分举例说明固定费用常被忽视：30 美元的交易中这 30 美分相当于 1%，使实际费率接近 3.9%，而流向发卡行的交换费只有约 1.75%。
- [jijji](https://news.ycombinator.com/item?id=49996178): 第一手经验：FedNow 每笔收 0.045 美元、7×24 即时到账，Same Day ACH 约 0.30 美元／笔，并把 B2B 争议窗口从信用卡的 120 天缩短到 3 天，作者称其企业因此节省数百万美元手续费。
- [gadders](https://news.ycombinator.com/item?id=49996070): 引用 Oliver Bateman 的访谈与播客，用一个谷歌隐私诉讼和解的实例说明集体诉讼里律师拿走 1900 万美元、200 人的集体获得零赔偿、其余资金流向与原告律师有关联的机构。

## 4. Show HN: Bigwords.page – 把任何屏幕变成一块告示牌。URL 就是应用本身 {#story-4}
*HN 第 4 名 · [bigwords.page](https://bigwords.page/) · 144 分 · 46 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=49994443)*
*原标题: Show HN: Bigwords.page – Turn any screen into a sign. The URL is the app*

Bigwords.page 是一个 Show HN 的单页网页应用，能把一个 URL 变成全屏的告示牌、计时器或消息：位于 # 片段之后的所有内容编码了消息以及诸如 bg、fg、font、interval、timer 和 until 之类的设置，并支持 markdown、用 || 分割幻灯片、{countdown}、二维码，以及脉冲/滚动/彩虹动画。其卖点在于片段永远不会发送到服务器，因此没有后端、没有账号、也没有存储，整个项目以 MIT 协议开源并可自行托管。作者（SpeakingOfBrad）做这个东西，是为了让一个他无法物理接触的远程管理的显示屏能被一个 URL 配置。

**讨论**: 整个讨论串总体是正面的：有人说它是 DOTADIW 的一个干净范例，也喜欢把 URL 当作静态应用的数据或 argv 这个想法；还有几个人说他们已经有用途了（会议告示牌、从手机发出一块坏掉汽车的消息、为跨时区的游戏之夜做 Unix 时间戳倒计时）。主要分歧在于投稿标题「The URL is the app」——notpushkin 和 rpdillon 说这是 LLM 腔调而且事实上就是错的，他们认为应用运行在服务器上，只有内容存在于 URL 里；而 rendleflag 反驳说没有任何证据表明这是 AI 写的，这只是简洁的措辞。作为回应，作者（SpeakingOfBrad）确认它正是使用 URL 片段，因为浏览器从不把片段发送到服务器，并承认标题被压缩了，因为只有 80 个字符可用。有人建议的扩展包括 Google TV / Apple TV 应用，以及让一台设备控制另一台设备显示的内容，其中 wiradikusuma 顺势推销他自己的 signagesync.app，用于咖啡馆多屏视频墙；其他评论还包括对 bigassmessage.com 的怀旧、一条关于 Apple Messages 中那个碍眼的 Open Graph 缩略图且无人回应的抱怨，以及一个在 Firefox 上出现 SSL 警告的报告。另有一处历史呼应来自 okaleniuk，他做过一个教学幻灯片演示，其中 URL 就是那一页幻灯片。

**值得一读的评论**
- [SpeakingOfBrad](https://news.ycombinator.com/item?id=49994461): 作者解释了它的由来：他需要把一条消息推送到一台无法物理接触的远程管理的平板上，解决办法就是把消息做成 URL 片段，因为浏览器从不把它发送到服务器——没有后端、没有存储、MIT 协议开源并可自行托管。
- [rpdillon](https://news.ycombinator.com/item?id=49997107): 对标题的一处尖锐纠正：URL 不是应用本身，应用运行在服务器上，而这整个东西本质上就是 github.com/antonmedv/textarea 那个 textarea 项目的另一种形态。
- [okaleniuk](https://news.ycombinator.com/item?id=49997241): okaleniuk 贴出了他自己基于同一原理做的教学演示（「URL 就是幻灯片」），并指出这些共同的好处：没有后端、没有存储、不收集数据、无需授权。

## 5. Docker Agent：由 Docker 打造的 AI Agent 构建器与运行时 {#story-5}
*HN 第 5 名 · [github.com](https://github.com/docker/docker-agent) · 28 分 · 12 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=49996259)*
*原标题: Docker Agent : AI Agent Builder and Runtime by Docker*

Docker Agent 是一个开源的 Docker CLI 插件（github.com/docker/docker-agent），用于以声明式 YAML 定义 AI agent——可以是单个 agent，也可以是相互委派任务的团队——它内置工具，并支持任意 MCP server、与供应商无关的模型支持（OpenAI、Anthropic、Gemini、Bedrock、Mistral、xAI、Docker Model Runner）、RAG 选项（BM25、embeddings、hybrid search、reranking），还能把 agent 打包成 OCI 镜像，随处 push 和 pull。它已预装在 Docker Desktop 4.63+ 中，也可通过 Homebrew（brew install docker-agent）或二进制发行版获取，运行方式为 `docker agent run myorg/agent:tag`。README 强调无需编写任何代码，并且 Docker Engineering 用 docker-agent 来构建 docker-agent。

**讨论**: 讨论最热的一条线是“这算不算模拟器”：有人指出这描述的其实就是一个模拟栈，只不过 CPU 层面换成了 AOT 重编译，而且生成的 C++ 仍然在操作一个 MIPS CPU 状态对象，因此本质上仍是模拟；反驳者认为 AOT/静态重编译传统上不被归为模拟，且这类项目是自成一体的独立作品而非通用产品，双方基本同意这只是措辞之争。第二条主线是 AI 与合法性：不少人对 AI 辅助反编译、直接移植老游戏表示兴奋，认为有利于游戏保存；也有人担心这会侵蚀版权、加速游戏业裁员，并质疑反向工程加分享 ISO 的合法性（有人纠正说仓库本身不含 ROM，自己拥有并提取的镜像通常合法，但分发镜像才违法，且判定因司法辖区而异）。第三条线更尖锐：有评论者称这“只是个需要针对性补丁的劣质模拟器，是把模拟器嵌进游戏二进制里的偷懒产物”，立刻遭到反驳，认为玩家只在乎能不能玩，而支持者又反击说 AI 写出的模拟器仍会崩溃、且连 Switch 2 模拟器都做不出来。还有人补充这是“重制”而非“保存”，并提到 Denuvo 近期被 AI 破解、以及有人在做《任天堂明星大乱斗 Melee》的同类浏览器移植（完成度约 80%）。

**值得一读的评论**
- [wren6991](https://news.ycombinator.com/item?id=49995520): 指出重编译生成的 C++ 依然是在操作一个 MIPS CPU 状态对象，从代码层面说明它并未绕开 CPU 模拟。
- [nikhilunni](https://news.ycombinator.com/item?id=49995370): 作者正在用同样思路把 GameCube 的《任天堂明星大乱斗 Melee》移植到浏览器（github.com/nikhilunni/melee），完成度约 80%，以 Dolphin 作为 oracle。
- [glouwbug](https://news.ycombinator.com/item?id=49997123): 从技术角度解释 AI 为何擅长这类工作：可在函数级别暴力反编译为 C，反复试错直到编译产物 md5 与原始二进制一致，但产出的源码不可读、难维护。

## 19. M-VAVE FM-1 袖珍合成器固件的逆向工程 {#story-19}

*原标题: Reverse Engineering of the M-VAVE FM-1 Pocket Synthesizer Firmware*

一个 GitHub 研究仓库（AL-255/FM-1-RE），记录了 M-VAVE FM-1 的逆向工程——这是一台售价约 60–80 美元的袖珍 FM 合成器。它将 SoC 识别为 JieLi AC791N/WL82，搭载 pi32v2 CPU，XIP flash 位于 0x02000000，并采用源自 Dexed/msfa 的六算子 FM 引擎——并主张内嵌的 JL-BR22 字符串是继承自库的命名，不能作为可靠的 SoC 识别依据。该仓库分析了 V13/V14 固件包、USB-MIDI OTA 协议，以及一个反编译的 Windows M-UPGRADE 升级工具，并明确警告：该更新路径并非经过验证的恢复机制——对于单 bank 布局，既没有确立 ROM 恢复、回滚机制，也没有安全的中断写入行为，而一次调试面审计未发现任何替代恢复入口。
