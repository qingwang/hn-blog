## 2. Lemmings CSS Animation {#story-2}
*HN 第 2 名 · [markblah.github.io](https://markblah.github.io/lemmings/) · 99 分 · 17 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50375354)*

MarkBlah 在 GitHub Pages 上的交互式玩具，把《Lemmings》里的行走小人放进了一个网页里：点击按钮或调用 `__walker.add()` 就能生成小人，可以拖着走、甩出去；调整窗口大小时，脚下踩着的“地面”会被带走，窗口快速缩小甚至能把小人弹飞。页面里的边框、按钮、表单字段、图片都是实心地面，文字则是可以穿过但能落脚的地板，而且行距比小人还窄，以免他们卡在两行之间。作者说这是给 Psygnosis 的致敬，纯属好玩。

**讨论**: 评论区基本是清一色的喜爱与怀旧，有人形容把小人放在视口边缘、然后上下滚动，就能让它先坠落再像蹦床一样弹起来。明显的批评集中在关卡设计上：好几位指出小人的站位会让它从侧面一路掉到底部，跳过了所有“关卡”，建议去掉 `<body>` 的 padding、多加点坑，让它必须一层层清关才能到底。另有 Safari 用户反馈滚动时小人不会跟随，移动端还有一些缩放 bug，有人直接贴出 `html { overflow-x: clip; touch-action: manipulation; }` 的修复方案，作者回复说会加上。讨论还延伸到同类项目：有人提到自己刚把 xpenguins 移植到网页版，可以做成 bookmarklet 跑在任何站点上，还有人回忆起当年的 DHTML Lemmings。

**值得一读的评论**
- [grumbel](https://news.ycombinator.com/item?id=50376336): grumbel 说自己刚把 xpenguins（经典桌面企鹅漫步程序）移植到了 Web，可作 bookmarklet 跑在任意网站上，只是里面是企鹅而非正宗 Lemmings。

## 3. Images 2.6 {#story-3}
*HN 第 3 名 · [openai.com](https://openai.com/index/introducing-images-2-6/) · 248 分 · 160 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50372945)*

这是 OpenAI 为 Images 2.6 发布的官方公告，该模型已在 ChatGPT、Codex 和 API 上线。它声称生成速度比上一代快 50%，新增 GIF 动画输出、API 端图像标记（image markup）和 SVG 导出，还引入了一个复杂度参数；模型被拆成 GPT‑Image‑2.6 Flare（低质量下最快约 6 秒出图）和 GPT‑Image‑2.6 Sunburst（质量更高、编辑一致性更强两个版本，低质量下的最快约 6 秒出图）。OpenAI 称 ChatGPT、Codex 和 API 每周合计生成 40 亿张图片，即每天超过 5 亿张。

**讨论**: 讨论从审美问题展开：许多评论者认为输出看起来仍像 「AI slop」，并追问模型为什么摆脱不了这种风格。反驳意见认为，AI 图像那种光泽感、有美感的观感正是普通用户和 RLHF 奖励所偏向的，可以用提示词绕开，只是一般人不会这么做；也有人否认这是标注者的问题，指出食物图像的失败，以及 Z 世代对人类偏好评估的排斥，表明奖励信号在跨领域时应用不当。还有一大串评论指责定价误导：输入输出 token 单价没变，但按 OpenAI 自己的价格计算器，低、中质量档的 token 用量约为 2.5 的 3–4 倍，所以实际每张图的价格大约翻了三倍。有几位实际测试者（包括一位运营 prompt-to-design 网站的开发者）报告称 2.6-flare 比 2.5-flare 更差，并称 arena.ai 排行榜上 2.5 得分更高，而 2.6-sunburst 则被认为更稳。技术评论聚焦在新功能上：一位长期做图像基准测试的评论者指出，基于网格的帧技巧早已存在，GIF 帧间一致性仍然有噪点，而且 SVG 实际上是一次光栅转矢量流程（接到 API 后他还发现需要单独传一个 svg.model 参数，否则返回 400 error）。有几个评论者抱怨他们找不到质量提升，认为图像生成已经趋于平台期，还有人开玩笑说，把每周 40 亿张图的数字看作大量浪费。

**值得一读的评论**
- [minimaxir](https://news.ycombinator.com/item?id=50373156): 长期做图像基准测试的评论者指出，GIF 生成依赖老式的网格/精灵帧技巧，帧一致性脆弱；SVG 文档证实是光栅转矢量流程，并指出 OpenAI 声称的 50% 加速伴随着与 2.5 相同的标价。
- [bsboxe](https://news.ycombinator.com/item?id=50373444): 具体算账：1024x1024 下，2.6 低质量消耗 823 token / $0.025，而 2.5 为 196 token / $0.006；中质量从 439 token / $0.013 变为 1449 token / $0.043，所以尽管「价格相同」，实际成本是原来的 3–4 倍。
- [jjcm](https://news.ycombinator.com/item?id=50373420): 一位运营 prompt-to-design 站点的开发者在使用一小时后把生产环境从 2.6-flare 回滚到 2.5-flare，称 2.6 的输出过于简单，甚至明显损坏，并称 arena.ai 排行榜上 2.5 得分高于 2.6。

## 4. 少了一千条通往 root 的路径 {#story-4}
*HN 第 4 名 · [openai.com](https://openai.com/index/a-thousand-fewer-paths-to-root/) · 291 分 · 187 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50372929)*
*原标题: A thousand fewer paths to root*

OpenAI 的网络安全团队描述了一条五阶段的自主流水线——侦察 agent 挑选出约 280 万行代码（占内核的 7%，共 5,034 个审计目标），分析 agent 在 12 小时内产出 2,308 条候选发现，分诊 agent 在 KASAN 下复现它们，随后进行漏洞利用与补丁生成——该流水线在 2026 年 10 月中旬针对 Linux 内核 master 分支运行。它复现了 1,724 条发现（74.7%），产出 291 个信息泄漏 PoC 和 948 个可用的本地提权漏洞利用，花费 1,213,430 美元的 API 额度（每个 LPE 合 1,279 美元）；相比之下，7 月用 GPT‑5.6 Sol 跑的那一轮花了 513,690 美元、得到 166 个 LPE；候选发现中只有 3.1% 是纯粹的模型错误。在一个改造过的 kernelCTF 目标上，它以约 32,936 美元换来了 25 个泄漏 PoC 和 21 个 LPE；它还声称至少掌握了 10 种新颖的利用技术，但细节未公开；作者把 120 万美元定位为一个上限，认为通过改进 harness 工程还能压低。

**讨论**: 最主要的反应是：这并不令人意外，也谈不上警报——人们早就默认 LPE 只差一个 bug，内核是 4000 万行内存不安全的 C 代码，而安全圈几十年来一直在说，任何依赖「不存在 LPE」这一前提的模型都不是安全模型。争论的焦点主要在 OpenBSD——一方认为它远低得多的 bug 数量证明 Linux 的设计与文化才是问题所在，另一些人则反驳说 OpenBSD 支持的硬件只占一小部分，盯着它的眼睛和投入的美元都少得多，而且它照样会发布 use-after-free 和越界类 CVE；有人举出 Anthropic 的 Mythos 那一轮，称其只报告了一个 OpenBSD 漏洞。怀疑者质疑这个头条数字，把它比作把每一条 SQL 注入路径都算作一个独立 bug；而流水线作者回应说，这些是按补丁统计的不同问题，且全部属于内核代码，以 root 运行的用户态守护进程不在范围内。还有几位评论者追问缺失的信息：按子系统与代码年代的分布、Sashiko 已经能抓到多少条发现、扫描是否会随每个新模型持续进行，以及一支人类团队拿到同样的 120 万美元能否做出相当的工作。

**值得一读的评论**
- [ky1ebot1337](https://news.ycombinator.com/item?id=50373607): 流水线作者解释说，948 这个数字是按补丁计数的不同漏洞（变体分析会把相关的利用合并），并且所有发现都是内核代码，以 root 运行的用户态程序被明确排除在范围之外。
- [amluto](https://news.ycombinator.com/item?id=50375361): 一位曾处理非公开 Linux 内核安全报告的人请求提供一份报告样本，并指出他自己遇到的最「肥」的内核 LPE 几乎从来不是内存安全类 bug，因此敦促团队不要止步于 LPE 和信息泄漏。
- [tiffanyh](https://news.ycombinator.com/item?id=50374692): 指出 Anthropic 的 Mythos/Glasswing 针对 OpenBSD 的那一轮据称只发现了一个漏洞——这是 OpenBSD 子讨论串中最有力的具体反证。

## 19. 好奇心对我们有好处吗？ {#story-19}

*原标题: Is Curiosity Good for Us?*

精神分析学家 Adam Phillips 在《London Review of Books》（第 48 卷第 20 期，2026 年 11 月 5 日）发表的一篇文章，主张好奇心是我们身上最好的东西之一，并提出弗洛伊德式的超我——内化的罪恶感与羞耻之声，本质上是我们身上对自己毫无好奇心的那部分，是一个扼杀我们活着之乐趣的「破坏者」。Phillips 追溯了这一观念的脉络，途经 Freud、Ferenczi（后者希望分析能消解超我）以及 Klein 的 Roger Money-Kyrle，并把好奇心界定为一种冒险：有方向而无目的地，是对依赖、对自身并非全知全能的承认，很容易被转交给他人，也常常在他人身上引起嫉妒。文章大体抽象，结尾是一段书评式的讨论；抓取到的文本被截断。

- [sublinear](https://news.ycombinator.com/item?id=50375363): 直接反驳：否定 Freud 的前提是假定已经有人确证了他错得有多离谱；并指出，什么算「直觉」会随时间变化，而这恰恰源于过去的探究。
- [roenxi](https://news.ycombinator.com/item?id=50374177): 实质性反驳：文章漏掉了谱系中不健康的那一端，也漏掉了更深层的问题——求真是否始终与人类价值观相容。

## 20. Show HN：DOOM 的 DNA——代码结构如何跨越 44 个移植版本存续 {#story-20}

*原标题: Show HN: The DNA of DOOM – How code structure survives across 44 ports*

Joe Esquibel 用他的 GitGalaxy 引擎扫描了 1997 年的 linuxdoom 发行版以及 43 个衍生版本（忠实副本、源码移植，以及翻译成约 20 种语言的版本，包括 Go、Scheme、Fortran、COBOL 和 SQL）；该引擎测量函数长度、分支、输入和调用图，同时忽略名称和文本。文章声称结构的作用如同指纹：Chocolate Doom 保留了原版 87% 的函数名，但只保留了这些函数内部 35% 的代码，Doom Retro 为 69% 和 0.2%，GZDoom 为 32% 和 0.2%；基于形状的相似检测精确率为 93%，并找出了约三分之二经文本验证的副本。作为对照，Quake、Quake II 和 Lua 与 DOOM 的形状重合度为 0–0.6%，而 Chocolate Doom 为 31%；即使隐藏所有名称，该引擎仍能把某个 Go 移植版 60% 的函数归入 16 个子系统中的正确那一个（随机为 20%，在其最有把握的四分之一中为 99%）。

**讨论**: 这个讨论串主要由对文章写法的反驳而非对分析的反驳主导：最高赞评论直截了当地断言这篇文字是 Claude 写的，另外几人称其为 AI 垃圾（AI slop），抱怨像「the hard case」和「the wiring carries the signal」这类含糊的修辞标签，并说这个页面读起来像 DevOps 仪表盘而不像一篇文章。作者 joe-esquibel 承认它大量由 LLM 撰写，但表示自己在方法论上下了很大功夫，并提供了 GitHub 仓库和 JSON 数据集供审查；他也认真对待反馈，说自己现在能看出 AI 腔了。反方意见来自少数真正喜欢这个实验的人，尤其是 DOOM 模组/dehacked 怀旧这一角度，他们给出了建设性建议——初稿自己写、删掉那些交互式的杂乱内容，并修正那段暗示 Lua 源自 id Tech 家族的段落。一位评论者在回复中指出了一个真实的谱系细节：id 从 Keen 到 Doom 一直沿用同一个瓦片地图编辑器和文件格式。对于这个成果没有共识，但大家广泛同意底层想法很有趣，是呈现方式拖累了它。
