## 2. Rust 标准库中的内存安全缺陷 {#story-2}
*HN 第 2 名 · [forge-blog.github.io](https://forge-blog.github.io/posts/rust-std-memory-safety/) · 84 分 · 28 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50478701)*
*原标题: Memory Safety Bugs in Rust Standard Library*

这是一篇 Microsoft FORGE Lab 的帖子，介绍该团队在 Rust 的 std 和 core 中发现的 soundness（类型/内存安全正确性）缺陷，其中一些缺陷可以从完全安全的 Rust 代码触达。部分发现来自 Hyenas，即该实验室对其 AI 漏洞扫描器代号 MDASH 的研究版本；这些缺陷可归为 unsafe 代码中三类误置信任的模式：信任调用不会 panic、信任调用方提供的 trait 实现、信任底层系统。示例包括 nightly 版 MapWindows::clone 中的 panic 安全漏洞、一个自定义 Pattern 使 str::replace 返回非 UTF-8 的 String、一个 str::join 的 Borrow 缺陷下溢为堆溢出，以及最近稳定化的 Allocator API——Rust 1.100（11 月 12 日）现在禁止分配器发生 unwind，而不是逐个审计每处分配点。

**讨论**: 这个讨论串主要争论的是这件事究竟有多令人警觉，而不是具体缺陷本身。以 simonask 为首的一方指出，Rust 的 issue tracker 上有 178 个未关闭的 I-unsound 问题，而未发现的缺陷被发布出去只是正常的软件现实；有回复反驳说，这件事属于正常现象本身就是丑闻，simonask 则回应说，指望维护者一次性写出完美代码并不现实。一个长长的子讨论串争论 Vec 索引越界时应当 panic 还是返回 Option——几位评论者为 panic 辩护，认为这是应当 panic 的逻辑错误，并指出 get() 存在；另一些人则说 panic 很容易被遗忘，在对外的网络服务中会成为 DoS 攻击面。在别处，一位评论者称 Rust 的 unwinding 是个错误，会带来虚假的安全感，并主张 panic 应当终止进程；还有几条回复跑题到 Microsoft 的工程轶事，讲用自旋循环（spin-loop）「修复」锁顺序问题。讨论串中没有人质疑所报缺陷的技术实质；除了「内存安全很难」之外没有共识。

**值得一读的评论**
- [simonask](https://news.ycombinator.com/item?id=50504923): 提供了有用的背景：Rust 仓库目前有 178 个未关闭的 I-unsound 问题，因此这些发现属于常态而非丑闻。
- [Panzerschrek](https://news.ycombinator.com/item?id=50504896): 认为 unwinding 本身就是设计错误——panic 安全太难做对，所以 panic 应当直接终止进程。
- [nektro](https://news.ycombinator.com/item?id=50504448): 指出 Oxide Computer 的「iddqd: unsafe」一文是关于信任用户提供的安全实现的一篇很好的配套读物。

## 3. 法院驳回DRAM价格操纵案的撤诉动议 {#story-3}
*HN 第 5 名 · [litnews.ai](https://litnews.ai/articles/garciaguirre-samsung-sk-hynix-micron-dram-conspiracy-suit-survives-dismissal) · 78 分 · 17 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50502988)*
*原标题: Court denies motion to dismiss DRAM price fixing case*

加利福尼亚北区联邦地区法院法官Noël Wise完全驳回了三家内存制造商提出的撤诉动议。该动议针对的是2026年6月25日由17名消费者和小企业提起的拟议集体诉讼，指控被告违反《谢尔曼法》第1条，合谋掐断传统DRAM（DDR4/DDR5）供应，并把产能转向用于AI加速器的HBM。起诉书称，这三家公司在2025年第三季度合计占据全球DRAM营收的91%以上，传统DRAM价格同比上涨171.8%、18个月内上涨697%，而它们都没有宣布实质性的传统DRAM扩产计划；法官认可了多项附加因素（plus factors），包括HBM长期锁定协议、拒绝签订长期DDR5合同、Micron关闭Crucial、晶圆厂延期、2026年1月近乎一致的客户审查，以及1998至2002年的卡特尔历史。她驳回了「DRAM II重演」的抗辩，也不采纳投资者关于「供应纪律」的言论、行业会议会面以及寡头结构作为证据，随后写道，原告的案情「更像是鹰群列队齐飞」，而不是鹰群互相注视。答辩状截止日期为2026年12月7日，首次案件管理会议改期至2027年1月12日。

**讨论**: 整个讨论串主要是成本之痛和黑色幽默，而非法律论证：一位研究者说256 GB内存现在要4–5千美元，威胁到一个已获资助的工作站搭建计划；其他人纷纷附和，说未来任何反垄断罚款相对营收都只是零头（有人开玩笑说是「整整一周的营收」，另一位则调侃自己活不到第13或第14次有罪判决）。唯一实质性的分歧在于DDR4→DDR5的过渡是否可疑：一位评论者称这是实打实的升级，并指出中国晶圆厂仍能生产DDR4；有人回应说两代产品使用不同的晶圆厂和制程，产能无法简单挪用；第三位则指出，绝对意义上的晶圆短缺才是根源，因为HBM吃掉了供应。有几个人权衡租用云GPU与自行购买，实际的反驳意见是：科研经费可以花在你保有的硬件上，但不能花在最终归还资助方的云额度上；一位欧洲评论者把EuroHPC共享的分层超级计算机基础设施描述为机构层面的答案。没有人公开为内存制造商辩护；大致共识是，无论法院怎么判，市场已经坏了。

**值得一读的评论**
- [gbnwl](https://news.ycombinator.com/item?id=50504804): 认为短缺归根结底是晶圆供应约束——是HBM对硅片的胃口让DDR4/DDR5产出枯竭，而不只是厂商的选择。
- [SubiculumCode](https://news.ycombinator.com/item?id=50504943): 解释了为何租用云算力解决不了经费问题：未花完的算力预算要退回政府，而购置的硬件在经费结束后仍留在实验室。
- [SubiculumCode](https://news.ycombinator.com/item?id=50504433): 关于价格暴涨的第一手数据：一个刚获资助的实验室，工作站预算被256 GB内存的4–5千美元加上32 GB GPU的4–5千美元吃光了。

## 4. Show HN: Gawain – 要求所有 Python 变量都带类型提示 {#story-4}
*HN 第 6 名 · [github.com](https://github.com/matheuzgomes/gawain) · 37 分 · 15 条评论 · [HN 讨论](https://news.ycombinator.com/item?id=50504072)*
*原标题: Show HN: Gawain – Require type hints on all Python variables*

Gawain 是 matheuzgomes 用 Rust 编写的 linter，强制要求每个 Python 变量、参数、返回值和类属性都带类型注解，然后把文件交给类型检查器处理，默认安装的是 Astral 的 ty（锁定在 0.0.100），也可以通过 extra 选用 Meta 的 pyrefly 1.4.1。与只覆盖函数的 ruff ANN 规则和 flake8-annotations 不同，它会对未加注解的变量、裸 Final 以及任何对 Any 的使用报警（GW001–GW004），并提供一个「obvious」默认模式，豁免字面量、字面量容器和只赋值一次的构造函数调用，以及一个 --mode strict，要求每个赋值都必须有注解。作者自陈的动机是厌恶 dict[str, Any]；前后对比例子展示了它能在 ty 中抓出返回类型不匹配，项目还附带一个 pre-commit hook（需要 Rust 1.97+），以及针对 1,847 个文件、974,586 行的 CPython 3.14 标准库的基准测试。

**讨论**: 这个讨论帖基本无视工具本身，转而聚焦它的名字：几位评论者用中古英语引用《高文爵士与绿骑士》（Sir Gawain and the Green Knight），认为这个亚瑟王典故用在一个以「毫不留情的精确」为目标的 linter 上很贴切，有人建议把这段引言放进 README。就实质内容而言，少数开发者表示，强制类型正是他们彻底离开 Python 的原因——「maybe just... stop writing py」——另一些人则反驳说 Python 类英语的语法是优点，由此引出一个子串讨论，称用显著空白（significant whitespace）做缩进是个疯狂的设计选择。有人希望有「一个真正跑得快、带类型的严格 Python」，mypyc 被视为显而易见的人选；还有人打趣预测 Python 9.x 的发布说明会宣布它是静态类型语言。最具前瞻性的观点是热情支持把它作为阻塞式 pre-commit hook 运行，因为 AI agent 能自动修复 lint 错误，从而得到 100% 带注解的、由 agent 编写的代码。

**值得一读的评论**
- [michalc](https://news.ycombinator.com/item?id=50504823): 认为 dict[str, Any] 还有一个伴生烦恼是 `| None`，并链接到自己那篇称类型安全是一把双刃剑的文章。
- [analog_daddy](https://news.ycombinator.com/item?id=50504299): 指出 mypyc 是最接近快速、静态类型 Python 的东西，不过他承认自己其实从没真正试过。
- [cadamsdotcom](https://news.ycombinator.com/item?id=50504555): 支持在阻塞式 pre-commit hook 中强制严格注解，恰恰因为 agent 会去修 lint 问题，从而消除掉一整类低质代码。

## 5. 在造出电脑之前，Woz 是怎么写出 Apple 1 BASIC 的？ {#story-5}

**值得一读的评论**

CBC News 的一项视觉调查追踪了 LinkedIn 和 Monster 上 1500 多条误导性招聘信息——远程「旅行规划师」和「客户支持」岗位，年薪最高 7.5 万美元，无需经验或简历——最终追溯到美国多层次营销公司 Evolution Travel，该公司通过合作伙伴 Archer Travel Services 销售会员资格。CBC 用空白简历申请后，被引导至销售说明会；在说明会上，申请人需预付数百美元，还要支付月度订阅费以及一笔不为人知的每年 50 美元费用，并通过招募他人获得佣金；这些广告以 Wanderwell Collective、Professional Travel Hub 和 Sunkissed Getaways 等名义发布，从未提及 Evolution Travel 或相关费用。LinkedIn 下架了约 900 条信息，Monster 下架了 600 条；前 FTC 主席 William Kovacic 表示，这些帖子会招致执法行动，并指出 Evolution Travel 是 FTC 在 2021 年警告过的 1000 家公司之一。
